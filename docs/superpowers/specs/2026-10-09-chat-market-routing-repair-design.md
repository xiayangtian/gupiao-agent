# 智能问答市场链路修复：对象、时间、澄清、来源与终态

日期：2026-10-09。设计基线：本地/远端 `main` `81959c4`（P1–P4 已合入）。**状态：方案口径已于 2026-10-09 确认，未获实施授权。**本设计不读取真实提供方、不执行行情/MCP 调用、不改生产服务。获得方案确认后另写实施计划；独立分支开发、隔离替身验证，合入 `main` 另行授权。

## 1. 现场证据与问题边界

本地会话中，诊断 ID `ca4ea34d2e6e47f98ba1f265f6732590` 对应如下连续输入：“分析今日股票行情”→“分析福耀玻璃近期行情”→“分析福耀玻璃近5日行情”→“近五交易日”。前三轮分别要求公司、时间、时间；第四轮持久化为 `report_fact`、`whole_corpus`、`plan_status=fallback`、`max_calls=0`、零工具产物、八条农业银行 PDF 片段、`verification=passed`、`status=completed`。记录表明该轮根本没有进入市场来源执行，**不能据此断言 MCP 服务本身坏了**。单轮实际耗时约 55 秒，却未完成用户的行情分析。

已复核的确定性链路：`webapp/chat_policy.py` 先将“今日股票行情”当需公司代码的 `market_quote`；`webapp/chat_time.py` 不识别“近期/近5日”；`webapp/server.py` 的预检澄清保存文本但下一轮不承接待补槽位，单独的“近五交易日”不携带市场主体，模型计划失败后落入本地财报默认；`webapp/chat_verifier.py` 无可核验数字时可给出 `passed`，`webapp/chat_execution.py` 因此可能给出 `completed`。现有 P4 九个合成用例没有覆盖这条“先澄清、再以短句补全”的端到端市场路径。

目标用户任务有两类，不应混用：①“分析大盘/今日 A 股”：查看指数的实际覆盖和可用的市场广度，不能被要求给个股；②“分析福耀玻璃近期走势”：用确认的公司和明确/默认的有界交易日窗口读取个股日线，不需要财报。报告财务问题仍必须走原本的财报范围及核验合同。

## 2. 目标、非目标与不变量

**目标**：任意一轮先由服务端确定分析对象（全市场/指数、唯一公司、财报主体或不明确）、时间窗口、来源类别和授权状态；待补信息可安全跨**同一会话的下一轮**承接；市场计划失败也不能落到全库 PDF；只有实际取得与请求对象/时间匹配的可用行情证据才可宣告完成。

**非目标**：提高 MCP 可用性本身、更换行情提供方、下载/重建 PDF 索引、放宽 ToolPolicy/调用预算、允许模型决定任意外部工具及参数、引入新的默认外网评测或重新解释旧 `AnswerRun`。与本问题无关的新闻归因、财务同业及研究模式不扩张；不开发新工作台页面。

**保留**：P1 来源授权、物理尝试计数/去重与失败标识；P2 冻结 Scope/公司/时间、复盘市场调用 ≤7、总调用 ≤9、网页 ≤2，且配置更低时以更低者为准；P3 整轮 120/300 秒、worker 4、缓冲 64、协作取消及研究恢复；P4 证据窗口、上下文预算和离线评测报告可比性。没有明确授权时不执行财报补充下载、真实 MCP 探测或生产账号操作。

## 3. 方案比较与选择

| 方案 | 优点 | 缺陷 | 结论 |
| --- | --- | --- | --- |
| 补更多关键词/日期同义词 | 改动较小，能修复部分独立问句 | 不承接澄清，不约束失败回退和完成判定 | 不足以解决整条链路 |
| 让模型从历史自由补问并选来源 | 表面灵活 | 旧模型回答可能被当授权，易扩大公司/时间、重复工具或误触财报 | 不采用 |
| **服务端冻结请求合同 + 一次性澄清槽位 + 受控来源回退** | 可验证主体/窗口/来源/终态，不依赖模型可靠性 | 涉及多模块与持久化兼容 | **采用** |

不采用“行情数据不够就检索财报”：公司财报不能填充近五个交易日股价；没有可用行情时如实告知，不借财报解释近期涨跌。

## 4. 请求合同与判定顺序

新增纯服务端归一化边界（建议 `webapp/chat_request_resolution.py`）：`resolve_chat_request(question, scope_request, pending, now, availability) -> ResolvedRequest | Clarification`。`ResolvedRequest` 至少包含 `subject_kind`（market_wide / company / financial / general）、`intent`（沿用已验证意图，宽市场走 market_recap 或经验证的市场总览合同）、`company_code?`、`market_window?`、`financial_period?`、`source_mode`、`scope`、`effective_question`、`window_origin`（explicit / recent_default / clarification）、`allowed_source_kinds`。`effective_question` 仅由可信槽位和当前用户输入确定，供路由、检索和生成一致使用；原始用户消息仍按原文存储。数据类事件和可见答复只显示有界标签，不展示内部推理或敏感参数。

判定优先级：

1. **显式当前输入优先**：财报/营收/净利等披露指标不因“近期”就变行情；“股价/行情/大盘/指数/成交量/涨跌幅”先归市场。识别“大盘、A股市场、指数、两市/市场整体”时，不因同时出现“股票”而要求单家公司；“某公司股价”走公司市场。明确出现两家或同时出现大盘与具体公司的混合请求，不擅自选其一，要求澄清或拆成用户确认的两个任务。
2. **权限边界优先**：显式 `focus_report`/`scope_mode` 如与市场对象冲突，要求用户确认转换问题，不暗中扩大范围。公司型市场请求可使用已验证唯一公司身份，不要求本地已有该公司 PDF；大盘请求不继承上一轮公司。只有明确财务披露意图可设 `needs_local_pdf=True`。
3. **时间窗口**：具体日期/区间优先，其次“今日/上周/本周/近五交易日”及“近5日/最近五日/近5个交易日”的有界别名；无显式时间的“近期/最近/近来”**仅用于市场走势**，建议默认“近五个实际交易日”，并在第一帧和最终答复注明默认口径。绝不将“近期财报”自动翻译为五日行情。时间以上海时区、请求时刻冻结，未来日期/逆序区间拒绝；节假日/尚无当日行情不得用前一日数据冒充今日。
4. **不明对象**：“分析趋势”“近五交易日”且没有可信待补请求，明确询问是大盘、哪只股票或财务指标，不允许默认 `general_knowledge → report_fact → whole_corpus`。

`MarketWindow` 保留请求标签和实际 `covered_dates`；`select_market_bars()` 根据实际带日期数据筛选，返回不足五日时只称部分覆盖。大盘指数与 MCP 广度可有不同时间覆盖，应逐来源披露查询窗口/实际数据窗口，不拼成“全市场当日总量”。

## 5. 澄清状态机与并发/兼容

在 `ChatStore` 会话级新增**可选** `pending_clarification`，旧记录缺字段视为无待补请求。结构仅存安全枚举/已验证公司代码/待补槽位/原请求引用或原文、服务端创建时间及版本号；不存模型推理或来源数据。建议最多保留一条、最多接收紧接的下一条用户回复，TTL 15 分钟；重开同会话可继续，换会话不可继承。服务端以同一会话的原始用户问题和已确认字段生成 `effective_question`，只追加新回复，不重写旧消息。前端保留当前 `clarification` SSE 及 `run=None` 的兼容结构，可增加安全的 `missing_fields`/`clarification_id` 供展示，但不能由浏览器自称已验证槽位。

状态：`none → pending → consumed | expired | cleared`。预检澄清时原子写入 `pending`；下一轮原子校验会话、TTL、版本和未消费状态，消费成功后才生成新的 Scope/Policy/计划。同会话并发补答只能有一轮消费成功，失败一轮返回可理解的澄清/冲突，不重复调用来源。用户明确换公司、换市场/财报类型或新开问题时清除旧待补请求并按新问句重新解析；无法明确判定是补答还是新话题时只问一次，不凭旧会话任意扩权。`focus_report`、显式公司及当前输入冲突时拒绝继承。取消与 deadline 不得残留已消费但未执行的授权。

重点示例：

| 当前输入/上下文 | 解析结果 |
| --- | --- |
| 新会话“分析今日股票行情” | 全市场今日，不索取公司 |
| “福耀玻璃近期行情” | 福耀玻璃公司行情，默认近五交易日并披露口径 |
| 系统已明确询问“福耀玻璃股价走势要看哪个时间段”，用户只回复“近五交易日” | 从未过期的待补槽位沿用福耀玻璃市场意图 |
| 旧会话曾输入“福耀玻璃近5日行情”但未建立待补槽位，再回复“近五交易日” | 不从旧助手回复反推权限；先确认分析对象 |
| 同会话改问“分析今日大盘” | 清除旧公司待补，切换全市场意图 |
| “农业银行近三年营收趋势” | 财报意图及财务期间，仍不得使用市场默认窗口 |

## 6. 来源计划与可用性

**市场请求的服务端意图必须权威**。模型仅可选择该合同允许的步骤、顺序和摘要格式；拒绝/超时/JSON 错误均转为同意图的**确定性安全计划**，不能落入 `IntentRouter` 的默认 `report_fact`。无法在授权、可用来源和现有预算中组出计划时停止取数，返回受控 `unavailable`，不能凭空生成市场分析。模型规划失败原因以安全码记录，不记录原始模型输出。显式研究任务保留原独立研究路径，不能被普通市场路由抢占。

- **公司当日快照**：冻结唯一代码；腾讯报价一步（现有受控来源）。公司近五日走势以腾讯 K 线一步为最低必需来源；若当前策略和配置预算允许，可增加报价作为可选补充，但不因设计擅自提高调用上限或把 MCP 当必需来源。MCP 实时行情家族仅在确实可用、授权且有预算时作为独立候选；是否需要自动回退必须在实施计划中明确调用计数、时间口径与去重规则。
- **大盘行情**：四个指数的带日期 K 线/报价（现有固定的 `market_indices` 四次物理调用），只代表**四个指数**；需要广度时使用 `market_overview` 的三个固定 MCP 调用（涨/跌停池各上限 50，行业资金流，不代表全市场总量）；网页事件解释仅在授权且仍在 ≤9/≤2 预算内补充。数据或调用预算不足时保留已完成来源并逐项披露，不能将 MCP 失败伪装为完整市场广度。
- **真实可用性门控**：`market_overview` 不能仅凭 `use_mcp=True` 就宣告可用，必须同时核对配置、熔断器、实时 MCP 定义、三项操作白名单及剩余调用预算；缺项时明确 `unavailable`，允许不需 MCP 的有限指数分析，但不称市场总体完整。配置较低时不为凑齐指数/广度提高上限。`web_search` 不可用时也不虚构网页证据。所有物理调用经 `SourceRuntime` 授权、计数、去重、超时/取消门控；模型不得自行改工具参数/扩大公司范围。
- **财报隔离**：市场合同禁止 `retrieve` 和 `request_missing_reports`；报价/K 线故障不能转去拉财报。财务合同则继续遵守本地报告身份/授权补报政策。

`ExecutionPlan` 验证改为逐意图检查 **source_mode、步骤种类、必需的最小来源及成本**，而非只限定允许集合（避免回答单步/无市场数据却通过）。`ExecutionExecutor` 的部分成功与必需来源缺失仍使用现有 `AnswerContext`；不另开并行工具通道。

## 7. 答案和终态的证据条件

新增**按请求任务的完成判定**，不能让 `ClaimVerifier` 的“没有数值可反驳”替代任务已完成。市场请求 `completed` 的必要条件：取得至少一个与冻结对象/窗口匹配且可核验日期的必需市场 `SourceResult`；完成合同要求的来源步骤；实际覆盖满足所声明的范围；数字论断经现有事实核验；无来源失败/越权。只取得局部有效指数或不足五个实际交易日，返回 `partial` 并列出缺失维度和实际数据日期；没有可用行情结果或授权/配置阻断，返回 `failed` 或明确不可用的终态（按现有 `AnswerStatus` 枚举），即使回答里有合理的限制说明也不得 `completed`。大盘若仅四指数可用，只能称“指数观察”，不得声称市场广度/涨跌停总体；MCP 三项中有失败亦不能宣称完整市场复盘。保持旧财务/知识合同，不将“没有数字”普遍判错。

持久化 `AnswerRun` 可选的安全诊断枚举（例如对象、窗口来源、来源降级码、计划回退原因），旧记录可读；前端已有 `scope_resolved`、`execution_plan`、`source_result`、`verification`、`done` 事件语义不变。安全日志只输出 run ID、阶段/码，不写用户问题、模型原文和工具参数。补答问句最终可展示“按你补充的近五交易日分析福耀玻璃”，避免用户误解系统分析的是孤立短句。

## 8. 交付切片与验证门槛

**切片 A：纯路由/时间合同。** 用冻结上海时钟校验“大盘今日、个股近期、近5日/近五交易日、财报趋势、市场/公司冲突”；只读解析可单测，不取真实来源。第一阶段即阻断“大盘需个股、近期需绝对日期、孤立短句落财报”。

**切片 B：澄清状态与安全计划。** 将现场四个输入逐项做离线真实 `POST /api/chat/stream` SSE 回放：新版本前三项应分别按大盘、公司近期、公司近五日独立正确路由；第四项若无新的待补状态，应询问对象而非检索财报。另以“福耀玻璃股价走势”→“近五交易日”构造真正的两轮待补场景，测试重开会话、过期、换主题、显式 focus/scope 冲突、并发仅消费一次、取消、计划器异常和 MCP 不可用；所有来源用固定替身。断言补答后公司为福耀玻璃、计划只有允许的市场步骤、PDF 检索与补报调用数均为 0；大盘不要求公司，低预算不偷用来源。

**切片 C：来源/终态/界面直接影响。** 替身分别返回全量、部分交易日、指数成功但 MCP 失败、全来源失败、无日期、越 Scope、授权关闭；核对实际日期/分子分母、物理调用次数及 `completed/partial/failed`。复用 P2–P4 既有单测、运行级离线评测、P3 容量/恢复及最小真实浏览器 SSE 澄清-补答交互；前端若有变更，按既有 UI/浏览器流程检查桌面/平板/移动、键盘/无障碍和错误网络请求。**不默认联网、调用真实 MCP/行情、生产账号、下载 PDF 或全量测试**；真实提供方诊断须另获明确授权。

最低可复核验收矩阵（全部通过才可切换默认链路）：

| 场景 | 预期来源/范围 | 预期终态与约束 |
| --- | --- | --- |
| “分析今日股票行情”，四指数与三项 MCP 固定调用均成功且数据期匹配 | 大盘、市场来源，不需公司 | 可完成限定覆盖的市场分析；行情不含 PDF，调用不超配置/9 总上限 |
| 同上，但 MCP 三项不可用而指数有效 | 仅四指数；明确不可称全市场广度 | `partial`，不下载财报、不生成涨跌停总量 |
| “福耀玻璃近期行情”，返回 5 个有日期的交易日 | 唯一公司代码 + 一次有界 K 线 | `completed`；披露默认窗口与实际五个日期，PDF 调用 0 |
| “福耀玻璃近5日行情”，只返回 2 日 | 同一公司/窗口；仅保留真实两日 | `partial`；不能推断剩余三日的涨跌 |
| “福耀玻璃股价走势”→“近五交易日” | 同会话一次性待补槽位；仅市场来源 | 只执行一次；跨会话、过期、重放拒绝继承 |
| 单独“近五交易日”且无待补槽位 | 无来源计划 | 澄清对象；不能取 PDF 或启动模型财报兜底 |
| 任一市场问句，全来源失败/未授权 | 来源失败与安全失败码 | `failed`/明确不可用；不能只因回答没有数字而 `completed` |
| “农业银行近三年营收趋势” | 财务期间 + 受限本地财报 | 保留旧财务核验/补报授权，不误走市场窗口 |

失败门槛：任何跨公司/时间来源、市场请求进入本地 PDF、无行情却 `completed`、MCP 实际调用绕过白名单或超过预算、澄清补答重放/跨会话串线均阻断交付；不能靠缩小案例集规避失败。三片分别有可复现结果，合入前后按变更影响做聚焦验证，用户另授权后才合入 `main`，不得默认推送。

## 9. 风险、回退与待确认选择

- 默认“近期＝近五个实际交易日”是**产品口径提案**，非交易日历的先验承诺：只能从真实返回数据选最后五个有效日期。若用户希望每次询问窗口，应将该词纳入澄清而不默认。单独回复“近五交易日”没有待补状态时永远先确认对象。
- `market_indices` 成本是四次来源调用，MCP 市场概览成本是三次；配置低于要求时不可强行补足。只读可用性检查与实际调用之间会有竞态，执行时仍以 `SourceRuntime` 最终授权/预算结果为准。
- 旧会话只有对话文本、没有 `pending_clarification`；不能从旧助手自由文本逆推出可信待补状态。升级后旧记录需兼容读取，并允许用户重提一次。
- 市场广度 MCP 的真实可靠性与数据质量**尚未验证**；本方案先解决未抵达 MCP 的确定性链路。若离线接线通过、真实调用仍失败，应另按诊断 ID 核查 provider/工具清单/熔断/字段契约，不预先宣称已修好 MCP。
- 若改动期间出现影响旧财报/研究路径的回归，回退市场请求至明确来源不可用/待澄清，不恢复“全库 PDF 兜底”。数据持久化仅加可选安全字段，旧 `AnswerRun`/索引保持兼容。
