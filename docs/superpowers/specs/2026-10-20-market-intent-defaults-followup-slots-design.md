# 市场请求默认值与多轮澄清槽位修复

## 背景

会话 `97a51c9daa40` 的序列“再分析下海尔的今日行情”→“海尔智家”→“今日行情”暴露了上下文丢失：待澄清的公司槽位没有与已确认的行情类型、今日窗口可靠合并，之后主体也未传入公司范围解析。

## 目标

1. 市场请求缺少市场时默认 A 股，缺少期限时默认今日；用户明确指定个股、市场或期限时不覆盖。
2. 新会话中仅输入“7天”也视为 A 股近 7 自然日行情请求；`7个交易日`保持现有交易日语义。
3. 同一会话中行情回答后的短补充可修改相应槽位并触发新一轮生成：例如“7天”改期限，“港股”改市场；只继承已验证的任务上下文，明确的新主体/期限优先。
4. 对待澄清请求，回复只填缺失槽位，保留其余已冻结条件；模型暂时判为 unclear 时不能静默清除匹配的 pending。主体仍须由现有股票索引/代码解析验证；无法解析时只继续询问主体并保留期限/任务。
5. 不改变财报、常识、非金融、无关新问题的既有路由；港股等没有已授权行情 API 的市场继续使用现有授权 Web 路径，披露来源/覆盖限制，不调用 A 股行情源。

## 边界与不变量

- 不跨会话读取上下文；pending 绑定当前 session、版本和 TTL。
- 只从服务端持久化 pending 或已完成的 `AnswerRun` 投影继承槽位，不把模型生成的自然语言当作可信公司身份。
- 只继承与行情任务相关的意图、主体和窗口；新请求显式改写的槽位优先。
- 调用和来源授权仍由既有服务端路由、`SourceRuntime` 与工具白名单控制。

## 验收

- “分析行情”→ A 股今日复盘，不发澄清。
- “7天”新会话→ A 股近 7 自然日；显式“港股”不被覆盖为 A 股，缺期限时取今日。
- pending 主体回复“海尔智家”时有效合并原问题和今日窗口；pending 窗口回复“7天”时只更新窗口。
- unresolved company 时仅主体 pending 被续存，已有 intent/window 不丢。
- 会话中断/新会话、“解释债券”等无关输入不误继承旧行情槽位。
- SSE 回归确认已完成行情回答不被澄清，且港股路径不触发 A 股工具。
