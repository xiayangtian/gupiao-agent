# 多轮问答与网页搜索设计

## 目标

把当前“检索一次、工具调用一次、直接回答”的对话升级为受限的多轮工具编排。模型先判断本地财报证据是否足够；信息不足时按需调用股票数据或网页搜索，再基于新证据复核。全过程通过 SSE 展示，用户无需等待静默黑盒。

## 约束

- 默认最多 3 轮工具决策、6 次工具调用；达到上限后无工具强制总结。
- 同一工具与同一参数的重复调用直接复用/拒绝，避免循环与无效花费。
- 网页搜索使用 Tavily `POST https://api.tavily.com/search`，密钥只读取 `TAVILY_API_KEY` 环境变量，绝不写入 YAML、日志或仓库。
- PDF/RAG 片段仍是财报数字的一等证据；网页结果仅作外部补充，最终响应把两类来源分开展示。
- MCP 清单拉取失败时仍使用既有内置工具定义；网页搜索不依赖 MCP 熔断状态。

## 事件协议

在既有 `delta`、`tool_call`、`tool_result`、`done` 上新增：

- `reasoning_stage`：`assess`（判断证据）、`retrieve`（检索）、`review`（核验）、`answer`（组织回答）；包含 `round` 和用户可读 `message`。
- `done.web_sources`：受控的 `{title,url,content,published_date}` 列表，前端以“网页补充来源”单独渲染为可点击链接。

## 交互

过程状态进入与工具步骤相同的轻量卡片，沿用现有加载样式而不是抢占回答区。状态卡使用文本而非仅颜色表达状态，并带 `aria-live="polite"`；最终回答到达后保留已完成步骤，网页来源紧随本地财报引用之后。

## 验收

1. 工具定义能够在 MCP 清单失败时回退；配置了 Tavily key 时注入 `web_search`。
2. 模型可执行两轮以上不同工具调用，达到限制仍能给出最终回答。
3. 缺失 key、HTTP 失败、重复查询都返回可解释结果，且不会泄露 key。
4. SSE 顺序包含判断、调用、结果、核验、回答；网页来源透传到前端。
5. 现有纯 RAG、MCP、会话持久化行为不回归。
