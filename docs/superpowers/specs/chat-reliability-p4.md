# 智能问答可靠性第四阶段：运行级评测、检索质量与上下文预算

日期：2026-10-08。设计基线：本地 `main` `e000f96`（P1–P3 已合入）。全局任务：TASK-20260924-006。

## 状态、目标与边界

用户已确认 P4 的方案方向；本文件是供其审阅的 P4 **详细设计**，不是实施授权或实施计划。P4 在设计台账保持「待实现／先补计划」；实施前须另写可执行计划并取得确认，在隔离分支开发、验证，合入 `main` 前另行授权。不推送远端，不隐式访问真实模型、外网、MCP、行情或生产账号。

目标：通过**运行实际 ASGI/SSE 问答编排**建立可复现质量与成本基线，在同一基线上比较检索和上下文改动；保证已有 P1–P3 Scope、来源授权、事实核验、研究恢复与终态合同不回归。

非目标：替换向量库/Agent 框架、自动下载新模型或财报、建立线上质量监控服务或工作台新页面、把模型判分当作事实真值、从离线替身推断真实提供方正确性。P3 未覆盖充分的并发容量/研究停止恢复浏览器检查可作为运行级验收补充，但不冒充答案质量提升。

## 现状与方案选择

现有 `webapp/chat_evaluation.py` 和 `scripts/run_chat_evaluation.py` 严格回放固定 `AnswerRun`/`ResearchRun`，只能证明序列化产物的安全合同，不能衡量真实编排的路由、检索、取数次数或首响应。`financial_report_fetcher/rag/qa.py` 已有 Scope 硬过滤和可选 reranker，但 `_context_lines` 每条仅用 `text[:300]`；`webapp/server.py` 仍从最近 8 条消息构建历史。固定消息条数/字符数不等于 token 预算，也无法证明关键证据没有被裁掉。

候选方案：

1. **采用：基线先行，随后检索与上下文各自受控比较。** 独立评测 runner 走完整编排，替身提供方隔离网络；每个候选优化在同一输入、语料、替身版本与预算下比较。能够归因，默认不改线上调用。
2. 同时改三部分后一次验收：开发路径短，但指标变化无法归因，容易掩盖证据丢失；不采用。
3. 以真实提供方直接建立唯一基线：更接近线上但结果随时间、费用和凭据变化；只保留显式人工探测，不作为默认 CI 或交付证明。

P4 是一个总设计，实施按依赖划为三个有自身验收结果的工作包：**运行基线 → 检索比较 → 上下文预算**。工作包是内部交付切片，不擅自把 P4 之外功能并入本期；后两包必须以前一包的可复现实测结果为依据。

## 工作包一：运行级评测与可复现基线

### 入口与数据流

新增与现有固定回放命令分离的**显式离线 runner**。runner 从版本化场景清单构造临时会话和隔离存储，向真正的 `POST /api/chat/stream` 发送请求、解析有序 SSE，再按场景使用 `GET /api/chat/research/{run_id}`、停止/恢复接口核对持久化运行。注入固定模型响应、PDF 检索命中、MCP/腾讯行情、网页结果、时钟及受控阻塞/失败；必须在网络入口设默认拒绝，漏注入的来源使该用例失败，绝不能回退真实 provider。保留旧 `FixtureAgent` 与质量侧车语义，不让新 runner 假装自己只是旧产物回放；既有工作台只读聚合 API 不自动读取逐题原始报告。

每个用例的清单包含：稳定 ID/版本、问题与多轮输入、冻结的公司及期间/市场窗口、允许来源、预期路由/终态、关键事实与可接受答案断言、必须引用的证据身份、禁止引用/禁止断言、模拟提供方响应及调用上限。测试语料限定在仓库可追溯的脱敏样本，PDF 命中含真实页码/报告身份和金标准证据定位；预期结论采用人工核对的事实/关系与禁止性断言，而非整段答案字符串或另一个模型的自由评分。证据是否**支持**结论，需要断言主体、期间、单位、数值/关系及引用定位一致；仅引用存在不算通过。需要模型措辞开放时仅作为人工复核项，不充当自动通过项。

运行产物分两层：用例级本地详细报告（仅测试隔离目录，明确是否包含问题/原文，不进入工作台公开 API，不提交敏感产物）；可分享的白名单聚合（计数、比例、延迟和安全失败码，不包含 prompt、来源正文、工具参数、路径/URL 中的私密信息）。记录代码 SHA、场景集版本/语料哈希、替身版本、配置、时区、模型标识或“固定替身”、索引版本及运行时间；基线与候选必须对齐这些维度，否则标为不可比较。报告写入使用独立输出路径与原子替换，不覆盖现有 `data/research_quality_summary.json`。

### 测量与判定

按场景分别记录：路由/Scope/允许来源、答案关键结论正确性、引用支持率（分母为有金标准的论断，不把“未要求引用”当 100%）、时效/时间口径、来源**实际物理尝试次数**及失败/重试、SSE 首身份/首内容/总时长、token 用量与费用。token 只采集提供方明确报告的用量；缺失记为 `unknown`，不以字符数伪装真实用量或价格。价格只在已显式配置费率且有可信用量时计算，注明费率版本；其余报告为不可计算。首次 SSE 身份与首内容分开统计，避免 P3 立即返回身份掩盖慢模型。

场景至少分组：PDF 数字事实与同公司多期、无本地报告的行情、日/周复盘截断口径、常识与时效性问题、显式研究计划、连续追问保留公司/期间、来源部分或全部失败、取消及研究恢复（已完成步骤不重复）。每个场景既检查事件也核对最终 `AnswerRun` 与研究步骤。负向探针（跨公司/跨期越权、伪造最新、无支持数字、错误终态）与健康集分开统计，不能以总体均值抵消安全失败。

自动阻断条件为任一 Scope/来源授权越界、无支持的确定性数值、伪造数据时间、终态伪装或研究恢复重复取已完成来源；质量指标与既定基线逐类对照，关键事实/引用支持不能下降。首次基线不预设凭空的“提升百分比”；目标阈值、允许的延迟/调用数变化必须在实际基线产出后，由计划记录并经用户确认，避免事后调阈值。差异同时列出分子/分母与逐类失败，不仅给总通过率。

### 可选真实提供方探测

另设**显式 opt-in** 的人工命令，必须同时指定允许的提供方/账号环境、用例白名单、最大调用数、总费用上限与超时，默认关闭且不加入 pytest/CI。敏感凭据只由受控环境提供，不写入 fixture/报告/日志；不操作生产账号、不自动下载外部模型/语料。真实探测结果与固定替身基线分栏展示，注明无法完全复现、取数时间和开销；缺少可靠用量或费率时不得声称费用可控，直接拒绝含费用上限的运行或将其限制为人工预授权的调用预算。

## 工作包二：以评测驱动检索改进

为索引中的脱敏 PDF/分析语料记录预期 `report_id`、页码、章节和包含关键数值/上下文的段落位置，区分“候选未召回”“召回但排序靠后”“已召回但被上下文截断”“答案引用错位”。比较相同索引/同一查询下的候选集、原有向量排序、可选 reranker 和上下文选择，不把生成文本流畅度当召回率。

先调整 `_context_lines` 的盲目 `[:300]`：在预算内按证据相关片段与邻近上下文选择，保留报告身份、页码和引用 ID；窗口不足则标为证据不足，不截掉限定条件后仍宣称可证。对跨页 PDF，现有章节分块若只保留 `start_page` 会使实际证据页码失真；任何分块修改必须使索引定位与原始页一致，旧索引不在未迁移时被解释成“精确页”。分块策略变化需单独版本化索引，使用临时索引做离线对照和回退；不得在同一索引上无提示混用新旧 chunk 身份。新增 rerank 仅在原有可选能力内优化候选和触发阈值，不引入新模型依赖为默认值；模型不可用时退回经验证的原排序。

默认策略切换前必须看到目标事实召回/证据定位改进，且无跨 Scope、引用失真或关键场景退化；记录查询延迟/本地资源成本。若评测没有识别稳定漏召回，保留现状并如实报告“未采纳检索改动”，不为了完成任务而重建索引。

## 工作包三：受控上下文预算与连续追问

设计唯一的消息构建边界，供普通问答生成及研究恢复使用；接收规范化 user/assistant 历史和服务端冻结的 Scope、期间、来源证据。只将经过白名单投影的 `role`/文本交给模型，拒绝历史中伪造的 `system`/`tool` 指令，保留当前问题和最新明确确认的范围，不从旧答案推断未确认新事实。研究恢复沿用原问题、原工具策略和已完成步骤的持久化证据；压缩不能让恢复重新调用已完成来源。

预算以具体模型/提供方已知的上下文窗口、输出预留和安全裕量计算输入上限；可用 tokenizer 时使用其确定性计数并记录版本，未知模型无可信 tokenizer 时采用有界保守估算并标注为估算，**绝不保证**完全等同真实 token 或让估算超限悄悄放行。按优先级保留服务端策略/Scope、当前问题、必要证据及引用定位、近期确认过的问答，再压缩较早对话和冗余来源片段。确定性摘要只能从已保存事实提取，不让另一轮模型自行改写公司、期间或结论；原始会话不修改，缩减消息为临时运行产物且不泄漏私有推理。预算内仍放不下必需证据时返回诚实的部分/澄清结果，不生成假定已引用的确定性结论。

对至少“连续追问保留公司及期间”“长历史中旧指令不扩权”“PDF 长段落数值位于第 300 字以后”“研究恢复不重取”“极小预算诚实降级”跑同源对照；分别报告实际/估算 token、引用支持、答对率、首内容/总时长、调用数。任何事实或 Scope 回归使该压缩方案不得作为默认值。

## 文件责任与兼容约束

实施计划再精确拆分文件：新 runner/场景 schema 与聚合报告只负责评测；现有 `webapp/chat_evaluation.py` 固定回放与公开质量侧车保持兼容，不在同一类中混入运行提供方副作用；`financial_report_fetcher/rag/{qa,chunking,reranker,ingest}.py` 仅调整经基线证明的检索边界；新增纯消息构建/预算模块供 `webapp/server.py` 和 `financial_report_fetcher/rag/qa.py` 复用，不让巨大 server 路由继续承载预算细节。若持久化模型需要元数据版本升级，旧 `AnswerRun` 保持可读；不把精简历史覆盖会话原文。

本阶段不新增必须联网的依赖，不改变现有 P3 120/300 秒整轮期限、worker/事件缓冲上限，不修改 P2 来源调用预算与公司/时间硬边界；所有测试以离线替身和隔离数据为默认。真实模型/数据结果仅为另列人工证据，不替代可复现离线门槛。

## 实施顺序、验收与剩余风险

1. **先交付运行级评测**：证明不同于固定输出回放，失败注入能暴露错误路由、跨 Scope、引用错位、重复来源及错误终态；输出版本化基线、负向探针与延迟/调用数报告。隔离浏览器补测 P3 容量饱和和研究停止恢复（如果已有证据不足），但与 P4 答案质量指标分列。
2. **再交付检索对照**：只对基线识别的漏召回/截断用例引入可回退变化；索引版本及定位校验、相关聚焦单测和真实 SSE fixture 通过。
3. **最后交付上下文预算**：多轮/小预算/恢复用例通过，不丢冻结边界或必须证据；报告基线和候选的质量、调用及延迟差异。每个包均可独立审核并记录“不采纳候选优化”的理由。

全部工作包验证并经授权合入本地 `main` 后，P4 才可标记已实现；只有离线基线而没有检索/压缩的判定结果，不等于 P4 全部交付。未通过阻断项或未完成三包时在台账保持未完成，记录确切交付与缺口。跨提供方 tokenizer 不可比、人工金标准维护成本、PDF 页码迁移与真实来源非确定性是明确剩余风险，应在实施计划中给出回退与验收责任。
