# 模型执行计划器设计

**日期：**2026-09-17  
**状态：**待评审  
**范围：**智能问答所有请求先经模型生成受限执行计划，再由服务端校验、执行和记录；本轮不实施。

## 1. 背景与目标

当前 `IntentRouter` 以关键词将请求映射到固定意图，再由 `ToolPolicyResolver` 决定是否可检索财报、调用行情 MCP 或网页搜索。该机制可以 fail-closed，却不能可靠理解用户任务。例如“分析今日行情”未命中已枚举词时会落入 `report_fact`，先检索财报且禁止外部工具。

目标是让模型根据完整问题、冻结范围和当前可用来源，先生成一个**受限且可验证的执行计划**。服务端而非模型拥有权限、工具参数执行和预算控制。实时行情请求可计划“行情 → 新闻/公告 → 综合分析”，且不启动无关的财报检索。

非目标：

- 不允许模型自行扩大公司、报告期或行业范围；
- 不允许模型输出任意工具名、URL、原始工具参数或链式推理；
- 不把全部普通问答升级为长时研究任务；
- 不包含交易、下单、主动轮询或持续推送。

## 2. 核心决策

采用“**模型计划、服务端裁决、确定性执行、模型综合**”四段式结构：

1. 范围解析器先冻结 `Scope`；
2. 计划模型只从受控步骤和已声明来源能力中选择，输出轻量 JSON；
3. 服务端用 `Scope`、可用工具、配置预算和步骤依赖验证计划；
4. 执行器按已验证计划调用检索/MCP/网页搜索；所有成功、失败和跳过均形成结构化产物，最后再将结果交给回答模型。

关键词规则降为两种安全用途：模型计划不可用时的保守 fallback，以及模型计划无法通过校验时的本地来源限制；它不再是正常请求的主路由。

## 3. 领域模型与契约

新增不可变 `ExecutionPlan`，它与 M3 的 `ResearchPlan` 并存：前者服务普通问答，最多 4 步，不显示内部推理；后者继续服务显式研究任务和可恢复研究运行。

```json
{
  "objective": "分析今日行情",
  "source_mode": "external_market",
  "steps": [
    {"id": "quote", "kind": "market_quote", "required": true},
    {"id": "news", "kind": "web_search", "required": false, "depends_on": ["quote"]},
    {"id": "answer", "kind": "answer", "depends_on": ["quote", "news"]}
  ],
  "acceptance": ["标注行情数据截至时间", "说明新闻来源或其不可用状态"]
}
```

允许的 `kind`：

| 步骤 | 含义 | 服务端输入来源 |
| --- | --- | --- |
| `retrieve` | 范围内财报/历史分析检索 | 已冻结 `Scope.report_ids` |
| `market_quote` | 实时行情或市场指标 | 已授权实时 MCP 工具族 |
| `web_search` | 新闻、公告、事件检索 | 已授权网页搜索工具 |
| `answer` | 基于已执行产物写作 | 已标准化的证据、工具产物与失败状态 |

计划模型不接受 `Scope` 的写入权，服务端在反序列化前注入冻结后的 Scope；也不接受工具名、公司代码、检索 query、URL 和原始参数。执行器从步骤类型、Scope 与问题生成/约束参数：公司范围、工具白名单、超时、次数上限和网页查询绑定继续沿用当前可信问答约束。

`source_mode` 仅可为 `local_evidence`、`external_market`、`mixed`。它是展示和验证字段，不能单独授权来源。

## 4. 运行流程

### 4.1 请求规划

`POST /api/chat/stream` 保留现有 API。Scope 解析完成后：

1. 收集当前可用能力快照：本地索引是否可用、可用实时工具族、网页搜索可用性、工具预算；
2. 以问题、Scope 的用户可读摘要和能力快照调用计划模型；
3. 解析严格 JSON 并用 `ExecutionPlanValidator` 校验；
4. SSE 发出用户可读 `execution_plan`（步骤标签、来源类别、计划状态），不发送模型理由或原始 JSON；
5. 无法生成有效计划时发出 `plan_fallback`，进入保守的本地证据回答或明确说明没有可用来源。

### 4.2 确定性执行

`ExecutionExecutor` 依次运行已验证步骤：

- `retrieve` 才调用 `RagQA` 的检索层；若计划没有该步骤，绝不加载或查询财报片段；
- `market_quote` 使用实时行情 MCP 工具；
- `web_search` 使用受范围绑定的网页查询；
- 任一步失败写入失败产物；非必需步骤失败继续，必需步骤失败使最终回答诚实降级；
- `answer` 接收规范化后的产物、证据与缺失说明，不能看到原始内部计划提示。

对“分析今日行情”，计划应为 `external_market`，无 `retrieve`，因此财报片段不参与调用；行情为必需步骤，新闻/公告为可选补充。最终回答必须标注行情的 `as_of`、新闻来源及缺失来源。

### 4.3 复杂研究兼容

显式研究请求先经过轻量计划器。仅当有效计划的复杂度超过普通问答上限，或模型请求的目标确实需多阶段比较/核验时，服务端将其转换为现有 `ResearchPlan`，并进入 M3 的可恢复运行。普通行情问题不创建研究任务。

## 5. 校验与安全边界

`ExecutionPlanValidator` 必须拒绝：

- 未知步骤、重复 ID、循环依赖、超过 4 步或缺少 `answer`；
- 与能力快照不匹配的外部步骤；
- 本地索引不可用时的必需 `retrieve`；
- `Scope` 外公司、报告期、行业、工具或来源；
- 总工具调用数、轮数、超时超出服务端上限；
- 模型输出中的自由文本参数、URL、工具名、推理字段或未知字段。

校验器输出 `PlanIssue` 的受控代码与用户可读说明。计划失败不回退到“任意模型工具调用”；只允许经过既有 Scope、白名单和执行预算约束的保守路径。

## 6. 持久化、SSE 与展示

扩展 `AnswerRun`，新增：

- `execution_plan`：仅用户可读的目标、来源模式、步骤标签和验收条件；
- `execution_steps`：每步 `planned/running/completed/skipped/failed`，及规范化产物引用；
- `plan_status`：`validated/fallback/rejected`；
- `source_summary`：本地证据、实时数据、网页来源的实际使用/不可用状态。

禁止持久化模型推理、计划提示、原始 JSON、原始参数、向量距离和未经清洗的工具内容。旧 `AnswerRun` 缺失上述字段时按兼容默认值读取。

前端在回答顶部显示“已按计划：实时行情 → 当日公开信息 → 分析”一类摘要；普通问题默认折叠执行明细。SSE 新增 `execution_plan`、`execution_step_started`、`execution_step_completed`、`plan_fallback` 事件；旧客户端可忽略它们。

## 7. 模块边界

| 模块 | 职责 |
| --- | --- |
| `webapp/execution_plan.py` | 契约、JSON 解析、严格校验、用户安全摘要 |
| `webapp/execution_planner.py` | 调用计划模型；仅接收问题、范围摘要和能力快照 |
| `webapp/execution_executor.py` | 根据已验证步骤确定性调用检索、MCP、网页搜索并规范化产物 |
| `webapp/chat_models.py` | 扩展 `AnswerRun` 的兼容持久化字段 |
| `webapp/server.py` | 编排 Scope → planner → validator → executor → answer SSE |
| `financial_report_fetcher/rag/qa.py` | 提供可单独调用的检索与最终写作能力，不再决定主路由 |

原 `IntentRouter`/`ToolPolicyResolver` 仅保留为计划失败 fallback 和最低权限限制，不再据关键词决定正常请求是否调用来源。

## 8. 验收与测试

1. 单元测试：JSON 严格解析、未知字段拒绝、Scope/预算/依赖校验、兼容旧 `AnswerRun`；
2. 规划测试：模拟模型为财报、实时行情、新闻、比较问题输出计划，断言请求通路由计划而非关键词决定；
3. 执行测试：`external_market` 计划不调用 RAG，且按顺序调用行情 MCP 与网页搜索；工具失败时保留产物并诚实降级；
4. 安全回归：模型计划不得调用范围外公司、未授权工具、自由 URL 或原始参数；
5. API/SSE 测试：计划和步骤状态可恢复、旧客户端不受影响；
6. 浏览器测试：实时行情回答展示数据截至时间、网页来源和“未使用本地财报”的来源摘要。

## 9. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 计划模型输出不稳定 | 严格 schema 校验、低温度、受控 fallback 和评测集 |
| 每次请求增加延迟/成本 | 轻量 JSON 调用、短上下文、最多 4 步；复杂任务才升级研究运行 |
| 计划器试图扩权 | Scope/工具/预算全部在服务端重新裁决，计划不含原始参数 |
| 外部来源失败 | 记录失败与数据时间，禁止把失败包装成实时结论 |
| 旧会话兼容 | 新字段可选，读旧记录时填充空摘要，不伪造执行轨迹 |

## 10. 分期建议

- **P1：** 契约、计划器、校验器、单元与评测样例；不改变现有执行。
- **P2：** 普通流式问答接入计划与确定性执行；覆盖实时行情、新闻、财报三类路径。
- **P3：** `AnswerRun`/SSE/前端来源摘要与浏览器回归；将复杂计划转接 M3 研究运行。

每期均可独立验收和合入；P1 之后才允许 P2 修改主问答路由。
