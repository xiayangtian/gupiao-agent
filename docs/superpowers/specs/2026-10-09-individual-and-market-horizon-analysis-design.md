# 个股与大盘短中长期行情分析设计

日期：2026-10-09  
状态：方案草案，待用户审阅  
关联任务：`TASK-20261009-009`

## 1. 目标

使聊天问答能稳定处理个股与大盘的历史行情分析，并以同一套时间语法覆盖用户表达的不同期限，而不是通过列举“半年、一年、三年”关键词决定能力。核心能力矩阵为：

- 对象：单一公司/个股；大盘主要指数。
- 时间：显式任意合理期限、明确自然日期范围、模糊短/中/长期。
- 数据：只使用与已确认对象和冻结时间窗相符的日/周/月 K 线；所有答案能被持久化事实和来源证明。
- 结果：行情可用时给出保守分析；覆盖不足时可给部分结论并准确说明实际区间；来源不可用时明确失败，不回退到实时报价冒充历史趋势。

明确不承诺从短期价格数据推断涨跌原因，不把主要指数样本称作全市场广度或整体市场完整统计。

## 2. 用户表达与时间合同

### 2.1 显式期限通用解析

解析器应基于数字/中文数字、期限单位及窗口修饰词构造窗口，不用固定周期列表路由。第一版支持：

- 交易日：`近N个交易日`、`过去N交易日`。
- 自然日：`近N天`、`过去N日`。
- 周：`近N周`、`过去N周`。
- 月：`近N个月`、`过去N个月`、`近半年`、`半年内`（半年等价六个自然月）。
- 年：`近N年`、`过去N年`、`N年内`。
- 已支持的单日、日期范围、今日、本周、上周继续兼容。

中文数字和阿拉伯数字应得到相同语义；自然月/年回退到不存在的日时取目标月份最后一天。交易日窗口保留 trading-day 计数语义；其他自然期限先解析成 Asia/Shanghai 的 inclusive 起止日期，再按实际 K 线日期过滤。所有期限统一设安全上限：最多 800 个自然月（对应现有来源最多 800 根月 K）；超出时返回明确的“超出可查询历史范围”澄清，不调用行情源、不改走实时报价，不能静默夹到另一期限。原始期限表达识别与成功生成 MarketWindow 分开，保证超限仍留在 market_trend/market_recap 分支并给正确错误。

### 2.2 模糊时间默认值

仅当用户没有提供可解析期限但表达模糊短/中/长期时使用默认窗口：

- 短期：最近 5 个实际交易日。
- 中期：过去 6 个自然月。
- 长期：过去 3 个自然年。

具体期限优先于类别默认值；没有任何时间表达时，按既有规则澄清，不凭模型猜测期限。默认映射集中在一个服务端解析模块，并在 run 的安全元数据中记录 `window_origin=explicit|fuzzy_default|clarification`，便于诊断。

### 2.3 路由规则

时间解析与对象意图解耦：

- 明确公司/股票对象 + 历史窗口 => `market_trend`，必需来源为公司 K 线。
- 明确“大盘/A股/市场整体”对象 + 历史窗口 => `market_recap`，核心来源为固定四个主要指数 K 线。
- 当前/最新报价仍走 `market_quote`。
- “半年/一年/过去N年”本身不能把行情问题误判为财报；财务指标词仍按财务规则优先且市场词不能覆盖公司财报边界。

由解析器识别出的期限必须传入安全计划合同，模型不得覆盖对象、期限、周期粒度、来源种类或代码。

## 3. 数据频率与覆盖

Tencent K 线支持 day/week/month，每次最多 800 根。服务端应按请求窗口选择满足覆盖的最细可用粒度，并在执行端统一过滤返回数据：

- 按跨度估算采样根数：日线不超过 800 根时优先日线；否则周线不超过 800 根时用周线；再长使用月线。
- 超过 800 根月线的安全窗口时明确拒绝/澄清，不静默夹短；未超安全窗口但服务端实际数据不足时，按实际覆盖返回 partial。
- 对长跨度/日线根数不足的请求，按周线、再按月线降采样，避免 800 根日线上限导致长期窗口被静默截断。
- 不同粒度的数据 period 必须与事实 `period_kind`、来源覆盖区间和验证器一致；同一 run 不混用不同粒度冒充连续序列。
- 源数据为空、缺日期、过期、对象不符或只覆盖窗口一部分时，保留实际覆盖起止日期并返回 `partial`；绝不宣称请求完整。

大盘中长期只查询固定四大指数 K 线；现有 MCP 广度源只提供今日/近 5 日参数，故这些期限从可用计划步骤中排除 `market_overview`，避免浪费预算或错配时间窗。结果应明确说明“主要指数观察，不含对应半年/多年全市场广度”。短期大盘仅在授权、预算及时间口径匹配时调用现有广度源；广度失败不能抹掉已取得的指数证据。

## 4. 证据、分析与终态

- 个股事实绑定唯一 `Scope` 公司代码、来源调用 ID、K 线粒度、period、单位、数据截至日期。
- 指数事实绑定固定指数代码；回答只能总结返回的指数，不宣称全市场涨跌家数/资金流向，除非对应来源成功并且其时间窗口精确匹配。
- 数字及涨跌幅必须由同窗口事实/可验证派生事实推导；周/月事实不能伪装为日线事实。回退短答复用同一个确定性 verifier。
- 主要结论至少披露请求窗口、实际数据窗口、引用的对象/指数和来源；不依据价格序列推断因果。
- `completed/partial/failed` 分别反映所要求的证据合同：必需对象/窗口无可用数据 => failed；指数有效但广度明确不在该长周期合同内 => 可回答的 partial/明确受限状态；所有必需证据完整且核验通过 => completed。
- 诊断 ID 记录解析后的安全意图/窗口来源、实际 K 线粒度、源覆盖摘要、失败阶段/安全错误码和 verifier 结果，不写原始 prompt 或模型思维文本。

## 7. 风险与明确边界

- Tencent 800 根上限是单次调用上限，不保证任意遥远历史都有数据。长区间需利用 week/month 粒度；来源实际起始日期不足时必须 partial。
- 月线/周线证据需扩展现有日线专用的事实提取、期间匹配、窗口验证和 deterministic fallback，不能只改变 query parser。
- 大盘四指数不等于全市场；MCP 广度工具不能支持多月/多年度，输出和质量指标须保留此边界。
- 真实 provider 可变；完整性判断用覆盖区间/实收 bars，不用假定交易日数或响应成功码替代。
- 模糊词“短期/中期/长期”默认值是可配置、集中定义的产品策略；显式期限永远优先，后续修改不能在多个模块各自复制映射。
