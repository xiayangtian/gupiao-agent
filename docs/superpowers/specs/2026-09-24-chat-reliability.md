## 已核对的问题依据

- `webapp/server.py`：预执行结果拼成 system 历史文本；随后 RagQA 仍可再次调用工具；预执行结果未进入统一证据事件链。
- `webapp/execution_executor.py`：来源失败仍可显示“已使用”，required/dependency 未实际约束执行，answer 先于最终生成被记为完成。
- `financial_report_fetcher/rag/mcp_tools.py`：上周/本周参数相同；涨跌停池最多 50 条，不能充当全市场广度；当前聚合仅含上证指数和行业资金流。
- `webapp/chat_verifier.py`：无事实支持的百分比/点位句子能 passed，金额句子则 blocked；引用存在不等于已建立结构化事实。

- `webapp/server.py` / `webapp/static/app.js`：同步规划发生在 SSE 前；普通计划步骤事件未被前端消费；正常计划不能稳定进入研究路由。

## 第一阶段详细设计（待确认）

### 目标与非目标

目标：同一轮回答只由一套来源执行服务负责权限、调用计数、结果归一、证据和状态；回答正文、来源区、SSE 与历史记录引用同一份运行结果。

非目标：本阶段不引入新市场数据源，不重做交易日历/上周语义，不扩展数字核验算法，不改公司 Scope 模型，不重构研究任务路由，也不做完整异步/取消架构。以上缺口保持第二、三阶段未完成，不因本阶段基础设施修补而关闭。

### 方案选择

1. **推荐：统一来源执行服务，保留兼容适配。** 已验证计划先取得结构化上下文，生成阶段禁止自主外部调用；旧回退/研究/补报恢复通路的外部调用也经过同一个服务。逐步收敛，不一次重写问答系统。
2. 只给预执行结果补证据：改动小，但两层预算和失败状态继续分叉，不满足第一阶段目标。
3. 全量替换成新 Agent 框架：迁移范围过大，会把后续阶段混入本次，暂不采用。

### 1. 运行级来源执行服务

建议新增小模块承载运行级上下文和适配器，而不是继续扩张 `server.py`。

- 服务端传入冻结 Scope、实际能力快照、白名单、开关和预算；模型输出不能成为授权依据。
- 腾讯行情、MCP、网页和本地检索使用统一的结果封装；各 provider 保持既有实现，只补必要适配。
- 已验证计划走确定性来源执行 → 基于上下文生成；生成阶段不再获得可自主执行的外部工具。
- 本地财报仍可保留 `request_missing_reports` 授权申请能力，该能力不直接执行外部数据查询；下载授权边界保持原样。
- 旧回退路径、研究处理器和补报恢复若需要模型选工具，工具 executor 必须复用运行级服务，不得绕过权限、预算和结果归一。旧同步 API 不得因重构而静默改变默认行为。
- 禁用 MCP、配置白名单排除或熔断时，不得将该能力当作可用；腾讯等独立数据源按自身能力单独授权，不依赖 provider 名称猜测。

### 2. 统一结果和证据

每个来源结果携带：来源/步骤身份、成功/部分/失败/不可用状态、安全错误码、provider、数据时间（as_of）、获取时间（fetched_at）、有界的结构化内容和证据引用。

- as_of 是数据实际时间，未知则留空并披露限制；绝不能拿当前获取时间伪装数据时间。
- 适配器解析明确错误响应、空数据、非预期格式；不以“没抛异常”判定成功。未支持的格式诚实降级，不通过关键词从错误文本拼造数据。
- 原始工具输出不作为 system 指令。使用明确标记为不可信来源的数据消息，并限制大小；供应方内容中的指令没有授权效力。
- 成功/失败来源均有可审计事件；成功产物进入既有 EvidenceNormalizer/工具证据体系，失败仅保存安全摘要。
- 只有满足现有 Fact 合约的数据可进入事实列表；不因 MCP 调用成功就标成 verified。PDF 全量事实抽取和百分比核验留给第二阶段。
- 来源结果、证据事件、AnswerRun 与重开历史必须一致；禁止最终回答有来源但持久化丢失，或失败来源被显示为成功。

### 3. 整轮预算与重复调用

- 普通问题维持既有策略上限；复盘聚合的四次 MCP 与最多两次网页调用须按实际调用计数，而不是把 market_overview 当成一次。
- 有效上限取服务端策略与用户配置约束的较小值。预执行、后续追加、兼容路径不能各自获得一份新预算。
- 同轮同 provider、同工具、同冻结参数的成功调用复用结果；失败不无限重试。
- provider 隐式重试也必须有界并计入外部尝试预算；优先为新入口关闭底层隐式重试、由统一服务决定是否重试，旧调用方保留兼容默认。
- 本地检索、授权申请不占 MCP/网页预算，但仍受自身次数/候选数限制。
- 计划最多四步与真实工具次数是两个维度；不得以聚合步骤绕过工具预算。

### 4. 步骤及最终状态

- 校验并执行合法依赖顺序；依赖未满足的取数步骤不运行，记录跳过或不可用原因。
- required 来源失败：缺少关键数据时不生成确定性业务结论，可返回“无法回答/仅能部分回答”的限制说明。
- optional 来源失败：保留已有来源，允许部分回答，并披露缺失项。
- 聚合部分成功不能记为全成功；全部不可用不能显示“已使用”。来源摘要区分成功取得、部分取得、失败和未调用。
- answer 只在生成与核验结束后结算，不能在取数阶段提前标 completed。
- 复用现有 AnswerRun 状态：关键来源不满足或核验 blocked/partial 的限制回答为 partial；执行崩溃为 failed；断开为 stopped；满足要求并完成核验才为 completed。核验 passed 的覆盖范围不在本阶段夸大。
- 旧记录缺少新增字段时正常读取，不能反推“已核验/已取到数据”。
