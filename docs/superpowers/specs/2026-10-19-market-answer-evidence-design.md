# 行情回答：模型理解来源、服务端核对数字依据

日期：2026-10-19。状态：设计草案，待用户审阅；尚未实施。

## 背景与目标

运行 `33f2e27ddacf4706aecfb59e95a35142` 的腾讯工商银行实时报价已成功返回，并带有来源时间；但 `project_sources` 只为 Tencent K 线、AkShare 快照及指数日线等已知操作投影行情 Fact，未从 Tencent `quote` 投影 Fact。模型生成的行情数字经 `ClaimVerifier` 检查时找不到 Fact，被标 `unsupported_numeric_claim` 并替换成整段无法回答的提示。这是程序对提供方字段/操作的有限映射，不是必须向另一家数据商查询的“双重验证”。

目标是：行情回答的**字段理解和文字组织交给模型**，数字结论必须能回溯到本次运行的受控来源原始值；接入新供应商时尽量不用在 `chat_facts.py` 增加完整的供应商字段映射；避免模型臆造价格、误用其他证券/时间或将截断样本说成全市场。来源可用但无法确认字段语义时诚实降级，不承诺“模型引用了一个相同数字就已验证语义”。

## 范围与不变量

- 第一阶段只覆盖智能问答 `market_quote`、`market_trend`、`market_recap` 的**行情数字回答**。财报、网页、研究路径的来源/Fact/核验合同保持不变；其他金融常识降级保持不变。
- 不改变 `SourceRuntime`、`SourceAccess` 的授权、固定参数、去重、预算、取消/超时，以及 Tencent→AkShare→BaoStock 的已授权降级顺序；新浪仍禁用，未获批准不得发起额外来源调用。
- 不改变服务器按实际交易日和覆盖率判断“完成/部分完成”的规则；前一实际交易日、盘中与日线、复权口径、截断样本及跨提供方冲突不得由模型自定。**同源数字核对不等于独立双源核验。**
- 行情图表、已存在的指数派生事实与确定性缺证据降级先保持现有结构化 Fact 路径。新机制只用于回答数字的追溯与核验；第一阶段不删除旧 Fact、改变 `AnswerRun` 旧记录解释或以任意 JSON 路径驱动图表。
- 出站数据只来自本次 `AnswerContext.sources` 内的合格 `SourceResult`。状态失败、来源不在授权清单、主体/时点/窗口不符或数据被截断到无法复查的值，不能作为数字依据。

## 可选方案与取舍

1. 继续按提供方逐字段写 Fact 适配器：确定、易于驱动现有图表，但每种新行情格式都需代码变更，且漏字段时整个回答被拦。
2. 将来源原文交给模型并信任输出：兼容性强、实现轻，但无法独立发现编造数字、错证券/错时间/错单位，不满足行情答案的可信边界。
3. **采用：模型产出回答与有界数字依据，服务端独立核查本次来源快照。** 不做全格式映射；仅保留核验不可省略的身份、时间、单位、有限数值、公式和来源范围约束。代价是需要在 SSE 终态前缓冲行情草稿，并清晰处理模糊字段及计算。数字存在的核对不证明模糊字段语义正确，须在无可靠语义时降级。

## 数据合同与流程

### 1. 服务端构造行情证据包

在现有 `SourceResult` 规范化与服务端选择后，按 `call_id` 为每个合格行情结果建立**只属于当前 run 的不可变证据快照**，携带 provider/operation、服务端冻结的请求主体与时间窗口、返回的主体标识、`as_of`（数据时间）、`fetched_at`（获取时间）、status、coverage 和有界 `payload`。证据包内的 `source_id` 必须能对应当前 run 的 `SourceResult.call_id`；同一 ID 不能跨轮复用。仅已通过来源适配层安全归一的数据进入证据包，剔除上游文本中的指令与非必要敏感字段；不得把“获取时间”当作行情时点。

为每条可引用值提供稳定的行/字段定位（例如规范化 JSON Pointer 或等价的结构化路径）及有限、非布尔数值原文。服务端解析定位符而非信任模型提供的字段值。对未进入有界快照的截断部分不允许引用；快照长度、行数和字段深度有上限，超限需记录覆盖缺口。来源间同值不能据此证明独立性，也不能混成同一引用。

### 2. 模型理解并提出依据

提示词允许模型阅读**本次**有界行情证据包并解读不同供应商字段；要求返回待公开的自然语言答案及与数字论断绑定的依据列表。每条依据包含该论断在答案中的明确位置/标记、`source_id`、数据路径、主体、指标语义、行情时点、单位、原值；若为派生数值，列出输入依据、受控公式标识及输出单位。模型不得声明已经通过程序核验、不得引用包外数据或改变服务器的来源选择。结构化输出只是模型的主张，不是核验结果。

答复中每一个确定性行情数字（包括表格单元格、百分比、点数、家数与成交额）都必须对应依据；没有依据的数字不得以“外部参考”字样绕过。日期、股票代码、引用编号等标识要与数字论断区分，避免旧正则把日期误当价格；同时不能通过改写单位、拆字或无单位裸数字绕过核验。对此使用有界的结构化回答/标记协议并对最终渲染文本二次扫描；若二者对不上则降级，而不放宽检验。

### 3. 程序独立核查与呈现

服务端在模型生成**完整草稿后、发送任何行情数字 `delta` 前**进行核查：

- 来源 ID 必须属于本 run 的授权、成功/可用行情调用；路径须准确解析到快照中一个有限数值，而非模型写入的复制值或来源摘要字符串。
- 引用行的证券身份、实际数据时点、数据种类（日线/盘中）必须与冻结 Scope、请求时间窗及服务端选定数据口径一致；同名或同值的其他股票、其他时段不可代用。身份或时点仅由上游自由文本声明且不可绑定到行时，不给确定性结论。
- 原值与答案数值按允许的单位换算和明确的舍入容差核对；空值、字符串数字歧义、NaN/Inf、未声明的单位和超出容差一律拒绝。仅通过有限白名单的公式对涨跌额、涨跌幅等派生值按同一主体、合格基线（上一**实际**交易日）和同口径输入复算；不能将模型给出的公式字符串当作执行代码。
- 字段语义需有可靠锚点：已知数据合同/供应商声明的单位或字段描述可用于确认；遇未知、歧义或冲突字段，仅“路径存在、数值相同”不足以放行“最新价/成交额/全市场总量”等确定性语义。服务端不需要为每种来源列完备映射，但需要一个小型可审核的语义/单位边界；无法核实时说明哪类指标不能确认。
- 复盘全市场广度/成交等口径还需现有覆盖率与样本不变量通过；单一来源数字不得被表述为全市场总量，来源冲突不平均、不择优隐藏。

依据与答案全数一致才报告 passed。局部论断失败时只发布能安全拆分、且独立通过核查的完整句/表格；如不能确定安全裁剪（跨句推断、表格数字或总结依赖失效指标），整个行情数字段降级。始终披露来源、实际行情时点、覆盖限制及“外部参考”；缺失或不可信时保持 partial/unavailable，不生成确定性行情结论。`VerificationReport` 应保留有限错误码及被拒原因，不持久化原始模型思考或无限长度源数据。

## 流式回答与失败处理

当前 `RagQA.answer_from_context` 和 `_relay_rag_event` 会立即向客户端转发模型文本 `delta`，而 `server.py` 在 `done` 后才验证；旧做法会短暂显示未核验数字再替换终态。本方案对**行情模式**引入专门的草稿缓冲与终态核验：可以继续发送步骤进度、来源状态和“正在核验”提示，但在通过前不得发送正文数字 `delta`、不把草稿持久化为最终答案，也不得由续写/证据 fallback 绕过门禁。核验通过后才释放完整文本（可按块播放已核验内容）；超时、取消、模型错误、结构化输出不合法、证据包超限或无法解析时不继续发布草稿，保留已安全取得的来源状态并按既有终态语义标记 partial/failed/stopped。

作为受控兼容，行情证据包不足时可沿用**现有已核验 Fact 驱动的确定性安全摘要**，但必须经过同一运行范围和终态规则；不得把旧不受支持的模型数字直接复活。对于需要实时问答的一般描述，可输出“取得数据但某数值暂不能确认”的简短说明。旧会话仍按旧 `AnswerRun` 结构读取，不回填或重验历史回答。

## 验收与风险

- 最小回归：模拟 run `33f2e27ddacf4706aecfb59e95a35142` 的**去标识、非真实用户数据**形状，成功来源可支持同主体同时间的价格论断；答案中的错证券、错时间、错单位、错字段语义、编造裸数、错路径、虚假“已核验”、非法公式均不得放行。不是直接重放真实会话或对真实数据执行删除/写入。
- 多格式：测试相同语义在两种不同来源结构中由模型提出不同路径并获核查；含糊/未知字段返回 partial 而非“通过”。来源不足、取消、预算耗尽、连续失败和旧 AnswerRun 的退化行为明确可复查。
- 时序：监听真实 SSE 流，断言**所有**行情答案正文数字在核验事件前不可见；最终答案和持久化 run 一致；服务器已发来源状态不等同数字核验成功。
- 聚焦 `test_chat_execution.py`、`test_chat_verifier.py`、`test_chat_facts.py`、`test_server_api.py`、`test_source_runtime.py` 及必要的浏览器交互/desktop-tablet-mobile QA；对财报、网页、原行情表格及图表做直接影响回归，检查没有未经授权出站或额外调用。
- 风险：受控快照不含必要字段会导致继续 partial；模型可能误解无语义描述的字段，因此程序不得只比较数值；结构化答案/正文可能不一致，宁可降级；缓冲降低逐字输出体验并占用有界内存；不能通过本方案宣称实现了双源核验或支持任意来源格式。
