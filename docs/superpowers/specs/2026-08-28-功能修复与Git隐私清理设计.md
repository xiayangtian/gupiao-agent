# 功能修复与 Git 隐私清理设计

## 背景

当前代码审查发现三类需要优先处理的问题：

1. 未指定会话 ID 的并发聊天可能复用同一个空会话，导致对话串线。
2. 启动脚本的配置优先级与应用层约定不一致，并会回显 API Key 片段。
3. Git 历史包含本机绝对路径，预提交扫描也存在可绕过的整行豁免。

此外，下载器直接写入最终 PDF 文件，进程中断时可能留下之后会被误认为完整文件的部分内容。

## 目标

- 保证并发发起的新聊天使用独立会话。
- 统一 AI 配置优先级为：显式构造参数 > 环境变量 > `config.yaml` > 默认值。
- 任何日志和终端输出都不回显 API Key 内容。
- 防止真实密钥、本机绝对路径和个人邮箱误入新提交。
- 下载只在 PDF 通过基本完整性校验后原子替换最终文件。
- 在所有功能验证通过后，将本地 Git 历史合并为一个干净的根提交。

## 非目标

- 本轮不大规模拆分 `webapp/server.py` 和前端 `app.js`。
- 本轮不引入新的 Web 认证系统。
- 本轮不切换财报数据源协议或修改外部 API 契约。
- 本轮不匿名化 GitHub 账户名或提交作者身份。

## 设计

### 1. 会话创建语义

`ChatStore.get_or_create(sid)` 保持单一、稳定的语义：

- `sid` 存在且有效时返回对应会话。
- `sid` 缺失或无效时创建新会话。

`POST /api/chat/sessions` 仍可以复用已有空会话，用于避免用户反复点击“新会话”造成空记录堆积。聊天请求未携带 `session_id` 时不走该复用逻辑，从而保证并发数据隔离。

### 2. 配置优先级

`AIClient` 继续作为 AI 配置合并的唯一执行点。`start.sh` 不再解析 `config.yaml`，也不再修改 `AI_API_KEY`。这样可以避免 shell 层和 Python 层产生两套不同优先级。

启动脚本可以提示“AI 配置将由应用加载”，但不输出密钥的任何前缀、后缀或长度信息。

### 3. 敏感信息扫描

保留现有预提交钩子，但把“整行安全”改为“具体匹配值是否为占位符”：

- 花括号不再使整行跳过。
- 只有匹配到的密钥值本身具有明确占位符特征时才豁免。
- 新增 macOS/Linux 用户目录绝对路径检测。
- 保留示例邮箱域名豁免，真实邮箱继续拦截。
- 扫描输出只显示截断后的命中内容。

单元测试将直接覆盖 JSON/字典行中的密钥、占位符、示例邮箱、真实邮箱和本机路径。

### 4. PDF 原子下载

下载流程改为：

1. 下载到与目标文件同目录的唯一临时文件。
2. 校验内容非空且以 `%PDF-` 签名开头。
3. 成功后使用 `os.replace()` 原子替换最终文件。
4. 任何失败都删除临时文件，不留下可被误判的部分 PDF。
5. 已存在文件只在签名校验通过时返回 `SKIPPED`；零字节或非 PDF 文件会重新下载。

### 5. Git 历史重构

功能修复和全量验证完成后：

1. 创建一个不会被推送的本地备份引用，指向重写前的 HEAD。
2. 将设计文档中的本机绝对路径改为通用相对路径。
3. 以当前最终工作树内容构造新的单一根提交。
4. 保留用户的 GitHub 提交身份，不匿名化作者名称和邮箱。
5. 扫描新 HEAD、所有可达历史、Git 作者元数据及已跟踪文件列表。

备份引用在确认新历史无误后删除，否则旧提交仍然会被“所有引用”扫描命中，也可能被误推送。

## 错误处理

- 会话写入失败保持现有 API 错误路径，不隐式合并到其他会话。
- 配置文件解析失败由 Python 应用层统一记录和处理。
- 敏感信息扫描脚本无法读取 Git diff 时应阻止提交，不再默默视为安全。
- PDF 下载失败返回 `FAILED`，并保证临时文件被清理。

## 测试与验证

- 先运行已失败的会话单测试和并发 API 测试，确认红灯原因与设计一致。
- 为启动脚本、敏感信息扫描和 PDF 原子下载新增最小回归测试，每项先验证失败再实现。
- 运行定向测试、完整 `pytest` 测试、`git diff --check` 和 shell 语法检查。
- Git 重构后重新运行完整测试与敏感信息扫描，并确认仅存在一个根提交。

## 验收标准

- 两个并发的新聊天使用不同 session ID，消息数据不交叉。
- 全量测试通过。
- `start.sh` 不解析或回显 API Key。
- 带花括号的真实密钥仍被拦截，占位符不误报。
- 下载中断或非 PDF 内容不会覆盖最终文件。
- 新 Git 历史不包含 `/Users/<name>/...`、`/home/<name>/...`、本地密钥或不应跟踪的运行数据。
- 最终提交保留用户的 GitHub 作者身份。
