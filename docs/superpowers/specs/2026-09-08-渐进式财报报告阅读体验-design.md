# 渐进式财报报告阅读体验设计

## 目标

将动态证据化财报分析从“多卡片信息面板”改为“精简摘要 + 单列报告正文 + 统一证据区”的阅读体验。读者应当快速识别重点、风险与待核验信息，并能从 PDF 证据跳转到对应页。

## 背景与问题

当前 `renderProgressiveAnalysis()` 将每条结论渲染为 `.analysis-finding` 卡片，并在卡片内嵌可展开证据。结果是：

- 多层边框切碎了长文本，阅读连续性不足；
- 正文、说明、重要数据普遍偏灰，缺少优先级；
- 主题 Tab 只改变边框/文字颜色，难以区分；
- 一条结论的多个证据散落在正文中，用户无法集中核验；
- PDF 证据虽含页码，但不能带用户定位到中栏预览的对应页。

本设计沿用用户认可的农业银行 2025 年报阅读感：克制的金融研究报告式排版、清晰层级、有限且有语义的颜色。

## 范围

### 包含

- 分析右栏的动态结果渲染：顶部摘要、主题导航、正文、统一证据区；
- PDF 证据点击后定位当前报告的中栏 PDF iframe；
- 对结构化、PDF/OCR 证据给出不同但一致的展示信息；
- 分析页专属 CSS token、深色正文、风险/重点/待核验状态和响应式规则；
- JavaScript 单元测试及已有分析页面测试的更新。

### 不包含

- 改变分析模型、证据生成、报告下载或后端 API；
- 修改历史页的旧版 Markdown 报告展示；
- 新增 PDF.js 或服务端页图渲染；
- 依据颜色单独传达信息（所有颜色状态同时带文字标签）。

## 页面结构

分析数据继续通过 `AnalysisWorkflow.renderProgressiveAnalysis(state)` 产出 HTML，保留现有 `state` 和 SSE 事件契约。

### 1. 精简摘要区

位于 Tab 上方，使用 `analysis-report-summary`：

- 显示“本期要点”标题和快速结论条数；
- 最多显示前三条 `quick.conclusions`；
- 每条使用轻量 `summary-item`：语义标签、结论正文、关键数据；不使用圆角卡片或外层阴影；
- 标签根据 `risk_state` / `style` 映射为“风险”“重点”“观察”，未知状态使用“待核验”；标签始终显示文字；
- 没有快速结论但存在 observations 时，沿用“参考观察”文案并使用观察样式；完全无结果时显示现有空状态提示。

### 2. 主题 Tab

保留“快速结论”和动态主题，重构为报告目录：

- 每个 Tab 带小型序号圆点、标题、结论数量；
- 激活项使用深蓝底色、白色文字和底部强调线；未激活项使用浅色背景与深色文字；
- 快速结论固定为第 1 项，动态主题按现有 sections 顺序编号；
- 维持 `data-analysis-tab`、`role=tab`、`aria-selected`，不改变 `app.js` 既有切换机制；
- 允许窄屏横向滚动，按钮文本不截断且保持可见 focus ring。

### 3. 单列正文

Tab 内容显示为 `analysis-report-body`，每个主题含：

1. 标题和可选 summary；
2. 结论按纵向排版，使用细分隔线而非完整边框；
3. `claim` 使用 15px 以上深色正文，`key_data` 使用 tabular figures 和强调色；
4. `significance` 是较小但可读的深灰补充文字；
5. 风险结论增加红色左侧标线和“风险”标签；重点结论增加蓝色标线和“重点”标签；观察使用橙色标线和“观察”标签；
6. `highlight_spans` 仅用低饱和背景色和字重强调，不能降低文字对比度；
7. 每条结论底部只显示“引用证据 N”锚点，点击滚动到本 Tab 的统一证据区；不在正文展开 `details` 证据列表。

正文主文字使用 `--text-primary`，补充说明使用对比度达标的 `--text-secondary`，`--text-muted` 仅用于非关键元信息。

### 4. 统一证据区

每个 Tab 正文后生成一个去重后的 `analysis-evidence-section`：

- 由该 Tab 的 quick conclusions 或 section findings 的 `evidence_ids` 聚合并保留首次出现顺序；
- 标题为“证据与出处（N）”；
- 每条显示编号、来源类型、标签、证据摘录，以及结构化来源的值/单位/期间；
- PDF_TEXT 与 OCR 证据在 `source_locator.page` 为正整数时呈现为 `<button data-evidence-page="N">PDF · 第 N 页</button>`；
- 点击按钮时触发一个自定义 DOM 事件 `analysis:evidence-page`，detail 为 `{ page: N }`。`app.js` 监听该事件，将现有 `#pdf-frame` 的 src 更新为当前报告预览 URL 加 `#page=N`，并滚动/聚焦中栏 PDF 预览面板；
- 若没有当前选中报告或页码不合法，按钮不渲染，仍显示不可点击的来源标签；
- iframe/document viewer 不支持锚点时浏览器仍会打开同一 PDF，标题/文本保留“第 N 页”以使用户可手动跳转；
- 结构化证据不生成页码按钮，避免暗示不存在的 PDF 定位。

自定义事件只传页码，不携带未经转义的证据文本；HTML 仍全部使用 `escapeMarkup()`。

## 视觉语言与可访问性

- 基调：白色表面、浅灰分隔、深海军蓝为主强调，绿色仅用于正向/成功，红色仅用于风险/错误，橙色用于观察/待关注；
- 颜色不独立传达信息，所有状态都有可读标签；
- 正文和可交互文本满足至少 4.5:1 对比度；
- 证据按钮、Tab、结论证据锚点有 `cursor:pointer`、hover、`:focus-visible`；
- `prefers-reduced-motion` 下不添加或保留会分散阅读注意力的动画；
- 在 1180px 以下，现有右栏会变为整行区域，报告内容最多占满该区域；在 560px 以下，Tab 维持单行横向滚动，证据项换行而不是截断。

## 错误与兼容性

- 状态缺少 evidence_catalog、evidence_ids、source_locator 或页码时，分析正文必须正常渲染，只省略相应证据入口；
- 未找到 catalog 中的 evidence id 时，不输出空证据条目或无效按钮；
- 保持旧分析缓存可读：没有 `risk_state`、`style`、`highlight_spans` 时使用“重点/待核验”的安全默认展示，不依赖新增后端字段；
- 不修改分析结果 JSON，因此已有缓存、SSE 快照与后端测试无需迁移。

## 验收标准

1. 农业银行 2025 年报和 2026 半年报的分析内容显示为摘要 + 报告式单列正文，不再出现每条结论一张完整边框卡片；
2. 主正文、重点数据、风险和观察可以在不依赖颜色的情况下区分；
3. 每个主题的证据只在底部统一出现一次，正文结论仅有引用锚点；
4. PDF/OCR 证据的页码按钮能让中栏 iframe URL 包含 `#page=<页码>`；
5. 结构化证据不生成 PDF 页码按钮；
6. 原有 Tab 键盘语义、分析进度、历史结果、PDF 下载和窄屏布局不回归；
7. 新增和相关单测通过，随后进行两份农行报告的人工验证。
