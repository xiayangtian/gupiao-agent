# 财报分析前端界面 — 设计文档

- 日期：2026-08-03
- 状态：已评审通过
- 目标版本：v1（本地单用户工具）

## 1. 背景与目标

现有 `financial_report_fetcher` 是纯 CLI 工具（download / analyze / chat 三个子命令）。
目标：为其开发一个本地 Web 前端，在浏览器界面内完成「选股 → 查财报 → 预览 → AI 分析 → 自由问答」全流程。

**核心需求**（用户确认）：
- 输入股票名称或代码，支持自动补全
- 查询年报/半年报/季报（一季/三季），默认近 3 年、年份范围可切换
- 浏览器内 iframe 预览 PDF
- 分析 = 预设三个维度（财务摘要 / 风险识别 / 经营亮点）+ 自由问答
- 不做的：登录权限、任务持久化、拼音/英文名搜索、报告在线编辑

## 2. 技术方案

**FastAPI 后端 + 原生 HTML/JS 单页**（用户选定方案 A）。

- 复用现有模块：`CNINFODatasource`（自动补全索数据源 + 财报查询）、`ReportAnalyzer`（分析/问答）、`AIClient`（模型调用）
- 新增依赖：`fastapi`、`uvicorn`、`pypdf`
- 前端无构建工具：一个静态页 + 原生 JS（fetch）+ 手写 CSS

## 3. 模块结构

```
webapp/
├── __init__.py
├── server.py            # FastAPI 应用 + 路由 + 静态文件
├── autocomplete.py      # 股票索引构建与自动补全搜索
├── tasks.py             # 长任务执行器（线程池 + 内存任务表）
└── static/
    ├── index.html       # 单页界面
    ├── app.js           # 原生 JS
    └── style.css        # 手写 CSS
```

启动：`uvicorn webapp.server:app`（本地 8000 端口），等价入口 `python -m webapp.server`。

### 3.1 autocomplete.py

- 后台线程启动时调 `CNINFODatasource.build_known_companies()` 构建索引（实测 ~1 秒）；
  构建完成前，补全 API 同步等待（最长 5 秒），避免前端拿到空结果
- 匹配规则（三级优先级）：
  1. 代码前缀匹配（`q` 为数字时）
  2. 名称前缀匹配
  3. 名称包含匹配
- Top 10 返回 `[{code, name}]`

### 3.2 server.py — REST API

报告的唯一标识使用 **报告期**（`{code}/{period}`，period 为 YYYY-MM-DD）：
同一公司同一报告期只有一份财报，天然唯一；一季报（3-31）与三季报（9-30）不会混淆。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/companies?q=` | 自动补全，Top 10 |
| GET | `/api/companies/{code}/reports?start=&end=` | 财报列表（类型/报告期/标题/本地是否已下载） |
| GET | `/api/reports/{code}/{period}.pdf` | PDF 文件流（iframe 预览） |
| POST | `/api/reports/{code}/{period}/analyze` | 启动分析，返回 `task_id` |
| POST | `/api/reports/{code}/{period}/chat` | 对指定财报提问（带会话历史） |
| GET | `/api/tasks/{id}` | 任务状态轮询：`{status, progress, result}` |

分析时由 period 推断财报类型（12-31 年报 / 6-30 半年报 / 3-31 一季 / 9-30 三季），用于落地文件名。

### 3.3 analyzer 小改动（唯一既有代码修改）

`ReportAnalyzer.analyze()` 增加可选 `meta` 参数（`ticker` / `year` / `company`），
传入时跳过文件名正则解析（新文件名 `长江电力_600900_年报_2025.pdf` 下原正则
解析不完整）；新增非交互式 `qa()` 方法供 Web 问答使用（CLI 的 `chat()`
保留不变）。参数缺省时行为与现状一致，不破坏 CLI 与既有测试。

### 3.4 报表与文件约定

- PDF 存放 `reports/`，命名 `长江电力_600900_年报_2025.pdf`（与 CLI 互通）
- 分析报告落盘 `reports/analysis/`（与 CLI 互通）
- PDF 只有首次预览时需要下载；已下载项在列表标记 ✓，直接预览本地文件

## 4. 页面交互（三栏单页布局）

```
┌────────────────────────────────────────────────────────────┐
│  财报分析工具                          [AI 状态·已连接/未配置] │
├────────────────────────────────────────────────────────────┤
│  股票搜索框（自动补全下拉）  年份：[2023] ~ [2025]   [查询]   │
├──────────┬────────────────────────────────┬────────────────┤
│ 财报列表  │  PDF 预览（iframe）            │  分析面板        │
│ 2025年报  │                                │  维度：□财务摘要 │
│ 2025一季  │                                │       □风险识别   │
│ 2024年报  │                                │       □经营亮点   │
│ ...      │                                │  [开始分析] ⏳进度 │
│          │                                │  [自由问答输入框] │
│          │                                │  问答历史...      │
└──────────┴────────────────────────────────┴────────────────┘
```

交互流程：
1. 输入 ≥1 字符即触发补全；选中后自动查询该股票
2. 列表按类型分组，已下载打 ✓；点击 → iframe 预览（未下载先自动下载并提示进度）
3. 分析：预选三维度可勾选 → 「开始分析」→ 每 2 秒轮询任务 → 分维度卡片渲染 → 可下载 `.md`/`.json`
4. 自由问答：同一财报下多轮提问，后端保留最近 4 轮上下文
5. 分析任务在同一时刻只允许 1 个（串行，避免并发消耗 AI Key）

## 5. 错误处理

| 场景 | 表现 |
|---|---|
| `AI_API_KEY` 未配置 | 顶栏黄色警告；分析/问答禁用并提示配置方法 |
| 巨潮接口查询/下载失败 | 列表区红色横幅 + 重试按钮 |
| 分析任务失败 | 轮询得 `failed` + 错误信息，显示失败卡片 |
| 无财报 | 空状态提示「该股票近 N 年无此报告」 |

## 6. 测试

- 后端 pytest + TestClient：
  - 补全接口：三级匹配、Top N、空查询
  - 列表接口：类型过滤、mock 巨潮、本地已下载标记
  - 分析任务：入队 → 状态流转 → 失败路径；并发只 1 个
  - 问答接口：带历史、无 Key 友好报错
- 现有 154 项测试保持全绿
- 手动验收：补全「600 / 长江」→ 列表 → PDF 预览 → 三维度分析 → 自由追问 → 未配置 Key 的提示

## 7. 不做的事（YAGNI）

- 不做登录 / 权限（本地单用户）
- 不做任务持久化（内存表，重启即清）
- 不做拼音/英文搜索
- 不做报告在线编辑
- 不做多用户并发

## 8. 验收标准

1. 起服务后可完成：输入「长江电力」→ 出现 2023-2025 年报列表 → 预览 2025 年报 PDF
2. 三维度分析生成可读报告并保存到 `reports/analysis/`
3. 对 2025 年报提问"现金流状况如何？"获得合理回答并可追问
4. 未配置 `AI_API_KEY` 时界面给出明确引导
