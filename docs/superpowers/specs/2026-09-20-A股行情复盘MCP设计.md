# A 股行情复盘 MCP 设计

**状态：**已确认，待实施  
**范围：**仅 A 股日度/周度行情复盘；不覆盖港股、美股或全球市场。

## 目标

让“今日行情”“日度复盘”“上周行情复盘”等请求由模型计划为市场数据工作流：先取 MCP 结构化行情，再取板块、成交、涨跌与资金流，最后用网页搜索补充事件解释。RAG 默认不参与；只有用户明确要求结合财报、基本面或公司披露时才可追加本地证据。

## MCP 工具族

| 工具 | 输出 | 日/周用途 |
| --- | --- | --- |
| `get_market_indices` | 上证、深证、创业板、科创 50 的 OHLC、涨跌幅、成交额 | 日/周 |
| `get_market_breadth` | 涨跌家数、涨停跌停、成交额、成交量 | 日/周 |
| `get_sector_performance` | 行业/概念涨跌、领涨领跌、成交 | 日/周 |
| `get_market_fund_flow` | 主力/北向（可用时）/板块资金流 | 日/周 |
| `get_market_news` | 受时间窗口约束的公告与新闻摘要 | 仅解释，不替代结构化行情 |

工具只读、时间范围受服务端规范化，最多四次 MCP 和两次网页搜索；不可用工具只产生失败产物，不中断已取得的数据。

## 执行计划

新增 `market_recap` 来源模式和服务端受控的 `market_overview` 步骤。该步骤在一次受控执行中聚合指数、广度/成交、板块与资金流 MCP 产物；模型只选择步骤种类，不能传工具名、代码、日期、URL 或参数。日度计划默认：市场概览→网页解释→回答；周度将所有行情窗口归一为最近五个交易日并要求周度累计变化。这样保持普通计划的四步上限，同时由服务端按当前交易日和请求意图生成全部 MCP 参数。

无明确公司时复盘使用市场工具；有公司但问题为市场复盘时也不自动转为个股或 RAG。个股实时行情使用既有 `market_quote`。RAG 仅在计划器判定 `local_evidence` 或 `mixed` 且用户问题明确涉及财报/基本面时启用。

## 回答与证据

回答固定组织为：市场概览、成交与广度、板块与资金、事件解释、风险/数据限制。每项结构化数据附 provider 与 as_of；网页仅作为事件来源。无可用数据时明确说明范围与失败来源，禁止由模型补造指数、板块或资金数字。

## 验收

- “今日 A 股行情复盘”计划不含 `retrieve`，至少执行包含指数和广度 MCP 的 `market_overview` 聚合步骤。
- “上周 A 股复盘”使用周窗口并给出指数、板块、资金变化。
- 网页搜索失败仍基于 MCP 数据输出部分复盘。
- “结合某公司财报解释表现”才允许 RAG，且 Scope 硬过滤仍有效。
- SSE、AnswerRun 与前端展示计划步骤、来源和数据截至时间。
