# 财务结构可视化设计

## 目标

在财报渐进式分析的对应主题 Tab 中，为利润、资产负债和现金流提供“图表辅助扫读 + 数据表精确核验”的本期结构视图。图表只使用从原始 PDF 提取、校验且可跳转到具体页码的合并口径数据；不根据结论文案解析、不反推、不猜算。

## 用户任务

读者打开某份已分析财报时，需要快速回答：

1. 本期利润由收入、成本和利润项目构成怎样的量级关系？
2. 资产、负债与所有者权益如何平衡；若为银行，贷款与存款处于什么量级？
3. 经营、投资、筹资活动对现金净变化分别贡献多少，哪些是流入或流出？

精确读数和来源必须不离开当前主题：读者可在表格中点击 PDF 页码直达原文。

## 范围

### 纳入

- 三种本期结构卡片：利润结构、资产负债结构、现金流结构。
- 独立于既有年度趋势 `metrics` 的 v4 `visualizations` 数据契约。
- PDF 抽取、指标校验、页码证据和前端图表/表格渲染。
- 重新分析后生成 v4 数据；旧报告安全降级。

### 不纳入

- 从 AI 结论文案、OCR、网页或结构化内部记录临时解析数据作图。
- 自动反推缺失项目、根据资产负债公式补齐权益、跨报告期混合口径。
- 历史报告批量重分析、打开旧报告自动重分析。
- 年度趋势图（仍由既有 `metrics` 负责，非本功能）。

## 数据模型

### 顶层契约

新分析报告升级为 `schema_version: 4`，新增可选字段：

```json
{
  "visualizations": {
    "version": 1,
    "cards": []
  }
}
```

`visualizations` 缺失、`null` 或无有效卡片时，表示未生成可用结构图；不视为报告加载失败。

### 卡片结构

```json
{
  "id": "cash_flow_structure",
  "topic_id": "cand_cashflow_004",
  "title": "现金流结构",
  "kind": "cash_flow",
  "status": "complete",
  "unavailable_reason": null,
  "rows": [
    {
      "metric_id": "operating_cash_flow",
      "label": "经营活动现金流净额",
      "value": 2876.12,
      "unit": "亿元",
      "direction": "inflow",
      "evidence_ids": ["<pdf evidence id>"]
    }
  ]
}
```

字段规则：

- `id`：`profit_structure`、`balance_sheet_structure`、`cash_flow_structure` 三选一。
- `topic_id`：由候选主题规划结果确定；某类主题不存在时，卡片不渲染，不创建虚拟 Tab。
- `kind`：`profit`、`balance_sheet`、`cash_flow`。
- `status`：`complete`（全部核心项目齐全）、`partial`（至少两个核心项目可安全绘图）、`unavailable`（不满足绘图条件）。
- `unavailable_reason`：仅 `unavailable` 时提供可读原因；前端不画空图。
- `rows[].value`：有限数值，金额统一为 `亿元`；不接受字符串、百分比或模型估算值。
- `rows[].direction`：现金流为 `inflow`/`outflow`/`neutral`；其余可为 `neutral`。
- `rows[].evidence_ids`：至少一个 `pdf_text` 且存在正整数 `source_locator.page` 的证据 ID；没有此类证据的行不能进入图表。

### 指标白名单

| 卡片 | 核心指标 | 可选指标 |
|---|---|---|
| 利润结构 | 营业收入、营业成本、利润总额、净利润 | 税金及附加、销售/管理/研发/财务费用（仅同口径时） |
| 资产负债结构 | 总资产、总负债、所有者权益 | 银行：发放贷款和垫款、客户存款 |
| 现金流结构 | 经营、投资、筹资活动现金流净额 | 现金及现金等价物净增加额 |

每张卡片须至少存在两个核心指标才可为 `partial` 并绘图。金额口径必须是合并口径且属于当前报告期。

## 抽取与校验

1. 在现有分析流程中新增独立的结构数据抽取步骤，输入为相关 PDF 页面文本和候选指标白名单。
2. 模型必须输出严格 JSON：指标 ID、显示标签、数值、单位、报告期、合并口径、PDF 页码、引用摘录。
3. 后端验证：
   - 指标属于白名单；数值有限；金额可统一换算为亿元；
   - 页码为正整数，期次等于本报告期，口径为合并；
   - 单张卡片内指标不得重复；
   - 现金流允许正负，其他金额不按数学关系补算；
   - 不完整数据标记 `partial` 或 `unavailable`，保留原因。
4. 验证通过的行写入现有证据目录为 `pdf_text` 记录，再以其 ID 引用；每条用于作图的记录必须由 PDF 原生文本坐标证明“本期”表头与数值单元格属于同一列，证据摘录只保留行名和该本期单元格；整页期次、模型声明期次或同页上期列均不得作为替代。前端继续只显示 PDF 页码和网页证据的既有规则。
5. 任何抽取/验证失败仅取消对应卡片，不得中断正文分析或影响旧报告读取。

## 前端信息架构

### 放置

图表不进入“快速结论”。

- 利润结构卡片放在收入/盈利相关主题 Tab 顶部；
- 资产负债结构卡片放在资产负债相关主题 Tab 顶部；
- 现金流结构卡片放在现金流相关主题 Tab 顶部；
- 卡片顺序：标题和状态说明 → 图表 → 语义数据表 → 原有分析段落。

主题 ID 是动态生成的，前端以 `topic_id` 匹配，不依赖固定标题或固定候选 ID；匹配失败时仅不展示该卡片。

### 图形

| 类型 | 图形 | 视觉语义 |
|---|---|---|
| 利润结构 | 横向条形图 | 同一量纲金额对比；不使用饼图 |
| 资产负债结构 | 并列/堆叠条形图 | 左侧总资产，右侧总负债与权益；银行可增加贷款/存款对比 |
| 现金流结构 | 零轴发散条形图 | 正值为流入、负值为流出；表格同步文字说明 |

使用项目内已有 Chart.js。颜色使用语义 token；现金流图的正负意义同时由表格“流入/流出”文字表达，不能只靠颜色。

### 表格与可访问性

- 原生 `<table>`：指标、金额（tabular figures）、方向/披露比率（存在才显示）、PDF 证据。
- 每一行 PDF 页码使用现有 `data-evidence-page` 机制，历史详情进入 PDF 原文并通过 `?jump=…#page=N` 定位。
- 图表 canvas 提供标题、简短文字摘要和紧邻数据表；无障碍用户不依赖图形读取数值。
- 图例和页码按钮可键盘访问，有可见焦点；图表容器提供稳定高度，避免加载后布局跳动。
- 移动端单列布局、表格不横向溢出；长指标名换行，数值列保留可读性。

## 旧报告与状态处理

- `schema_version < 4` 或没有 `visualizations`：不展示图表，不改变正文；在相应主题顶部展示一条中性提示：“重新分析后可生成结构图”。
- `unavailable`：显示后端给出的原因，不显示空画布。
- `partial`：显示图与表，并显示“数据不完整，仅展示已核验披露项”。
- 报告重新分析成功后，历史项刷新为 v4 结果并展示新卡片；不自动触发重分析。

## 测试与验收

### 后端

- 白名单、单位换算、有限数值、重复指标、正负现金流、非本期/非合并口径拒绝。
- PDF 页码/摘录写入证据目录，卡片行只能引用可定位 PDF 证据。
- `complete`、`partial`、`unavailable` 和抽取失败的序列化。
- 旧 v2/v3 报告兼容读取。

### 前端

- 三种卡片生成对应 Chart.js 配置和语义表格。
- 仅可定位 PDF 页码生成证据入口；空/无效数据不创建画布。
- 动态 `topic_id` 匹配、无匹配降级、旧报告重新分析提示。
- 正负现金流文字语义、表格列与 focus 状态。

### 浏览器

- 对包含三类已核验数据的 v4 报告检查：图、表、PDF 页码跳转。
- 桌面、平板、手机检查无横向溢出、无控制台/页面错误、无失败 API 请求。
- 旧报告与 `partial/unavailable` 卡片验证降级文案和无空图行为。

## 现实核对

| 结论 | 证据 |
|---|---|
| 既有 `metrics` 只覆盖营收、净利润、ROE、毛利率、资产负债率 | `financial_report_fetcher/facts.py:METRIC_RULES` |
| 既有指标抽取协议是年度趋势格式，不能表达本期结构与页码证据 | `financial_report_fetcher/analyzer.py:METRICS_PROMPT` |
| 现有证据模型可以表示 PDF 页码、报告期、口径与验证状态 | `financial_report_fetcher/evidence/models.py` |
| 前端已有 Chart.js 依赖但没有财务结构图渲染器 | `webapp/static/vendor/chart.umd.min.js` 与静态目录检索 |
| 样本农业银行 2026 半年报 `metrics` 为 null | 本地 `reports/analysis/农业银行_601288_2026-06-30_分析报告.json` |

## 风险与决策

- 报告披露口径差异是核心风险：宁可不画图，也不能混合口径或补算。
- 结构数据需要重新分析才能生成；历史数据不迁移。
- 任何需要网页、OCR、结构化内部来源才能证明的指标，不进入图表。
