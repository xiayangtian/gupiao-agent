# RAG 增强多维度分析 设计文档

> 日期：2026-08-18
> 状态：设计方案（未实现）
> 前置：`2026-08-17-RAG知识库与通用问答设计.md`（已实现 Phase 1/1b）的增量演进

## 1. 背景与目标

### 1.1 现状与痛点

1. **分析上下文受限于截断全文**：`ReportAnalyzer.analyze()` 对每个维度把 `_extract_pdf_text(max_chars=15000)` 的截断文本直塞给 LLM（前 10 页 + 后 10 页 + 中间 20 页，硬截断 1~1.5 万字符）。年报 150+ 页中，公司治理、行业分析、分业务数据、研发投入、ESG、风险因素等章节基本丢失。
2. **维度仅 3 个**：`ANALYSIS_TEMPLATES` 只有财务摘要 / 风险识别 / 经营亮点 + 自定义。受限的根源是内容覆盖不足，而非模板机制（模板本就是配置驱动、可扩展的）。
3. **前端已具备扩展基础**：维度 Tab 切换、勾选面板、`/analyze` 的 `dimensions` 参数均支持任意维度组合。

### 1.2 目标

1. **RAG 增强分析**：`analyze()` 的上下文来源从"截断全文"改为"按维度从 RAG 定向检索相关片段"，覆盖全文任意章节；库未就绪时回退现有截断逻辑。
2. **多维度扩展**：新增盈利质量、成长性、偿债与资本结构、营运能力、现金流、公司治理、股东回报、研发与创新、行业与竞争、战略与展望、ESG 等维度，按年报章节定向检索。
3. **前端增强**：维度勾选面板扩展 + 全选快捷按钮 + 结果 Tab 展示（沿用现有机制）。
4. **可配置**：默认维度集合、增强开关可在 `config.yaml` 配置。

### 1.3 非目标

- 不改变分析结果的落盘格式（.md/.json 结构兼容，仅维度数量增加）。
- 不做多轮/智能体式自主分析（仍为"每维度一次 LLM 调用"的确定性管线）。
- 不做分析结果跨报告对比（属 Phase 2）。

---

## 2. 总体架构

```text
analyze(报告)
  ├─ 1. 确保已入 RAG（auto_ingest_report 幂等；失败/未启用 → 走现有截断路径）
  ├─ 2. 对每个勾选维度：
  │      ├─ 构造检索策略（查询词 + 章节定向 + top_k）
  │      ├─ RAG 多路检索（store.query + where 过滤，合并去重）
  │      ├─ 组装上下文（片段带 [n] 编号 + 章节 + 页码）
  │      └─ 现有维度 prompt + 上下文 → LLM 分析
  └─ 3. 落盘 .md/.json（维度列表变长，格式不变）
```

**核心改动点**：`analyzer.py` 中"构造 user_content"那一步，把 `pdf_text`（截断全文）替换为 `rag_context`（按维度检索片段）。新增 `rag/analysis.py` 负责检索与上下文组装，`ANALYSIS_TEMPLATES` 增加 `retrieval` 字段描述每维度的检索策略。

## 3. 维度设计

| 维度 id | 名称 | 分析内容 | RAG 检索策略（章节定向 + 查询词） | 默认勾选 |
|---|---|---|---|---|
| financial_summary | 财务摘要 | 营收/净利/ROE/毛利率等核心指标 | 财务报告 + 指标摘要；"营业收入 净利润 毛利率 ROE" | ✅ |
| risk_warning | 风险识别 | 业绩下滑/现金流/负债/营运风险 | 管理层讨论 + 财务报告；"风险 下降 负债 现金流 存货 应收" | ✅ |
| business_highlights | 经营亮点 | 增长点/战略/竞争力 | 管理层讨论 + 经营情况；"增长 亮点 战略 研发 分红" | ✅ |
| profit_quality | 盈利质量 | 利润含金量：现金流匹配、应收/存货、毛利率趋势 | 财务报告 + 附注；"应收账款 存货 毛利率 经营现金流" | ✅ |
| cashflow | 现金流分析 | 经营/投资/筹资现金流结构 | 现金流量表章节；"经营活动现金流量 投资活动 筹资活动" | ✅ |
| growth | 成长性 | 营收/利润增速、板块增长、新市场 | 管理层讨论 + 分行业数据；"同比增长 增速 新市场 新业务" | — |
| solvency | 偿债与资本结构 | 资产负债率、有息负债、流动性 | 财务报告（资产负债表）；"资产负债率 有息负债 流动比率" | — |
| operation | 营运能力 | 应收/存货/总资产周转率 | 财务报告 + 附注；"周转率 应收账款周转 存货周转" | — |
| governance | 公司治理 | 股权结构、董事会、高管、关联交易、内控 | 公司治理章节；"股权 董事会 高管 关联交易 内部控制" | — |
| shareholder_return | 股东回报 | 分红率、每股股利、回购 | 重要事项 + 财务报告；"分红 股利 回购" | — |
| rnd_innovation | 研发与创新 | 研发投入、资本化率、专利 | 管理层讨论研发部分；"研发投入 资本化 专利" | — |
| industry_competition | 行业与竞争 | 行业地位、市占率、竞争格局 | 管理层讨论行业部分；"行业 市场份额 竞争 地位" | — |
| strategy_outlook | 战略与展望 | 管理层未来判断、战略规划 | 管理层讨论展望部分；"发展战略 展望 计划 目标" | — |
| esg | ESG 与社会责任 | 环保、社会责任、员工 | 环境与社会责任章节；"环境保护 社会责任 员工" | — |

> 默认勾选 5 个（财务摘要/风险识别/经营亮点/盈利质量/现金流）保证核心质量与时间可控；其余按需勾选。全部维度可选，前端提供"全选"。

## 4. 检索策略（rag/analysis.py）

- 接口：`RagAnalysis.build_context(report_id, dimension, top_k=8) -> str`（返回组装好的上下文文本，带 `[n]` 编号与章节/页码）；或返回 `List[Dict]` 由 analyzer 组装。
- 每维度检索策略来自 `ANALYSIS_TEMPLATES[dim]["retrieval"]`：`{queries: [...], sections: [...], top_k: N}`。
  - `sections`：可选章节定向（按 metadata.section 模糊匹配或直接过滤）；缺省为整报告检索。
  - 多路检索：每个 query 检索一次（`where={"report_id": ...}` + 可选 section 过滤），结果合并去重（按 chunk id）。
- 指标摘要（section="指标摘要"）在财务类维度（financial_summary/profit_quality/cashflow）自动并入。
- 上下文不足（检索结果为空）时返回空，由 analyzer 回退截断全文。

## 5. 接口与配置

### 5.1 analyzer 改造（兼容现有）

- `ReportAnalyzer.analyze(...)` 新增可选参数 `rag_ctx: Optional[Callable[[str, str], Optional[str]]]` 或直接持有 `RagAnalysis` 实例；缺省 None 时维持现有行为（向后兼容，现有测试不动）。
- 组装逻辑：`rag_context = rag_analysis.build_context(report_id, dim_id)`；非空则用它替代 `pdf_text` 作为"财报内容"；为空回退 `pdf_text`。
- `DEFAULT_DIMENSIONS` 更新为 5 个默认维度（或从配置读取）。

### 5.2 配置（config.example.yaml）

```yaml
rag:
  enabled: true
  enhanced_analysis: true          # 分析时用 RAG 检索上下文（需 enabled: true）
  analysis_dimensions:             # 分析页默认勾选维度；空/缺省用内置默认 5 个
    - financial_summary
    - risk_warning
    - business_highlights
    - profit_quality
    - cashflow
```

### 5.3 server / CLI 接入

- `POST /api/reports/{code}/{period}/analyze`：任务开始时确保 ingest（`auto_ingest_report`）；`dimensions` 校验扩展到新维度 id（沿用 `ANALYSIS_TEMPLATES` 过滤）；缺省维度从配置读取。
- CLI `analyze` 同样接入（前置 ingest + 默认维度从配置）。

## 6. 前端

- 分析页维度勾选面板：从 `ANALYSIS_TEMPLATES` 生成全部维度复选框（可从前端维护清单或新增 `GET /api/analysis/dimensions` 端点返回维度元数据）；默认勾选配置的默认维度；增加「全选 / 清空」快捷按钮。
- 结果展示：沿用现有维度 Tab 机制（`bindDimTabs`），新增维度自动成为新 Tab。
- 分析中提示维度数量与预计耗时（每维度一次 LLM 调用）。

## 7. 兜底与错误处理

| 场景 | 处理 |
|---|---|
| RAG 未启用 / 未初始化 | 分析完全走现有截断路径 |
| 报告未索引 / 检索为空 | 该维度回退截断全文 |
| 单个维度检索异常 | 记录日志，回退截断全文，不影响其他维度 |
| 维度模板缺失 retrieval 配置 | 回退全文检索（where 仅 report_id） |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 检索片段拼接后上下文过长 | top_k 收敛（默认 8）、片段截断（300 字）、按维度控制总量 |
| 维度增多导致分析时间/成本上升 | 默认仅 5 维度；其余按需勾选；串行任务天然限流 |
| 检索策略不精准（命中无关片段） | 章节定向 + 查询词双重约束；上下文带编号，LLM 可忽略无关片段 |
| 新维度 prompt 质量参差 | 模板先覆盖高频维度；Prompt 结构复用现有风格 |
| 与现有分析结果格式兼容 | .md/.json 结构不变，仅维度数组变长；现有测试为回归基线 |
