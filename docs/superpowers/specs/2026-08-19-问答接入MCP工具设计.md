# 问答接入 MCP 工具 设计文档

> 日期：2026-08-19
> 状态：设计方案（未实施）
> 前置：`2026-08-18-RAG增强多维度分析设计.md`（已实现）的问答侧增量演进

## 1. 背景与目标

### 1.1 现状

- 智能问答（`/api/chat/stream`）只基于 RAG 知识库片段回答，答案局限于已索引的年报文本。
- 项目已具备 `StockMCPClient`（china-stock-mcp，30 个工具：三大报表、财务指标、资金流、
  股东/高管/分红、研报、估值、技术指标、宏观数据等），通过 `call_tool(name, arguments)`
  同步调用并返回文本；已有通用端点 `POST /api/stock/mcp/call` 与 CLI `mcp` 子命令。
- `AIClient.chat_stream` 目前只解析 `delta.content` / `delta.reasoning_content`，
  **不支持流式 tool_calls 累积**；`RagQA.answer_stream` 为单轮「检索 → 生成」。

### 1.2 目标

1. 问答流程中让模型可按需调用 MCP 工具获取**年报之外**的增量信息（实时行情、最新财务指标、
   资金流、股东变化、研报观点等），辅助回答问题并标注数据来源。
2. 保持现有流式体验：工具调用过程在前端可见（「正在调用 MCP 工具 xxx…」），答案仍流式返回，
   引用（RAG 片段）机制不变。
3. 向后兼容：MCP 不可用 / 未启用时，行为与现状完全一致（纯 RAG 问答）。

### 1.3 非目标

- 不引入独立 Agent 框架，仍在现有「每问一轮模型生成」的确定性管线内扩展工具调用。
- 不做多报告/多工具并行编排（工具串行执行即可）。
- 不把工具消息写入会话历史（历史仍只存 user/assistant 最终问答，避免多轮上下文结构膨胀）。

---

## 2. 总体流程

```text
用户问题
  → RAG 检索片段（现有）
  → 第一轮 LLM（messages + system[片段] + tools=工具定义）
      ├─ 无 tool_calls → 直接流式输出答案（现状路径）
      └─ 有 tool_calls → 逐条执行 MCP 工具（超时/截断/错误兜底）
           → 追加 assistant(tool_calls) + tool(结果) 消息
           → 第二轮 LLM（可再带 tools，最多 max_tool_rounds 轮）
           → 最终答案流式输出
  → done 事件（答案 + RAG citations + 用到的工具名列表）
```

**核心改动点**：
- `AIClient.chat_stream`：支持 `tools` 参数 + 流式 `delta.tool_calls` 分片累积；
- `RagQA.answer_stream`：工具调用编排（tool_executor 注入、多轮、事件透出）；
- `StockMCPClient.list_tools`：返回 MCP 原生 `inputSchema`，自动转 OpenAI function 格式；
- server `/api/chat/stream`：注入带股票代码解析的工具执行器，新增 `use_mcp` 开关；
- 前端：识别 `tool_call` / `tool_result` 事件更新「思考中」提示文案。

## 3. 工具定义（function calling 格式）

OpenAI 兼容 API 的 tools 定义：

```json
{
  "type": "function",
  "function": {
    "name": "get_financial_metrics",
    "description": "关键财务指标（营收/净利/毛利率/ROE等）",
    "parameters": {
      "type": "object",
      "properties": {
        "symbol": {"type": "string", "description": "6 位股票代码，如 600519"},
        "output_format": {"type": "string", "enum": ["json", "markdown"]}
      },
      "required": ["symbol"]
    }
  }
}
```

### 3.1 工具清单来源（推荐：自动 + 白名单兜底）

- **自动**：增强 `StockMCPClient.list_tools()`，把 MCP `Tool.inputSchema` 一并返回
  （新增 `input_schema` 字段，`name`/`description` 保持兼容），由转换函数生成 OpenAI 格式。
- **兜底**：MCP 启动失败/慢时，使用内置白名单（`_MCP_SYMBOL_TOOLS` 已有 9 个 + 常用
  行情/现金流/股东工具），parameters 用统一模板 `{symbol, output_format}`。
- 工具数量控制：默认注入 ≤ 12 个常用工具（避免请求体过大、模型选择困难），可配置。

### 3.2 常用工具建议（Phase 1 默认注入）

`get_stock_basic_info` / `get_realtime_quote` / `get_financial_metrics` /
`get_balance_sheet` / `get_income_statement` / `get_cash_flow` /
`get_fund_flow` / `get_shareholder_info` / `get_profit_forecast` /
`get_news_data` / `get_stock_indicator`（估值） / `get_industry_chain`（行业，可选）

> 工具名与描述以 `list_tools()` 实际返回为准；此处为占位清单。

## 4. AIClient：流式 tool_calls 支持

### 4.1 `chat_stream` 新增参数

```python
def chat_stream(self, messages, *, model=None, system=None, temperature=0.3,
                max_tokens=4096, response_format=None, tools=None) -> Generator
```

- `tools`：OpenAI function 定义列表；非 None 时写入 `request_body["tools"]`，同时
  `request_body["tool_choice"] = "auto"`。

### 4.2 流式 tool_calls 累积

SSE 的 `delta.tool_calls` 是分片：

```json
{"choices":[{"delta":{"tool_calls":[{"index":0,"id":"call_1","function":{"name":"get_financial_metrics","arguments":"{\"symbol\":"}}]}}]}
{"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"\"600519\"}"}}]}}]}
```

解析规则：
- 按 `index` 分组累积 `id` / `function.name` / `function.arguments`（字符串分片拼接）；
- 流结束（`[DONE]` 或完成帧）时若存在 tool_calls，产出完整事件：
  `{"type": "tool_calls", "tool_calls": [{"id", "name", "arguments"(json字符串)}]}`；
- 同时存在 content 与 tool_calls 时：content 照常 `delta` 产出，tool_calls 在结束帧
  `tool_calls` 事件产出；
- 不传 `tools` 时行为与现状完全一致（回归基线）。

### 4.3 事件清单（chat_stream 级）

| type | 说明 |
|---|---|
| `delta` | 内容/推理增量 `{text, reasoning}` |
| `tool_calls` | 完整工具调用列表（流结束时） |
| `done` | 最终答案（无 tool_calls 场景，与现状一致） |
| `error` | 请求/解析失败 |

## 5. RagQA：工具调用编排

### 5.1 构造与接口

```python
class RagQA:
    def __init__(self, store, ai_client, top_k=8,
                 tool_executor: Optional[Callable[[str, Dict[str, Any]], str]] = None,
                 max_tool_rounds: int = 3,
                 tool_result_max_chars: int = 2000)
```

- `tool_executor`：`(name, arguments) -> str`；默认 `None` 表示不启用工具（现状）。
  生产由 server 注入（带代码解析 + `stock_mcp.call_tool`），测试注入 fake。

### 5.2 `answer_stream` 流程（新增 tools 支持）

```python
def answer_stream(self, question, history=None, filters=None, tools=None):
    hits = store.query(...)          # 现有检索
    if not hits: yield {"type": "empty"}; return
    system = SYSTEM_PROMPT_TEMPLATE.format(context=...)
    messages = history + [user]

    round = 0
    while True:
        round += 1
        for evt in ai_client.chat_stream(messages, system=system, tools=tools if round == 1 else None):
            if evt["type"] == "delta": yield evt
            elif evt["type"] == "error": yield evt; return
            elif evt["type"] == "tool_calls":
                calls = evt["tool_calls"]
                for c in calls:
                    yield {"type": "tool_call", "name": c["name"],
                           "arguments": c.get("arguments", "{}")}
                # 组装 assistant tool_calls 消息
                messages.append({"role": "assistant",
                                 "content": None,
                                 "tool_calls": [{"id": c["id"], "type": "function",
                                                 "function": {"name": c["name"],
                                                              "arguments": c["arguments"]}}
                                                for c in calls]})
                for c in calls:
                    result = _safe_execute(c)          # 超时/异常 → 错误文本
                    yield {"type": "tool_result", "name": c["name"],
                           "summary": result[:200]}
                    messages.append({"role": "tool", "tool_call_id": c["id"],
                                     "content": result[:tool_result_max_chars]})
            elif evt["type"] == "done":
                # 无 tool_calls 的第一轮直接结束（现状）；有工具时本轮不 yield done
                ...
        if no tool_calls in this round:
            break
        if round >= max_tool_rounds: break
    # 最终 done：答案 + citations + tools_used
```

- **多轮**：`max_tool_rounds`（默认 3）限制循环；tools 只在第一轮注入（后续轮不重复给，
  避免模型反复调用）——或每轮都注入但依赖 `tool_choice: auto`，设计采用「首轮注入」。
- **引用**：citations 仍由最终答案文本中的 `[n]` 校验生成（RAG 片段编号不变）。
- **事件**：新增 `tool_call` / `tool_result`（前端展示用）；`done` 增加 `tools_used` 列表。

### 5.3 工具执行兜底

| 场景 | 处理 |
|---|---|
| MCP 未启用/未注入 executor | 不传 tools，纯 RAG 路径（现状） |
| 工具执行异常 | 错误文本作为 tool 消息回传，模型可说明「该数据暂不可得」 |
| 工具返回超长 | 截断 `tool_result_max_chars`（默认 2000） |
| 无法解析股票代码 | executor 返回提示文本，模型改用 6 位代码重试 |
| 超过 max_tool_rounds | 停止工具循环，用已有上下文生成最终答案 |

## 6. server 接入

### 6.1 工具执行器（注入 RagQA）

```python
def _build_mcp_tool_executor(cfg) -> Optional[Callable]:
    if not cfg.enabled or not cfg.mcp_tools:
        return None
    def executor(name, arguments):
        args = dict(arguments or {})
        symbol = args.get("symbol")
        if symbol and not re.fullmatch(r"\d{6}", str(symbol)):
            resolved = stock_index.resolve_code(symbol)   # 名称→6位代码（复用自动补全）
            if resolved:
                args["symbol"] = resolved
            else:
                return f"无法解析股票「{symbol}」，请使用 6 位股票代码"
        args.setdefault("output_format", "json")
        return stock_mcp.call_tool(name, args, timeout=cfg.mcp_tool_timeout)
    return executor
```

- `_init_rag()` 构造 `RagQA` 时注入 executor（RAG 启用且 `rag.mcp_tools: true` 时）。
- **线程安全**：`StockMCPClient` 内部已实现锁 + 长会话复用，多个问答流并发调用安全。

### 6.2 流式端点

- `/api/chat/stream` 请求体新增可选 `use_mcp: bool = True`（前端可关）；
- gen 循环中新增事件分支：`tool_call` / `tool_result` 透传 SSE；
- `done` 事件增加 `tools_used`（前端展示「参考了 MCP 工具数据」）；
- 会话历史保存逻辑不变（只存最终 user/assistant）。

### 6.3 工具定义获取（端点内缓存）

- 首次需要时 `list_tools()` → 过滤常用 12 个 → 转 OpenAI 格式，模块级缓存（LRU/固定）；
- `list_tools` 失败 → 使用内置白名单兜底；两者都失败 → 不注入 tools（纯 RAG）。

## 7. 前端

- 流事件新增处理：`tool_call` → 思考气泡文案更新为
  「正在调用 MCP 工具「{name}」…」；`tool_result` → 追加「已获取 {name} 结果」；

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| MCP 启动慢/不可用拖慢问答 | 工具定义缓存 + 启动失败回退纯 RAG；工具调用独立超时 |
| 模型乱调工具 / 无限循环 | 白名单限定工具；max_tool_rounds=3；tool_choice=auto |
| 工具结果超长刷爆上下文 | 截断 2000 字符；每轮限制工具数 |
| 股票名称无法解析为代码 | executor 返回提示文本，模型改用 6 位代码重试 |
| 工具返回错误数据误导回答 | system prompt 要求标注「来自 MCP 实时数据，以交易所/公司公告为准」 |
| 与现有 RAG 引用冲突 | citations 仅针对 RAG 片段；工具数据以 tools_used 徽章区分，不进入引用编号 |
