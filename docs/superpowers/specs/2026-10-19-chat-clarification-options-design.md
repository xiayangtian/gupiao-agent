# 智能问答澄清选项交互设计

## 目标
当聊天澄清确实提供了多个明确答案方向时，以可点击选项替代用户手动输入；没有可靠候选项时，继续使用自由输入，避免模型或界面猜测选项。

## 方案
- 在请求解析层为可枚举的澄清场景提供结构化 `options`，当前覆盖意图不明确时的“财报经营指标 / 证券价格走势”、以及行情/财报范围冲突等明确二选一场景。一般缺少公司、时间等信息的澄清不展示按钮。
- SSE `clarification` 与终态 `done` 携带相同的受控选项数据；现有纯文本 `message` 及历史持久化保持兼容。
- 前端在澄清答复下方显示语义化、键盘可操作按钮。点击后禁用本组选项并将选项文字作为下一条聊天消息提交，仍由现有请求解析和授权边界决定后续行为。
- 选项数量限制为 2–5，文本使用 `textContent`，不得把选项作为 HTML 注入。

## 验收
- 澄清 API 为有明确选择的场景返回结构化选项，非选择澄清保持空选项并兼容现有 SSE 客户端。
- 客户端只渲染有效选项；按钮选择提交对应文字，普通澄清自由输入不变。
- 聚焦验证澄清解析、SSE API、聊天渲染相关单测及 JavaScript/Python 语法检查。
