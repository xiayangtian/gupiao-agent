# 上下文追问与 WebSearch 查询词溯源设计

## 目标

让针对上一轮回答或展示结果的追问先利用该轮上下文；只在确实需要外部资料时才搜索，并使每次实际发送给 WebSearch 的查询词可追溯。

## 当前行为与问题

- `/api/chat/stream` 保存的 assistant 消息包含结构化 `AnswerRun`，但请求规划器目前只接收本轮问题；Answer 模型虽可接收近期文本对话，历史投影会移除结构化 run 元数据。
- 规划执行的 WebSearch handler 将当前问题原文作为 query，不能解析“这个为什么没画图”等指代上一轮的追问。
- 此类追问可能被规划为 `general_web`；即便其答案已可由上一轮运行结果解释，也会调用 WebSearch。
- 计划执行结果投影为 `ToolArtifact` 时未保存 `SourceCall.arguments`，因此该路径的 query 丢失。RAG 工具事件路径已有参数白名单/脱敏摘要能力。

## 已确认决策

- 构造严格有界的上一轮上下文：最近一条完整 user/assistant turn、可验证 `AnswerRun` 的安全展示字段、公司范围、执行来源/步骤、事实和工具摘要；不带模型推理、prompt、原始工具返回体或整段旧会话。
- 上下文始终标注为历史数据，只用于解析指代与解释上一轮结果，不得当成指令或可复用的当前市场事实。当前问题仍是本轮意图的权威输入。
- 对明确询问上一轮呈现/来源状态的追问（例如“这个为什么没画图”），在调用计划模型或任何外部来源之前做受限识别；建立 `conversation_context` answer-only 计划，关闭工具和检索，将安全上下文提供给回答模型。
- 不把一般的“为什么”都视为上下文解释。诸如“股价为什么涨/跌”“上涨原因是什么”的市场归因仍走相应外部信息路径；无法识别上一轮或缺少完整上一轮运行时，不采用 context-only 快捷路径。
- 普通上下文追问的执行计划模型只接收上一轮有界上下文。若计划允许 WebSearch，模型同时生成短查询词；外部调用实际使用该 query，而不是直接使用当前追问原句。无上下文时可用当前问题；模型未给有效 query 时以当前问题加最小的上一轮主体引用作有界回退，不把整段历史拼进 query。
- 每个实际 WebSearch 调用在独立工具来源记录中保存其实际 query；复用现有白名单和脱敏，query 上限调整为最多 300 个字符。来源面板展开后可查看“搜索词”。不同 query 不合并成一个来源组；既有来源、Facts 和来源状态仍保留。

## 安全与边界

- 只有当前会话中最近的已完成 assistant run 与紧邻用户问题可作为上一轮上下文；不得跨会话、跨用户或从用户控制字段恢复历史上下文。
- 保持服务端既有来源授权、调用预算、计划校验和 Fact 校验；模型生成的 query 不获得工具权限。
- Search query 做边界长度、空值和敏感值处理；持久化内容不能含密钥或访问令牌。界面按纯文本 escape，不解释为 HTML。
- Context-only 路由不触发执行规划器、RAG 检索、MCP、腾讯行情或 WebSearch；只以当前 run 的安全摘要和对话文本回答。

## 不在范围内

- 全会话长期记忆、自动改写/复用更早 turns、跨会话搜索、对市场因果问题强制禁用搜索。
- 记录完整 WebSearch 请求/响应正文、访问凭证、模型思维过程或超长转录。
- 将旧的 Facts 当作本轮新取行情或作为新的数值核验依据。

## 验收

1. “这个为什么没画图”在存在上一轮 run 时采用 `conversation_context` answer-only 计划；计划器与外部来源 mock 均未调用，回答上下文含上一轮 subject/facts/source metadata。
2. “这只股票为什么涨了”不会命中 context-only；正常规划和获准来源链保持可用。
3. 需要外部搜索的代词追问能将上一轮主体和当前目标解析为搜索 query；查询模型缺省/输出无效时使用有界回退。
4. ExecutionPlanner 路径和 RAG 工具调用路径的每次真实 WebSearch 均保存实际 query（有界、脱敏），并在展开来源面板显示；不同查询词保留独立来源组，UI 对恶意 HTML 字符安全转义。
5. 最近 turn 以外的记录不影响上下文；缺失/损坏 run、无上一轮或跨会话场景安全退回普通路由。
