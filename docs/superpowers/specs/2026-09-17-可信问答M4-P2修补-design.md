# 可信问答 M4 P2：工作台体验与质量运营修补设计

**日期：** 2026-09-17  
**状态：** 已确认设计，待实施计划  
**范围：** 修补 M4 已合入后的五项 P2：工作台决策文案即时一致性、离线质量摘要观测、健康/负向评测分离、稳定 Fact ID、后端证据身份规则收敛。  
**不包含：** 自动交易、主动监控/推送、真实 AI/MCP/网页评测调用、服务启动时自动评测、修改既有不可变 AnswerRun/ResearchRun 证据内容。

## 1. 目标与非目标

### 目标

1. 保存或撤销研究决策后，已打开的工作台立即反映该决策；
2. 提供显式本地命令生成质量摘要，Web 工作台只显示最近摘要，不执行评测；
3. 分离健康评测和负向探针，避免故意泄漏样本使健康状态恒为失败；质量状态仅作观测指标，不阻断发布；
4. 让新 Fact 拥有稳定 ID，允许同一 PDF 页上的多个已验证 Fact 被精确保存；
5. 将 PDF/网页证据身份与可用性判断收敛为后端单一规则，避免记忆、导出、评测的规则漂移。

### 非目标

- 不迁移或伪造历史 AnswerRun 中缺失的 Fact ID；
- 不在浏览器、服务启动或用户 API 请求中运行评测；
- 不把质量摘要、提示词、完整外部正文、模型推理链写入 API 响应；
- 不改变 Scope、ToolPolicy、所有权检查、事实核验或 M1–M3 的持久化真相。

## 2. 设计决策

| 主题 | 决策 | 原因 |
| --- | --- | --- |
| 质量状态 | 仅观测，不阻断发布 | 用户选择；保留质量可见性但避免把本地摘要变成部署依赖。 |
| 摘要生成 | 显式本地命令 | 避免用户请求和服务启动产生长任务、网络或模型副作用。 |
| 评测分组 | 健康集与负向探针独立聚合 | 负向样本用于证明门槛会捕获错误，不应使健康结果恒红。 |
| Fact 保存身份 | 稳定 `Fact.id` | 页码证据可由多个事实共享；复合字段容易漂移。 |
| 旧数据 | 缺 Fact ID 时 fail-closed | 不猜测事实身份或修改历史不可变运行。 |
| 证据规则 | 后端单点模块 | 前端消费可保存状态/ID，导出/评测/记忆共享同一身份与页码校验。 |

## 3. 架构与数据流

### 3.1 工作台即时刷新

现有保存决策与撤销记忆操作成功后，前端若工作台区域已展开，则调用既有 `loadResearchWorkspace(researchWorkspaceFilters())`。该刷新使用 M4 已有 request generation 保护，旧响应不能覆盖新筛选结果。后端查询、记忆 sidecar 和所有权语义不变。

### 3.2 离线质量观测

新增本地 CLI/模块入口：读取版本化 fixture、通过固定 fixture-backed fake 运行健康集与负向探针、分别传入 `QualityGate`，写入原子 JSON 摘要 `data/research_quality_summary.json`。

摘要仅含：schema version、生成时间、健康汇总、探针汇总和枚举化 failure code 计数；不含 question、prompt、完整原文或单用例结果。写入失败不覆盖已有有效摘要。`GET /api/research/quality` 扩展为读取并返回这两个聚合字段；工作台显示最近生成时间、健康状态、探针覆盖状态和“本地命令刷新”说明。

### 3.3 评测语料分组

fixture 保持版本化，新增明确字段 `suite: "health" | "probe"`：

- `health` 用例输出应满足范围、引用、时间、状态和工具策略；其汇总是工作台展示的主要状态；
- `probe` 用例故意包含 Scope 泄漏、无页码、外部无时间、停止伪完成等错误，其“预期检测到失败”才算 probe 通过；不计入 health 汇总。

所有评测仍只重放固定 AnswerRun/ResearchRun，不调用真实 AI、MCP、网页或生产数据。

### 3.4 Fact ID 与证据身份

`Fact` 增加非空稳定 `id`，由创建/归一化新事实的单一工厂确定性生成；ID 基于规范化的 metric、公司、期间、期间类型、主体口径、数值、单位与证据 ID 序列计算，使用不可逆短哈希前缀并加 `fact_` 前缀。相同事实在同一契约版本下获得相同 ID；不同事实即使共用同页证据也拥有不同 ID。

`AnswerRun.from_dict` 兼容旧 Fact：旧数据可读取，`id` 为空表示不可保存。记忆保存 API 请求改为 `fact_id`（稳定 Fact ID），不再用 evidence ID 反向查找事实；前端只在 `fact.id` 非空且既有 eligibility 检查通过时渲染保存动作。

新增 `webapp/evidence_identity.py`：提供 `artifact_evidence_ids()`、正页码 PDF identity/index、网页 identity、受信 PDF URL 校验和 `fact_is_backed_by_pdf()`。记忆、导出和评测改用该模块；前端不再自行推导 `report_id#p{page}`，只使用 API/渲染数据给出的 ID 与可保存标志。

## 4. 错误与兼容性

| 场景 | 行为 |
| --- | --- |
| 质量命令加载 fixture/摘要失败 | 非零退出，保留原有摘要文件；Web 继续显示最后有效摘要或 `available:false`。 |
| 摘要 schema/failure code 非法 | API fail-closed 返回 `available:false`，不泄露原始内容。 |
| Probe 未检测到预期失败 | probe 汇总为失败，健康汇总不受污染；命令明确输出诊断 code。 |
| 旧 Fact 无 ID | 可以展示/导出，不能保存至研究记忆；UI 不渲染保存操作。 |
| 新 Fact ID 碰撞或异常 | 工厂拒绝创建或序列化，不能落盘为可保存事实。 |
| 证据无法形成受信身份 | 导出保留不可用状态；记忆/评测 fail-closed。 |
| 工作台刷新失败 | 保留现有卡片并显示已有业务化失败提示，不清空用户当前筛选。 |

## 5. 测试与验收

- 单元：保存/撤销决策触发工作台刷新；健康/探针语料 schema 与独立聚合；质量命令原子写入和失败不覆盖；Fact ID 稳定性、同页多 Fact、旧 Fact fail-closed；后端证据身份规则供三处消费者一致使用；
- API：质量摘要仅返回安全聚合；新 Fact ID 保存成功；旧 Fact/未知 ID 422；
- 浏览器：工作台打开时保存/撤销决策即时更新行文案；质量状态展示与无摘要降级；390px 无横向溢出；
- 回归：M1–M4 相关单测、全量 pytest、CSS 检查、`git diff --check`；
- 发布验收：质量命令不使用真实网络/模型，摘要 sidecar 仍被 `.gitignore` 忽略。

## 6. 风险与后续

- 稳定 Fact ID 可能需要调整旧测试 fixture 的构造方式；只允许兼容读取，不允许批量改写历史运行；
- 新证据身份模块必须通过回归验证覆盖全部既有 PDF/网页来源类型；
- 质量状态为观测而非发布门槛，团队仍应在需要时手动运行命令并审阅健康与 probe 两部分结果。
