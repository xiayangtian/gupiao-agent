## 1. 目标与阶段边界

P2 依赖 P1 的运行级来源授权、预算、来源结果与事实持久化契约。本阶段让公司身份、报告可用性、用户所指时间、实际来源覆盖范围和回答中的数字保持一致。

本阶段目标：

1. 公司身份不再要求必须已有本地报告；未知公司/时间需澄清，不静默扩大 Scope。
2. 区分财报经营趋势与证券价格走势，并把自然语言时间转换为服务端可复核的明确窗口。
3. 复盘回答准确描述四大指数、涨跌停池及行业资金流的实际覆盖范围和缺失项。
4. 让数值论断按公司、指标、期间/窗口、口径和单位匹配来源事实；支持有证据链的确定性派生值。
5. 普通常识不因财报库没有命中而被拒答，同时明确模型常识不是来源核验。

### 非目标

- 不实施 P3 的异步规划、取消、进度或研究路由；不实施 P4 的真实链路评测、检索质量优化或上下文压缩。
- 不新增第三方行情提供方，也不将现有来源不具备的全市场广度、总量或完整资金口径推断出来。
- 不改变 P1 的来源权限/预算/持久化安全边界；不将普通常识通道用于绕过公司财报或行情数字核验。
- 不自动补报或扩大财报下载授权；报告缺失不能通过全库检索或无关报告替代。
- 不把来源获取时间当作行情数据截至时间；不以模型生成内容补齐缺失行情。

## 3. 运行时行为契约

### 3.1 公司身份与报告范围

将“已识别的公司”和“可检索报告 ID”作为两个不同事实表达。实施可在 `Scope` 中允许 `company_only` 保留单个 `CompanyRef` 而 `report_ids` 为空，或采用等价的显式报告可用性状态；不得以伪造 report ID 表示缺失。

- 公司代码/名称只由服务端报告索引或既有 `_resolve_symbol_code`/`stock_index` 身份解析结果建立；使用现有 MCP 名称词典回退时仍须得到唯一映射，不新增身份/行情提供方。解析不可用或有歧义时先澄清；模型输出不能创建或更换股票代码。
- 目标公司明确但报告列表为空：报告检索对该公司是空命中；行情请求仍须分别经过既有行情授权、预算及运行级来源服务。
- 用户要求财报指标而无匹配本地报告：返回缺少对应公司/期间证据的限制或澄清，不用其他公司的报告、不扩大到全库，也不把行情工具结果当财报事实。
- 多个公司候选或无法安全映射代码时，先澄清；不得通过模糊匹配任选一个实体。
- 显式报告 ID 仍将公司身份和报告期间绑定；行业/全库 Scope 现有隔离约束保持不变。

### 3.2 意图及时间窗口

使用服务端意图/时间解析结果作为规划硬约束，模型规划器不能覆盖它。优先级由专用复盘意图、明确市场价格意图、明确财报指标意图、其他/歧义组成。示例：

- “营收/净利润趋势、同比、环比、历年业绩” → 财报事实路径；必须先确定公司及需要的报告期。
- “股价、K 线、涨跌、走势” → 行情路径；必须有明确公司或市场对象。
- “分析趋势”而未说明财务指标或价格对象 → 发出澄清，不允许规划器擅自改成个股行情。
- “A 股复盘” → 市场复盘路径，不能因聊天中存在公司 Scope 而改成个股财报分析。

时间窗口由服务端解析成不可变、可审计结构，至少含用户原始表达、窗口类型、时区、起止日期（含边界约定）、解析依据和实际数据 `as_of`。日期以 `Asia/Shanghai` 解释。

| 表达 | 解析语义 | 数据要求 |
| --- | --- | --- |
| `上周` | 前一自然周周一至周日 | 从来源返回的日线按实际日期过滤；不等同于最近五个交易日。 |
| `本周` | 本自然周周一至请求时点/来源截至日期 | 只报告实际返回的交易日；未来日期不补齐。 |
| `近五交易日` | 截至当前有效来源数据的最近五个交易日 | 取五个带日期的实际日线；不足五根标部分覆盖，不向更早期间静默补足。 |
| 明确日期/报告期 | 用户所指日期或财报周期 | 与实际报告索引/行情数据相交；无匹配时澄清或报告不可用。 |

行情由已接入的日线来源返回日期作为交易日事实，不另行推算节假日。查询应取得足以覆盖目标自然周的有界历史日线，再由服务端按日期过滤；若 provider 回传不足、日期无法解析或四大指数区间不一致，返回部分状态并披露。`as_of` 使用实际行情日期/时间；未知则留空，绝不使用 `fetched_at` 代替。

### 3.3 复盘覆盖与资金口径

复盘只使用当前已经授权和配置的腾讯行情、stock-data MCP 等来源。模型不能提交工具名、股票代码、日期或池参数。

- 四大指数按实际成功取得的指数逐一报告；不把缺失指数视为持平。比较时使用同一解析窗口和可比数据日期。
- 涨停/跌停池请求上限为 50 条。除非响应提供可信总数并能证明覆盖完整，否则将结果标记为“最多返回 50 条/总量未知”；返回恰好 50 条也不能推断完整或必然已截断。
- 当前行业资金流工具的 `今日`/`5日` 行业排名仅代表其响应声明的范围；不得表述成全市场主力净流入、北向流入或完整股票资金流。若请求自然周而工具只返回最近 5 日，不能将其当作该自然周累计。
- `stock_zt_pool` 若只返回当前池/单日截面，不得用于声称历史整周涨跌停数量；只可作为明确注明 `as_of` 的单日补充，否则对请求窗口标记不可用。
- 当前来源没有完整上涨/下跌家数接口时，市场广度只能标“未取得/不可用”；不能由涨跌停池数量估算全市场广度。
- 每个来源产物单独保留 P1 状态、`as_of`、窗口、返回数量/上限和安全错误码。部分调用失败不清除成功项；最终回答明确列出缺项，不把部分成功显示成全量成功。

#### 调用预算一致性（已获用户确认）

P1 的 `build_source_runtime` 原将复盘总调用上限约束为 6，市场调用上限为 4、网页最多 2。用户已授权 P2 将复盘硬上限调整为总调用最多 9、市场最多 7、网页最多 2；实际值仍受更低的用户配置及 SourceAccess 授权约束。ToolPolicy 仍控制其对应的模型工具循环，不因复盘预算提升而新增工具权限。最多 7 次市场调用由四次 Tencent 指数日线、两个涨跌停池 MCP 调用和一次行业资金流 MCP 调用构成；不再重复调用单指数 MCP `index_prices`。普通问答预算不变。若来源无法按请求自然周提供资金流，必须标出查询期不匹配且不能将其用于上周结论。

### 3.4 数值事实与论断核验

在既有 `Fact`/证据契约上补齐数值语义；确切字段/模块拆分由实施计划确定。事实至少保留指标、公司/实体、期间或行情窗口、期间类型、单位、来源证据 ID、`as_of`、来源类别（`local_pdf`/`market`/`mcp`/`web`/`unknown`）和直接/派生来源关系。历史 Fact 缺少来源类别时保留读取兼容，但不得仅凭 company code/数字为新问答提供来源类型支持。实际选入窗口的 Tencent Kline bar 可归一为逐日行情 reference fact；自由文本/不识别结构的 MCP 输出不能成为数字事实。历史财报指标只能由匹配期 PDF facts 支持；行情事实只支持相同证券、市场窗口及指标的行情论断，MCP financial reference 不能替代缺失的本地报告。旧 Fact/AnswerRun 仍可读取；不得伪造历史记录的证据或核验状态。

#### 单位和匹配

- 识别阿拉伯数字及常见格式化数字；覆盖 `%`、`％`、`百分比`、`个百分点`、`点`/指数点、`家`及现有金额/股数/倍数单位。
- 规范化时严格区分百分比（例如比率值 5.2%）、百分点（例如两个比率的差值 1.2 个百分点）、指数点（指数数值差）和数量（家）。任何单位转换须有明确规则，不把百分点当百分比，也不把“50 家”当全市场总数。
- 每个数值论断只在自身句子/子句与对应事实匹配；同一回答另一处提到的指标、数字或期间不能代为支持。
- 事实支持须匹配公司、指标、单位、实体口径、用户请求的期间/窗口及可比数据时间。缺少可确定期间时不能仅凭公司和数值相同通过。
- 若事实/来源不足、口径冲突或数据窗口不完整，使用现有 `partial`/`blocked` 机制和精确问题代码；不能将“有来源引用”直接视为数字已核实。

#### 派生数字

派生数值由服务端确定性逻辑计算，不交由模型自行计算后仅靠文本核对。计算产物携带公式、参数事实 ID、单位及期间映射，并可被展示层/验证器追溯。

- 同比/环比增长率：`(当前值 - 基期值) / abs(基期值) × 100%`。只允许同一公司、同一指标/单位/实体口径且期间类型可比的两个事实；基期为零、期间映射不明确或口径不同则拒绝派生。
- 百分点变化：两个可比比例值的差，单位为百分点；不使用增长率公式替代。
- 指数点变化：窗口内可比收盘值之差；涨跌百分比可由同一指数的可比收盘值按上述比率公式推导，或者使用来源直接提供且带窗口的涨跌事实。
- 派生 Fact 必须引用全部输入事实证据；任一底层事实越界、不可比或不可信时，派生结果不能进入支持集合。

未支持的数字论断不能因扩展了正则匹配而被误判通过；降级只影响不受支持的论断，保留已支持文本并指出限制。对于时效数据和公司财务数据，坚持来源闭环。

### 3.5 普通知识路径

增加显式 `general_knowledge` 意图/来源模式，与现有 `general_web` 区分。该模式由服务端意图约束，不由模型计划器自我声明即可获得。

- 稳定、非公司特定、非时效问题可采用 answer-only 路径，不调用财报检索或无关行情工具；回答/来源摘要明确标记“依据模型常识，未检索外部来源”。
- 行业/金融概念解释可以属于普通知识；涉及某公司的披露、现值、股价、当前排名等具体事实则不能归入此通道规避证据要求。
- 明确时效问题只在网页来源已配置、已授权且调用成功时作当前事实陈述；否则明确无法核实当前状态，不用模型记忆冒充最新数据。
- 通用知识路径允许一般百科数字不经过财务/行情 Fact 核验，但状态必须显示未检索/未核验；公司财务与行情数字始终执行对应 Fact 核验。
- 不因没有本地财报命中而发出“知识库为空”的失败；模型生成失败仍按真实失败状态处理。

## 4. 备选方案及取舍

1. **选定：服务端确定性范围/时间/数字契约，模型只在约束内规划和组织答案。** 可靠处理歧义、日期边界、口径和派生计算，缺数据时可明确拒绝；实现面较大但与 P1 的 fail-closed 合约一致。
2. 继续让模型主导路由、日期与数字解释，仅在生成后增加提示词或文本正则。改动较少，但无法保证“营收趋势”不误走行情、节假日不混窗口，或错期间事实不背书；不采用。
3. 接入新行情服务获得完整广度。可增加数据覆盖，但用户确认本阶段不新增行情提供方；不采用。缺失的全市场指标必须诚实标记不可用。

## 6. 验收场景

1. 已识别公司但无本地报告：财报请求不扩大范围；行情请求只使用该公司受控市场来源。
2. 公司名称有多个候选/无法安全识别：产生澄清，不执行行情或财报取数。
3. “营收趋势”必须走报告检索；“股价走势”走行情；单独“趋势”要求澄清；A 股复盘不因公司 Scope 被改道。
4. 财报事实缺少请求期间：不能用另一期间支持；明确期间而本地无对应报告时清楚说明限制。
5. 以固定日期/跨周末和节假日的日线验证“上周”“本周”“近五交易日”窗口、边界及不足数据，不依赖当前系统时间。
6. 四大指数部分成功、50 条池边界、池总量未知、行业资金流口径及来源失败均显示真实范围；不得声称完整广度/全市场资金流。
7. 测试无证据百分比/百分点/指数点/涨跌家数被拦截；格式化数字和同句指标匹配正常；跨公司/期间/口径的同值事实不支持该论断。
8. 同比/百分点/指数点派生公式用可比事实验证；零基期、缺失期、不同合并口径、单位不一致均拒绝计算并保留失败理由。
9. 静态常识在无 PDF 命中时仍可回答且标记未检索；当前事实无可用网页时不伪装最新；公司财务/行情数不能通过常识模式绕过核验。
10. 旧 AnswerRun、Fact、SSE 与聊天历史兼容；来源运行级预算、权限、部分失败语义及 P1 测试无回归。

## 7. 验证与停止条件

- 用户已确认详细实施计划；按 TDD 对本设计每条核心契约先编写失败测试，再实现；验证范围限于本阶段及直接受影响面。
- 使用固定日期、时区显式设置、真实日期字段的 fixture 和可控 provider 替身；不在常规测试中隐式联网、调用真实模型或修改生产数据。
- 适用单元/集成测试、最小真实 ASGI/SSE 流程及与状态/证据显示相关的本地浏览器测试必须通过；浏览器验证依项目规范检查 console、page errors、失败请求及移动端横向溢出。
