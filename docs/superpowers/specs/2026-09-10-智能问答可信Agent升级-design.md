# 智能问答可信 Agent 升级 — 设计方案

**Date:** 2026-09-10  
**Status:** scoped  
**Scope:** 将当前“RAG + MCP/网页工具调用”的智能问答升级为范围可控、证据可追溯、状态可恢复的研究 Agent；先交付可信回答底座，再逐步升级受控工具、研究计划、工作台与评测体系。**不包含**自动交易、下单、未经用户设定的持续推送、自由协作多 Agent，或把模型推断自动写入长期记忆。
**Prototype:** 无；本轮以文本方案确认信息架构与领域契约。

---

## 1. 现有业务模型

### 已存在的概念与状态

| 概念 | 当前事实 | 终态 / 义务 |
|---|---|---|
| 财报 | 以公司、报告期、报告类型标识；PDF 与分析产物可保存在本地 | PDF 是财务数字、会计口径与管理层披露的第一证据 |
| RAG 片段 | 带 `report_id`、章节、页码、文本的本地检索单元 | 命中片段可为回答提供 PDF/分析来源引用 |
| 工具调用 | MCP 市场数据和网页搜索可由模型调用；已有次数上限、去重与 MCP 熔断 | 成功、失败、熔断均应被用户理解，不能伪装成已获取数据 |
| 会话 | `id/title/messages/created_at/updated_at` 持久化；模型只接收最近 4 轮 | 当前仅保存角色和文本，重新打开后无法复核来源或完成状态 |
| 流式回答 | 可 SSE 流式输出；用户停止后会保存已生成文本 | 已停止的部分文本必须与完整研究结果区分 |
| 聚焦报告 | 当前通过 `priority_report_id` 提升目标报告召回权重 | 不是硬边界，其他报告仍可能混入结果 |

### 当前业务没有建模的概念

以下缺失不是视觉问题，而是本次升级需要补齐的领域能力：

- **回答范围合同（Scope）**：系统没有“仅本公司 / 本公司+行业 / 全库”的不可变范围对象。
- **研究运行（Research Run）**：系统没有一条回答对应的计划、步骤、工具轨迹、证据包、状态与结果。
- **结构化事实（Fact）**：数字、单位、期间、合并口径、来源与可信状态未作为独立对象存在。
- **可审计证据包（Evidence Artifact）**：网页、工具、PDF 证据不会随回答持久化。
- **可恢复研究任务**：停止、失败、部分完成不能定位到步骤或从失败处重试。
- **用户确认的研究记忆**：系统没有区分可保存事实与模型推断。

## 2. 用户视图模型

### 用户任务

用户进入“智能问答”通常不是为了泛聊，而是完成以下任务之一：

1. 查证某公司某期财报中的数字、变化和披露；
2. 比较同公司多期表现；
3. 在明确行业范围内进行同业比较；
4. 查询近期行情、新闻或异动原因；
5. 形成包含结论、事实、证据、风险和下一步的研究记录。

### 用户首先需要确认的四个问题

回答的首屏必须在不点击时回答：

1. 这次回答覆盖哪个公司、哪些报告期，是否扩展到行业；
2. 结论主要依据本地 PDF、实时数据还是网页；
3. 外部数据截至何时；
4. 此回答是完整、部分完成、已停止还是失败。

### 附着在回答上的证明

| 结论类型 | 必要证明 |
|---|---|
| 财报数字、会计口径、管理层披露 | 对应报告、页码、片段 |
| 实时价格、成交、估值 | 工具提供方、数据截至时间、参数摘要 |
| 新闻、公告、事件 | URL、标题、发布日期或抓取时间 |
| 行业比较 | 行业分类来源、参与比较公司、各公司的原始证据 |
| 模型判断 | 与原始事实分离，标明为分析或推断 |

### 用户已确认的产品决策

- 聚焦单一公司时，默认范围为**本公司**；
- 仅当问题明确涉及行业、同业、竞争、排名或对比时，才扩展到**本公司 + 行业**；
- 行业归属以数据源公司基本信息为准；无法可靠识别行业时，不自动扩展；
- 近期、实时、新闻、异动类问题允许 Agent 自动调用 MCP/网页，但最终答案必须清楚标示外部来源、数据截至时间与适用范围；
- 首期优先可信查证，不在同一版本内一次性完成完整研究工作台。

## 3. 结构性诊断

当前页面把“财报查证、全库检索、实时工具、网页补充、会话历史”都放进一个普通聊天流，但没有把**范围、证据和运行状态**作为回答的一部分。

这导致三个与视觉无关的结构性错误：

1. “聚焦报告”承诺的是优先级而非边界；用户无法判断是否混入了其他公司/期次的事实。
2. 新回答临时拥有引用与工具状态，但会话持久化只保存文本；历史回答失去证据链，研究结论不可复核。
3. 工具结果以长文本进入模型上下文，数字的单位、报告期、口径和数据时间没有统一验证；模型可以把不兼容来源写成同一结论。

## 4. 设计原则

| 原则 | 拒绝的替代方案 |
|---|---|
| 范围先于检索；`company_only` 必须是硬过滤 | 继续只提高目标报告权重，再依赖模型“注意不要混用” |
| 证据和运行状态是回答数据，而非临时 UI | 只在本次 SSE 完成时渲染卡片、历史页仅保留文本 |
| 财务事实先结构化再写作 | 让模型直接从 PDF 片段、网页摘要和 MCP 文本中自由摘数 |
| 外部数据可自动调用，但必须显式说明来源和时间 | 每次调用都打断用户确认，或完全隐藏外部来源 |
| 简单结论保持连续段落；复杂任务才展示过程 | 用卡片、徽章和工具名堆满所有普通回答 |
| 停止/失败是领域状态，不是前端提示 | 将残片当作完整消息，靠用户自行判断 |
| 先稳定可信底座，再扩大自主性 | 一次性引入多个自由协作 Agent 和长期任务 |

## 5. 信息架构与交互

### 5.1 回答首部：范围与来源摘要

每条新回答顶部展示不可变 Scope：

```text
农业银行 · 本公司 · 2026 半年报
已使用：PDF 原文 4 处 ｜ 外部实时数据 0 处
```

行业扩展时：

```text
农业银行 · 银行业（数据源分类） · 2026 半年报
已扩展同业范围：用于行业对比
```

范围栏不展示内部执行字段；用户可通过“调整范围”选择本公司、本公司+行业或全库。没有公司上下文的泛问题可使用全库，但必须显示“全库财报检索”。

### 5.2 回答正文与证据

- 简单回答：左对齐连续段落，关键数字在行内附 PDF 页码链接；
- 复杂回答：按“结论 / 关键事实 / 证据 / 风险或冲突 / 下一步”组织；
- PDF 证据点击后必须直达对应 PDF 页；文件不存在时显示不可用，不生成伪链接；
- 网页来源显示站点、标题、URL 和发布日期/抓取时间；
- 实时工具显示业务化说明与“数据截至”，不能仅显示 `get_xxx` 工具名；
- 不重复显示同一个数字，也不为一般结论增加“待核验”标签。

### 5.3 过程与任务状态

简单问答只显示简洁状态；复杂任务显示可折叠的研究过程：

```text
已完成 3/3：检索本公司报告 · 获取实时行情 · 核对来源
```

停止状态：

```text
已停止：已保留前 2 个已完成步骤；最后一段回答未完成
[继续研究] [重新生成]
```

### 5.4 会话与研究资产

会话列表以公司、行业、报告期、意图、运行状态、更新时间为可筛选字段，而不是只依赖首问标题。用户可收藏结论和证据包、编辑重问、分支追问、继续已停止任务、导出研究纪要。研究记忆仅保存用户显式确认的事实、证据和研究决策。

## 6. 数据契约

### 6.1 `Scope`

```json
{
  "mode": "company_only",
  "companies": [{"code": "601288", "name": "农业银行"}],
  "report_ids": ["601288:2026-06-30:semi_annual"],
  "industry": null,
  "source_policy": {
    "local_pdf": true,
    "historical_analysis": true,
    "market_data": false,
    "web": false
  },
  "resolved_at": "2026-09-10T20:30:00+08:00"
}
```

范围解析：从报告跳转或识别到单一公司时为 `company_only`；问题明确要求行业/同业/竞争/排名/对比时解析为 `company_industry`；多公司比较仅包含明确公司；无法识别公司时为 `whole_corpus`。行业分类失败必须回退 `company_only` 并在回答中说明。

### 6.2 `Fact`

```json
{
  "metric": "operating_cash_flow",
  "value": -621.69,
  "unit": "亿元",
  "period": "2026-06-30",
  "period_kind": "semi_annual_cumulative",
  "entity_scope": "consolidated",
  "company_code": "601288",
  "source_type": "pdf",
  "evidence_ids": ["pdf_p40_cell_12"],
  "verification": "verified"
}
```

`Fact` 必须包含数值、单位、期间、期间类型、主体口径、公司和证据。缺少口径的事实不能参与计算、排名或确定性结论。

### 6.3 `EvidenceArtifact` 与 `ToolArtifact`

| 类型 | 必要字段 |
|---|---|
| PDF | `report_id/source/page/snippet/pdf_filename` |
| 网页 | `url/title/published_at/fetched_at/snippet` |
| 工具 | `provider/tool_name/arguments_summary/result_summary/as_of/status` |
| 冲突 | `fact_ids/conflict_reason/resolution` |

### 6.4 `AnswerRun`

每条助手消息以 `AnswerRun` 保存：`id/role/content/status/scope/facts/artifacts/retrieval/created_at/completed_at/elapsed_seconds/model`。状态仅允许 `completed/partial/stopped/failed`。旧消息迁移后标记为“历史回答，未保留证据包”，不伪装为新式可核验答案。

## 7. 四阶段交付

### M1：可信回答底座

**目标：** 解决证据持久化、PDF 页码跳转、范围硬过滤、事实/来源基础校验。

- 引入 `Scope`、`Fact`、`EvidenceArtifact`、`ToolArtifact`、`AnswerRun`；
- 会话 schema v2 持久化所有回答产物与完成状态；
- 本公司范围改为检索硬过滤；行业扩展按用户确认的规则进行；
- PDF、网页、工具来源统一渲染；PDF 引用可跳页；
- 用户停止后保存 `stopped` 与已完成产物；
- 历史旧消息保留但明确其没有证据包。

**验收：**

1. 历史重开后引用、工具轨迹、外部数据时间和状态完整保留；
2. 关键 PDF 数字可跳至准确页；
3. `company_only` 不得混入其他公司证据；
4. 行业分类失败时不扩展同业；
5. 外部事实无来源或无截至时间时不得进入最终结论；
6. 停止回答不显示为完整结果。

### M2：受控检索、工具策略与事实核验

**目标：** 将问题、范围、工具使用和事实比较从提示词约束提升为可验证策略。

- `IntentRouter` 输出 `report_fact/company_trend/industry_benchmark/realtime_market/event_attribution/research_task`；
- `ToolPolicy` 按意图限制工具、次数、超时和来源；
- `FactNormalizer` 统一金额、单位、时间、单季/累计、合并/母公司口径；
- `ClaimVerifier` 检查数字证据、Scope、数据时间、引用页码与冲突；
- 冲突创建 `FactConflict`，最终答案必须说明而非自行选边。

**验收：**

1. 本报告问题的其他报告召回为零；
2. 关键数字均有期间、单位、主体口径和证据；
3. 不需要实时信息的提问不调用外部工具；
4. 同一指标冲突时输出来源差异；
5. 检索或工具降级时不生成伪 PDF/网页引用。

### M3：研究型 Agent

**目标：** 让复杂任务具备 Planner → Executor → Verifier 的可见、可恢复执行链路。

- `ResearchPlan` 保存目标、Scope、子步骤、完成判据；
- 状态机：`planned → running → verifying → completed`，或 `awaiting_input/partial/stopped/failed`；
- 独立步骤可并行检索，归一、比较和验证按依赖顺序执行；
- 仅重试失败步骤，避免重复使用仍有效的工具结果；
- 最终输出固定包含结论、关键事实、证据、风险/冲突、下一步。

**验收：**

1. 多步骤任务可见计划、步骤状态、证据数量与阻塞原因；
2. 停止后能从已完成步骤继续；
3. Verifier 不通过的关键结论不能标为已确认；
4. 简单问题不被冗长计划打断。

### M4：研究工作台与质量运营

**目标：** 将会话升级为可检索、可复用、可评测的研究资产。

- 会话按公司、行业、期间、意图和状态筛选；
- 收藏、分支、编辑重问、恢复、导出证据纪要；
- 用户显式保存的事实/决策进入可撤销研究记忆；
- 建立回归评测、运行指标与发布门槛。

**验收：**

1. 任一历史结论均能回到完整证据包；
2. 会话筛选不依赖标题关键词；
3. 每个版本可运行固定金融问答评测集；
4. 可量化范围混入率、关键数字引用覆盖率、页码跳转成功率、工具成功率、停止恢复率和性能。

## 9. 失败、降级与安全边界

| 场景 | 强制行为 |
|---|---|
| 本公司 PDF 未索引 | 明确提示，不自动混入其他期或同业 |
| PDF 文件缺失 | 显示来源不可用，不生成伪页码跳转 |
| 行业分类失败 | 保持本公司范围并解释原因 |
| MCP/行情失败 | 保留 PDF 结论；实时问题明确说明不可用 |
| 网页搜索失败 | 不生成网页来源；仅使用已有证据 |
| 检索模型降级 | 标明未使用本地 PDF 检索，禁止生成 PDF 引用 |
| 用户停止 | 保存 `stopped` 与完成步骤，禁止标记完整 |
| 工具或网页内容 | 不得自动成为财报事实；必须带来源、时间和适用范围 |

红线：**系统不得产生买卖指令、自动交易、未经用户配置的持续监控或主动推送；不得把模型推断、来源缺失文本或停止任务残片写为长期已确认事实。**

## 10. 测试、评测与发布策略

### 自动化测试

- 单元：范围解析、行业失败回退、Fact 单位/期间/口径校验、Artifact 序列化、旧会话迁移、工具策略和状态机；
- 集成：SSE 全生命周期、停止/恢复、硬范围检索、PDF 页码 URL、工具降级与冲突输出；
- 浏览器：范围栏、来源页码跳转、历史重开、外部时间展示、移动端无横向溢出；
- 回归：现有 RAG 引用、MCP 熔断、会话历史、流式草稿与停止行为必须继续通过。

### 金融问答评测集

覆盖本报告数字、跨期比较、行业比较、实时行情、新闻归因、来源冲突、PDF 缺失、工具失败、停止恢复。每个用例定义范围、允许来源、预期事实、禁止混入数据和验收引用。

### 发布门槛

- 本公司范围无跨公司证据混入；
- 关键数字均有有效证据；
- PDF 页码跳转有效；
- 外部事实均有来源与时间；
- 停止任务不伪装完整；
- 全量测试、评测集和桌面/平板/移动浏览器验收通过。

## 11. 范围分层

| Bucket | 能力 | 说明 |
|---|---|---|
| ✅ 已建模且已暴露 | RAG 片段、页码、流式 SSE、会话、MCP、网页搜索、熔断、工具预算 | M1/M2 可复用现有能力 |
| ⚠️ 已建模但未完整暴露 | 报告身份、报告聚焦、来源引用、停止时部分内容保存、工具阶段 | 需改为硬范围、可持久化、可恢复的用户能力 |

**推荐的完整首个切片：** M1。它完成“针对本公司财报查证，回答可追溯、范围不混、历史可复核”的用户任务。
