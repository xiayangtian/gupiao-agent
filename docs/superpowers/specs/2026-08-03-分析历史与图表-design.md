# 分析历史入口 + 财务指标折线图 + 全页分析视图 设计文档

> 日期：2026-08-03
> 前置：`2026-08-03-财报分析前端界面-design.md`（已实现）的增量演进

## 1. 背景与目标

当前 Web 前端（FastAPI + 原生 JS 单页）的局限：

1. 分析结果落盘 `reports/analysis/*.json` 后没有读取入口 —— 每次"开始分析"都重新调用 AI，已有结果无法直接查看；
2. 分析维度为纯文字，没有基于财务经营数据的可视化；分析面板挤在右侧 340px 窄栏，与 PDF 预览共享版面，可读性差。

**目标：**

- 提供"分析历史 + 本地资源"查看入口：已下载 PDF 与已分析报告可直接查看，不经过 AI 重新处理；
- 基于财务经营数据生成折线图（Chart.js 本地化，离线可用）；
- 分析结果独占整页展示（全页分析视图）。

**非目标（本次不实现，但见 §7 预留扩展）：**

- 同一公司多年财报的**对比分析**与对比图（数据结构预留，功能后续做）。

│  （文件名解析 + JSON 内容内嵌）                          │

## 3. 后端

### 3.1 `GET /api/history`

扫描本地磁盘，返回按公司分组的资源。**响应一次性包含分析内容**（单文件几 KB 级），前端无需二次拉取。

```json
{
  "companies": [
    {
      "code": "600900",
      "name": "长江电力",
      "analyses": [
        {
          "year": 2024,
          "period": "2024-12-31",
          "filename": "长江电力_600900_2024_分析报告.json",
          "content": { "...AnalysisReport.to_json() 完整内容（含 meta/dimensions/metrics）" }
        }
      ],
      "pdfs": [
        { "period": "2025-12-31", "type": "annual", "title": "长江电力_600900_年报_2025.pdf" }
      ]
    }
  ],
  "orphan_analyses": [
    {
      "company_label": "长江电力",
      "year": 2024,
      "filename": "长江电力_2024_分析报告.json",
      "content": { ... }
    }
  ]
}
```

- **分析文件扫描**：`reports/analysis/*.json`（不含 `*_分析报告.json` 以外的 JSON，约定 `_分析报告.json` 后缀）。
  - 从文件名解析：`公司_代码_年份_分析报告.json`（Web 端命名）与 `公司_年份_分析报告.json`（旧 CLI 命名）。
  - code 存在（`_(\d{6})_` 模式）→ 归入对应公司；无 code → `orphan_analyses`（仍可查看分析，但不绑定 PDF 预览/公司名映射）。
  - period：分析 JSON 的 `meta` 内含 period（新格式由 Web 写入）→ 直接使用；否则按年份推断 `YYYY-12-31` 并标记 `period_from_filename: true`（仅用于展示排序，不承诺 PDF 匹配）。若完全无法确定年份 → 该条分析仍展示，year 为 null。
  - JSON 解析失败（损坏）→ 跳过该文件，不影响其他条目。
- **PDF 扫描**：`reports/*.pdf`，沿用 `ReportDownloader.build_filename` 的命名 `{公司}_{代码}_{类型}_{年份}.pdf`（类型 ∈ annual/semi_annual/quarterly；semi_annual/quarterly 无法确定季度号 → 归入对应类型的 period 末月，**不提供 PDF 预览入口**（避免错误关联），仅展示文件名；annual → period=YYYY-12-31）。
  - PDF 与公司关联用代码（无畏 `公司名` 变色）。
- **排序**：companies 按最近一次分析时间倒序（取该组内最新分析文件的 mtime）；组内 analyses 年份倒序、pdfs period 倒序。
- **错误处理**：`reports/` 或 `reports/analysis/` 不存在 → 返回 `[]`，HTTP 200。

### 3.2 分析接口扩展（analyzer）

```python
def _extract_metrics(self, pdf_text: str) -> Optional[List[Dict[str, Any]]]:
    """从财报正文抽取 5 项核心指标（含可用年份），失败返回 None"""
```

- 调用一次（`response_format={"type": "json_object"}`），System prompt 固定 5 项指标、单位约束、年份约束、"仅输出正文出现的数据，缺省 null"。
- 指标定义（固定集合，避免 prompt 漂移）：

| 字段 | 指标 | 单位 | 用途 |
|---|---|---|---|
| revenue | 营业收入 | 亿元 | 图 1 |
| net_profit | 净利润 | 亿元 | 图 1 |
| roe | 净资产收益率 ROE | % | 图 2 |
| gross_margin | 毛利率 | % | 图 2 |
| debt_ratio | 资产负债率 | % | 图 2 |

- **校验**：year 为整数且在 [2000, 当前年+1] 区间；数值为数字；异常/越界值丢弃；输出按年升序；数据为空 → 返回 None。
- 抽取失败（网络/解析/非法 JSON）→ `metrics=None`，**不阻塞**三个文字维度，分析照常进行。
- **存储**：`AnalysisReport.metrics`（新增可选字段，默认 None）；`to_json()` 增加 `"metrics"`；`save()` 落盘 JSON 同步携带。
- **兼容性**：CLI `analyze`/`analyze --all` 同样获得（多一次 AI 结构化调用，增产文档）；旧 JSON（无 metrics）保持可读。

### 3.3 报告列表 `analyzed` 标记

`GET /api/companies/{code}/reports` 每项新增 `"analyzed": bool`：

- 判据：读取 `reports/analysis/` 下全部 JSON，为每份分析解析出 `(code, period, year)`（新格式读 `meta.period`；旧格式按文件名 `公司_年份_分析报告` 得 year，code 不可得）。
  - 报告项有**精确 period 匹配**（meta.period == 报告 period）→ true；
  - 无 meta.period 的旧格式文件，若 code 匹配且年份 == 报告期年份 → true（近似：同一年年报/中报共享一个分析文件时均标记）；
  - 其余 false。

## 4. 前端

### 4.1 左栏 tab「列表 | 历史」

- 左栏 header 两个 tab 按钮；默认「列表」（现有行为不变）。
- 「历史」渲染 `GET /api/history`：
  - 公司条目：`名称（代码）`＋折叠箭头；展开：
    - 分析条目（年份 ＋ 「查看分析」→ 全页分析视图）
    - 已下载 PDF 条目（点击 → 切回列表视图并 iframe 预览对应报告 + 选中高亮；无法定位 period 的条目不可点，灰色）
  - `orphan_analyses` 分组「无法关联的旧分析」：仅展示分析入口。
  - 空历史：显示「暂无本地分析记录」。
- 进入/退出历史 tab 触发一次刷新（每次进入拉取最新 `/api/history`；新分析完成回切列表）。

### 4.2 全页分析视图（view-analysis）

页面为两层包裹，`display` 切换（state 不丢、轮询不中断）：

```
<div id="view-browse">  现有 topbar + searchbar + 三栏 layout
<div id="view-analysis" class="hidden">
```

全页视图结构（自上而下，最大宽 1200px 居中）：

1. **顶栏**：`← 返回列表` | 标题「长江电力 · 2025-12-31 年度报告」 | AI 状态徽章（复用）
2. **指标速览卡**（当前年份 5 项指标，无 metrics 整卡隐藏）
3. **折线图区**：
   - 图 1：营收/净利润（左轴 亿元）
   - 图 2：ROE / 毛利率 / 资产负债率（右轴 %）
   - 数据 = 该 **code** 所有本地分析 JSON metrics 的并集（按年升序，同指标同年冲突取最近分析的值）
   - 双图布局：宽屏并排、窄屏纵向（CSS Grid/flex 自适应）
4. **维度卡片**：财务摘要 / 风险识别 / 经营亮点（现有 renderReport 复用，全宽三列自适应）
5. **自由问答区**：复用 `/chat`，会话 key 不变（与浏览视图同一报告同历史）
6. **来源注**：`reports/analysis/xxx.json` 路径 + 模型 + 时间戳

**图表数据缺口处理**：某年某指标 null → 该系列该点断开（不伪造连续）；全部无图数据 → 图表区显示提示文案（针对旧格式：「⚠️ 该分析为旧格式，无指标数据；如需图表可对最新报告重新分析（会与历史合并）」）。

**Chart.js 使用**：

- 版本固定 Chart.js 4.4.x UMD；实现阶段先下载 `webapp/static/vendor/chart.umd.min.js`（来源 jsdelivr `chart.js@4.4.x/dist/chart.umd.min.js`）再引入。
- `index.html` 仅本地 `<script src="/static/vendor/chart.umd.min.js"></script>`；不引用 CDN。
- `drawCharts()` 前置判断 `typeof window.Chart === "undefined"` → 渲染文字提示，不抛错。
- 销毁：切换视图/重绘前 `chart.destroy()` 防内存泄漏。

### 4.3 进入全页视图的数据流

- 来源两种，统一渲染入参 `{code, name, period, year, dimensions, metrics}`：
  1. **历史记录**：内容内嵌在 `/api/history`，直接渲染；
  2. **当前报告**：若磁盘已存在分析 →「查看本地分析」按钮（优先级高于「开始分析」）读取本地 JSON 渲染；不存在 → 现有 AI 任务流程（提交→轮询），完成后**自动打开全页视图**渲染结果。
- 轮询中切走再切回：轮询不中断（`pollTask` 结束渲染时若用户在分析视图则直接刷新）。
- 维度渲染复用现有 `renderReport`/`renderMarkdown`，仅布局宽度变化。

### 4.4 报告列表「已分析」标记

- 列表项右侧：`✓（已分析）`当 `analyzed=true`（样式与现有已下载 ✓ 区分，如紫色小标记「AI」或「已分析」文字）。
- 选中已有分析的报告：分析面板在「开始分析」上方显示「查看本地分析」按钮（点击 → 全页视图，无 AI）。

## 5. 错误处理

| 场景 | 行为 |
|---|---|
| `/api/history` 目录不存在 | 200 + `{companies: [], orphan_analyses: []}` |
| 单份分析 JSON 损坏 | 跳过该条，其余照常（不整体 500） |
| metrics 抽取失败 | `None`，分析照常，无图表提示 |
| Chart.js 未加载 | `drawCharts()` 前置判断，文字提示 |
| 旧格式无 metrics | 维度正常 + 「无图表数据」提示 |
| 历史 PDF 无法定位 period | 条目展示但不可点击预览（说明文字） |

## 8. 扩展预留：同一公司多年财报对比分析（本期不实现）

**数据结构已预留**：metrics 是「(company, year, 指标值)」扁平集合，随各分析 JSON 落盘；`/api/history` 已按公司聚合返回全部（含历年 metrics）。

后续"多年对比分析"最小改动路径：

1. 前端：全页分析视图增加「对比年份区间选择」→ 图表按所选区间重排数据（现有数据点无需任何格式变更）；
2. 可选：`/api/history` 增加 `?code=&year_start=&year_end=` 过滤参数（后端 1 行 filter）；
3. 如需对比"同一年年报 vs 中报"：`period` 已支持 `semi_annual`/`quarterly` 类型标注 → 图例按类型分组。

**不需要**：修改存储格式、迁移历史文件、新增持久化 schema。

## 9. 风险与决策记录

- **Chart.js 本地化**（用户决策）：不依赖 CDN，提前下载 vendor 文件入库，页面本地引用。
- **指标集合固定为 5 项**：避免 prompt 漂移导致图表不一致；后续如需扩展字段，只需更新 prompt + 前端图定义点（向后兼容新增 key）。
- **AI 每份分析多 1 次调用**：换取结构化数据；失败降级为 None，不阻塞主流程。
- **旧文件不自动补数**：不重跑 AI（尊重"不经过 AI"诉求），提示语引导用户对最新报告重新分析。
