# 智能问答对话链路文案优化

## 背景

智能问答已具有进度提示、资料查询、来源与事实说明、授权补充、完成/失败状态及后续操作等多类用户可见文案。部分文案偏内部实现术语（如“正在制定受限执行计划”），且同一链路语气与命名不够一致。

## 目标

仅优化智能问答对话链路内的用户可见表达，使其直白、简洁、状态准确且前后一致。用户已确认覆盖：进度、查询与来源、完成/失败、授权、证据说明及操作按钮。

## 范围

- 思考/执行阶段、查询开始/完成/失败、答案完成/部分/停止/失败。
- 财报补充授权、补充结果、检索不足及核验状态。
- 来源/证据/口径说明、研究步骤与恢复入口。
- 改写后再问、另开会话追问、重试回答及反馈编号等对话操作。
- 限于智能问答对话界面及其 SSE 用户可见消息。

## 非目标与不变量

- 不修改执行逻辑、状态机、来源授权、会话所有权、数据范围、证据事实、校验/拒答规则或安全边界。
- 不扩展到财务报告、下载页、设置页、MCP 诊断页等其他页面。
- 不在没有证据时暗示来源已查询、数据已获取或研究已完成；失败信息继续使用受控文案，反馈编号仍关联既有 run id。
- 不变更既有 API 字段、事件类型或按钮动作标识。

## 验收标准

1. “正在制定受限执行计划”替换为面向用户且不暴露内部控制术语的阶段提示。
2. 查询、完成、失败、部分完成、停止及授权文案能准确表达当前状态，并避免内部工具名/错误码。
3. 来源/证据文案保持来源归属、数据时点及核验边界，不增加证据主张。
4. 操作按钮文字能清楚表达动作和后果，事件处理与授权边界不变。
5. 相关单元测试、对话浏览器回归通过；`git diff --check` 通过。
