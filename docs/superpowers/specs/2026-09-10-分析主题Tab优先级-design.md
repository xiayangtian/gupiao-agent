# 分析主题 Tab 优先级设计

## 目标

将分析结果中的动态主题 Tab 从长句标题改为短标签，明确表达主题重要程度，并按重要程度稳定排序；完整标题和摘要移入主题正文，避免信息丢失。

## 范围

- 仅处理分析结果的动态主题 Tab。
- 不处理分析文件命名/迁移，也不处理“待核验”标签。
- 旧报告不自动重新分析、不消耗 AI 配额。

## 数据契约

- `InsightCandidate` 与 `InsightSection` 增加可选 `tab_label: str`。
- Planner 对新报告输出 `tab_label`：最多 6 个汉字，不含编号与标点。
- `AnalysisDocument` 序列化/反序列化保留该字段；历史 v3 文档缺失字段时视为空字符串。
- 不增加 schema 版本；字段可选，旧文档兼容。

## Tab 标签

前端按下列优先级取得可见标签：

1. 合法的 `section.tab_label`；
2. 由 `section.title` 的关键词映射得到的固定短标签（如现金流、资产负债、盈利结构、成本费用、股东回报、股权治理、风险事项、研发投入、运营效率）；
3. 标题首个分句的前 6 个字符加省略号。

Tab 必须保留完整标题的 `title` 与 `aria-label`。主题正文必须新增完整标题 H3，且在 `summary` 非空时显示为导语。

## 重要程度

- 分数为 `score` 中 evidence_sufficiency、source_reliability、materiality、clarity、interest_relevance 的有限数值和。
- 在本次可见主题集合内按相对分档：`score >= max - 3` 为“高”；`score >= max - 8` 为“中”；其余或无有效分数为“一般”。
- Tab 显示短文本标记“高 / 中 / 常”及颜色，避免只依赖颜色；`aria-label` 包含“重要程度：高/中/一般”。
- 不为风险主题增加额外颜色，避免与正文“风险”语义混淆。

## 排序与交互

- 前端每次渲染都复制并按总分降序排序；同分按发现数降序，再按 `section_id` 升序。
- 默认及无效 active tab 回退到“快速结论”；有效 active tab 始终按 `section_id` 保持，不按视觉位置。
- 标签保持键盘可聚焦，触控高度至少 44px；移动端必须换行且不能横向溢出。

## 视觉

- 复用现有设计 token；重要度颜色只用于小型状态标记，不替代文本。
- 高：深红系；中：深琥珀系；一般：深蓝灰系；文字/背景对比度至少 4.5:1。
- 活动 Tab 保持既有深色选择态，重要度标记调整为高对比前景。

## 验证

- Python 单测覆盖 planner 合约、清洗、持久化和 v3 兼容。
- Node 单测覆盖标签回退、分数分档、排序和 active-tab 回退。
- 浏览器测试与真实浏览器 QA 覆盖短标签、完整标题、重要度文本、排序、键盘可访问性和桌面/平板/手机无横向溢出。
