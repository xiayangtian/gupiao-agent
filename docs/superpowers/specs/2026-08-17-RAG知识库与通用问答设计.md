# RAG 知识库 + 通用对话入口 + 单报告问答增强 设计文档

> 日期：2026-08-17
> 状态：设计方案（未实现）
> 前置：`2026-08-05-智能体架构优化设计.md`（可复用其"证据优先 / 可恢复 / 兼容现有"原则）

## 1. 背景与目标

### 1.1 现状与痛点

当前项目已经具备：PDF 下载、AI 多维分析、Web 任务轮询、单报告自由问答（分析页 + 历史页两个入口）。但问答链路本质上仍是"截断全文直塞 LLM"：

1. **信息覆盖严重不足**：`ReportAnalyzer._extract_pdf_text()` 只保留"前 10 页 + 后 10 页 + 中间 20 页"，并硬截断到 1~1.5 万字符。年报普遍 150+ 页，公司治理、行业分析、分业务数据、研发投入、ESG 等章节大量丢失，问到这些内容模型只能靠编造或答"未披露"。
2. **每次问答重复解析 PDF**：无索引、无缓存，pypdf 每次全量解析，慢且浪费；无法做跨报告 / 跨公司 / 跨年度的综合检索。
3. **两套数据孤岛**：PDF 原文与已生成的分析报告（`reports/analysis/*.md|.json`，含结构化指标 `metrics`）互不打通——而这些提炼结果恰恰是问答命中率最高的资产。
4. **没有通用对话入口**：目前只能"选中某份报告后提问"，缺少一个可回答"长江电力近三年营收趋势""对比贵州茅台与长江电力毛利率"这类跨报告问题的统一入口。

### 1.2 目标

1. 建立**持久化 RAG 知识库**：把本地年报 PDF 原文 + 既有 AI 分析报告（`.md/.json`）等**本地产出资产**全部切块、向量化、入库（可增量更新）。
2. **通用对话入口**：基于全库检索回答跨报告 / 跨公司 / 跨年度问题，返回带引用来源的答案。
3. **单报告问答增强**：现有"分析页 / 历史页针对此报告的对话"改为走 RAG（按 `report_id` 过滤检索），回答更全、更快、带页码引用；库未就绪时回退现有截断全文逻辑，保证兼容可用。
4. 兼容现有 CLI、Web API、Markdown/JSON 产物与前端交互。
5. **自动摄取**：下载 PDF 或完成分析后，自动把对应结果建入 RAG（可配置开关）。
6. **文件管理页面**：按类型分类展示已加入 / 未加入 RAG 的本地文件，支持单文件加入与一键全加。
7. **索引可回收**：支持删除部分文件的 RAG 索引，恢复"未添加"状态。

### 1.3 非目标

- 不引入分布式向量库 / 多副本 / 大规模集群（当前单机单进程部署）。
- 不做多用户权限体系。
- 不实现自主交易或自动下单。

### 1.4 可入库的本地产出资产盘点

除 PDF 原文外，项目里还有多种**本地产出资产**，按入库价值排序：

| 资产 | 位置 / 结构 | 入库价值 | 切分方式 | 建议 |
|---|---|---|---|---|
| AI 分析报告（JSON） | `reports/analysis/*.json`：`meta` + `dimensions[]` + `metrics[]` | ★★★★★ 高质量提炼，问答命中率高、token 省 | 按维度切；超长按小节再切 | **Phase 1 入库**，与 PDF 双源并列返回 |
| 结构化指标（metrics） | JSON `metrics[]`（营收/净利/ROE/毛利率） | ★★★★ 跨年对比问答的核心数据 | 自然语言化句子（"2025 年营业收入 862.42 亿元"） | **Phase 1 随分析报告一并入库** |
| AI 分析报告（Markdown） | 同名的 `.md` | 与 JSON 内容同源 | 由 JSON 派生，避免重复解析 | 只入一份（JSON 优先） |
| 用户问答记录 | Web 内存会话 / 未来落盘 | ★★★ 高频问题 + 高质量回答可沉淀为 FAQ | 整轮 QA 作为一条 chunk | 可选入库（默认关闭，避免噪声） |
| 未来智能体中间产物 | 事实抽取 / 指标计算 / 校验结果（见智能体架构设计） | ★★★★★ 可溯源证据 | 按"事实 + 引用"成 chunk | Phase 3 预留 `source=fact` |
| 下载 / 分析状态、会话 | — | 不适合 RAG | — | 走 SQLite / manifest，不进向量库 |

> 原则：**结构化、已提炼的资产优先入库**（分析报告 > 指标 > 原文 > 问答沉淀）；同一事实多源命中时，用提炼结论解释、原文作证据。

## 2. 技术选型

| 层次 | 推荐选型 | 备选 | 理由 |
|---|---|---|---|
| 向量库 | **ChromaDB**（嵌入式、本地文件持久化） | LanceDB、SQLite-vec、FAISS+自管索引 | 零独立服务、`pip` 即装、自带元数据过滤与持久化；数据量级（几十份年报 × 每份千级 chunk）完全够用，后续可平滑迁移 |
| Embedding | **本地 `BAAI/bge-small-zh-v1.5`**（sentence-transformers / onnxruntime） | `bge-m3`、中转站 Embedding API（如 `text-embedding-3-small`） | 中文财报效果好、离线可用；提供 `provider: local | api` 开关，网络受限或内存紧张时可切远程 API |
| 分块 | **章节感知分块 + 表格整块保留 + overlap** | 固定窗口切分 | 年报章节结构高度稳定（第一节 重要提示 … 第十节 财务报告），按章节切可显著提升检索命中质量 |
| 检索 | 初版：**向量 top-k + 元数据过滤**；二期：**BM25 关键词混合 + 轻量 rerank** | — | 向量检索对语义问题友好，关键词检索对"营收/ROE/资产负债率"这类精确指标查询更稳 |

## 3. 总体架构

```text
┌────────────────── 数据摄取层 Ingestion ──────────────────┐
│  reports/*.pdf（逐页全文）  reports/analysis/*.json|.md   │
│        章节识别 → 智能分块 → 元数据抽取 → 向量化          │
│                  ChromaDB（幂等 upsert，增量摄取）        │
└──────────────────────────┬───────────────────────────────┘
                           │ 查询
┌────────────────── 检索层 Retrieval ──────────────────────┐
│  Query Embedding → 向量 top-k + 元数据过滤（report_id/   │
│  ticker/year/source）→（二期：BM25 混合 + rerank）        │
└──────────────────────────┬───────────────────────────────┘
                           │ 片段（含 report_id/章节/页码）
┌────────────────── 问答层 QA ─────────────────────────────┐
│  通用入口 POST /api/chat（跨报告）                       │
│  单报告 POST /api/reports/{code}/{period}/chat（RAG 补强）│
│  Prompt 组装 → LLM → 答案 + 引用列表（可跳转 PDF 页码）  │
└──────────────────────────────────────────────────────────┘
```

**核心思路**：摄取层把"原文"变成"带元数据的可检索片段"；问答层不再依赖每次现读 PDF，而是"检索 → 拼装上下文 → 生成 + 引用"。

## 4. 数据模型与索引结构

### 4.1 文档身份

```text
report_id = {ticker}:{period}:{report_type}
示例      = 600900:2025-12-31:annual
```

### 4.2 Chunk 元数据（ChromaDB metadata）

| 字段 | 示例 | 说明 |
|---|---|---|
| `report_id` | `600900:2025-12-31:annual` | 报告身份，过滤主键 |
| `ticker` / `company` | `600900` / `长江电力` | 公司与代码 |
| `year` / `period` | `2025` / `2025-12-31` | 报告期 |
| `report_type` | `annual` | 年报 / 半年报 / 季报 |
| `source` | `pdf` / `analysis` / `qa`（可选）/ `fact`（预留） | 来源：PDF 原文 / AI 分析报告 / 问答沉淀 / 未来事实抽取 |
| `section` | `第三节 管理层讨论与分析` | 章节标题（pdf）；`财务摘要` 等维度名 / `指标摘要`（analysis） |
| `page` | `23` | 页码（pdf 源，用于引用跳转） |
| `chunk_index` | `5` | 章节内分块序号 |
| `text_hash` | `sha1(...)` | 内容指纹，用于幂等去重 |

### 4.3 幂等设计

- chunk id = `sha1(report_id + section + chunk_index + text_hash)[:16]`，重复摄取走 **upsert** 天然去重；
- 整份报告更新/删除按 `report_id` 过滤批量处理；
- 摄取状态单独落一份 `manifest.json`（或 SQLite）：记录每份报告的 `content_hash`、chunk 数、摄取时间，供增量摄取与状态展示。

## 5. 摄取流程（Ingestion Pipeline）

1. **扫描**：`reports/*.pdf` + `reports/analysis/*.json`（同名 `.md` 由 json 派生，不重复入库）。
2. **PDF 全文提取**：复用现有 pypdf 能力，改为**逐页全量**提取并记录页码，不再截断；财务报告章节（第十节）表格错乱时，二期用 pdfplumber 整表提取兜底。
3. **分析报告切分（source=analysis）**：直接读 `dimensions[]`，每个维度 content 为一个 chunk（超长按小节再切，`section=维度名`）；`metrics[]` 自然语言化为"指标摘要"chunk（如"2025 年营业收入 862.42 亿元、归母净利润 345.03 亿元、ROE 15.9%"）；`meta` 写入 chunk 元数据。
4. **章节识别（source=pdf）**：内置 A 股年报章节关键词表（`第一节 重要提示`、`第三节 管理层讨论与分析`、`第十节 财务报告` 等），按出现位置切分；未命中章节的按页序兜底切分。
5. **分块策略（source=pdf）**：
   - 优先按章节边界切；
   - 章节内按自然段聚合到 `chunk_size`（默认约 800 字）；
   - 表格内容优先整块保留（年报财务数据表是问答核心）；
   - 相邻 chunk 保留 `chunk_overlap`（默认约 100 字）防止截断丢失语义。
6. **元数据抽取**：公司 / 代码 / 年份复用 `_parse_meta` + `_extract_company_name`；分析报告直接读 json 的 `meta` 字段与维度 ID。
7. **向量化 + upsert**：embedding → ChromaDB collection `annual_reports`。
8. **状态落盘**：更新 manifest，支持增量摄取（只处理 hash 变化的报告）。

触发方式：CLI `rag ingest`；Web 提供"同步索引"按钮 / 报告分析完成后自动触发增量摄取。

### 5.1 文件级管理（列表 / 单文件加入 / 删除索引）

**文件条目**：`(report_id, source)` 唯一定位一个本地文件——`source=pdf` 对应 `reports/*.pdf`，`source=analysis` 对应 `reports/analysis/*_分析报告.json`。

**状态判定**：以 manifest 为准——`manifest[report_id].pdf_hash` 存在 → PDF 已加入；`analysis_hash` 存在 → 分析报告已加入；否则未加入。删除索引 = 删除对应 `(report_id, source)` 的 chunks 并把 manifest 中该 source 的 hash 置空，文件即恢复"未添加"。

**API**（详见 §7）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/rag/files` | 扫描本地 PDF + 分析报告，与 manifest 对比返回全部文件条目（含 `added` / `chunk_count`） |
| POST | `/api/rag/ingest/one` | body `{report_id, source}`，单文件加入（后台任务） |
| DELETE | `/api/rag/index/{report_id}/{source}` | 删除单文件索引，恢复未添加状态 |
| POST | `/api/rag/ingest` | 一键全加（跳过已添加，等价全量增量摄取） |

**分类**：前端按报告类型（年报 / 半年报 / 季报）筛选，每条目带来源标签（PDF 原文 / AI 分析报告）；分析报告归属其报告期展示。

### 5.2 自动摄取钩子

| 触发点 | 时机 | 说明 |
|---|---|---|
| CLI `download` | `download_all` 成功汇总后 | 对成功下载的 PDF 逐个 auto ingest |
| CLI `analyze` | 分析报告 `save()` 后 | ingest 该报告（连带 PDF，幂等） |
| Web `analyze_report` | 后台任务 `_run` 中 `save()` 后 | 同上 |
| Web `serve_pdf` | `_ensure_pdf` 下载成功后 | ingest 该 PDF |

开关：`rag.auto_ingest: true`（默认 true，前提 `rag.enabled: true`）。幂等由 manifest 保证：已加入且内容未变化的文件直接跳过，不重复计算。

## 6. 问答流程

### 6.1 通用对话入口 `POST /api/chat`

```json
// 请求
{ "question": "长江电力2025年营收和净利润是多少？", "filters": { "ticker": "600900", "year": 2025 } }
```

流程：
1. 查询向量化 → 向量 top-k（默认 8）+ 可选 `filters` 元数据过滤；PDF 原文、分析报告（含指标摘要）**双源并列返回**，各带 `source` 标注；同一事实双源命中时以分析报告提炼结论优先解释、PDF 片段作证据；
2. 拼装 Prompt：
   - system：金融分析师人设 + 引用规则（"引用必须用 `[n]` 标注，且只引用已提供的片段，找不到就说未披露"）；
   - 上下文：检索片段，每条带 `[n]` 编号与报告身份 / 章节 / 页码；
   - 历史（保留最近 4 轮）+ 用户问题；
3. LLM 生成；
4. 返回 `{ answer, citations: [{ report_id, company, year, section, page, snippet }] }`，前端可跳转 PDF 对应页。

### 6.2 单报告对话增强（现有 `/api/reports/{code}/{period}/chat`）

- 内部改为：`filters = { report_id: code:period }` 检索 top-k（同样包含该报告的分析报告与指标摘要），其余流程与通用入口一致；
- **保留**现有请求/响应字段与会话历史（内存 dict，最近 4 轮）——前端两个入口（分析页 qa-box、历史页 h-qa-box）**零改动即可获得增强效果**；
- **兜底**：RAG 库未就绪 / 该报告未索引 / 检索结果为空时，回退现有"截断全文直塞"逻辑，保证任何情况下可回答。

### 6.3 会话与引用

- 会话历史仍存内存（与现状一致），二期迁 SQLite 持久化；
- PDF 引用跳转：`/api/reports/{code}/{period}.pdf#page=N`（浏览器定位页码）。

## 8. 配置扩展（config.yaml / config.example.yaml）

```yaml
rag:
  enabled: true
  store_path: data/rag              # ChromaDB 持久化目录（gitignore）
  embedding:
    provider: local                 # local | api
    model: "BAAI/bge-small-zh-v1.5"
    api_model: "text-embedding-3-small"   # provider=api 时
  chunk_size: 800
  chunk_overlap: 100
  top_k: 8
  auto_ingest: true                 # 下载 / 分析完成后自动建入 RAG（需 enabled: true）
  rerank: false                     # 二期启用
```

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| pypdf 对复杂表格提取错乱 | 财务报告章节整表提取（pdfplumber 或规则拼接）；表格 chunk 优先整块保留 |
| 本地 embedding 模型下载体积 / 内存 | `provider: api` 开关；选用 100MB 级小模型 |
