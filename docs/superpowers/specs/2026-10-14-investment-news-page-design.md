# 投资资讯页：A 股市场、自选股与每日 AI 综述

**日期：** 2026-10-14  
**状态：** scoped（需求与方案经用户逐段确认；数据源使用条件仍待准入验证）  
**范围：** 为当前单机 Web 应用新增持久化 A 股资讯页，覆盖市场与最多 20 只共享自选股，定时/手动采集并提供分时点 AI 日综述；不做登录、多用户、全文转载或投资建议。  
**原型：** 无；当前不需要原型来解决已确认的交互结构。

## 1. 业务模型

### 核心概念

- **资讯条目**：新闻标题、来源提供且允许保存的摘要/片段、原始发布时间、来源名称、原文 URL、采集时间、市场/行业/证券关联。
- **资讯来源**：一个可单独启停、显示健康状态并记录最近采集结果的公开来源。
- **共享自选列表**：当前单机实例的全局 A 股列表，用户可添加/删除，最多 20 只；没有账户归属或跨用户隔离。
- **采集运行**：一次只负责读取来源、规范化、去重/关联和持久化；手动采集不隐式调用 AI。
- **今日综述**：针对一个 `Asia/Shanghai` 自然日、基于当天全部已入库且符合来源许可的资讯生成的 AI 结构化总结；手动生成不隐式采集。

### 状态及动作的业务后果

- 采集状态为排队中、运行中、成功、部分成功或失败。状态用于说明数据新鲜度和来源覆盖，不代表新闻真实性评级。
- 综述状态为未生成、生成中、成功、失败或已过期。旧综述保留并明确标注生成时间/数据水位，不伪装为最新结果。
- “手动采集”只产生一次采集运行并更新数据库；“手动生成今日综述”只读取数据库并重新调用 AI。两项操作互不触发。
- 自选股新增/删除只改变后续采集和筛选范围，不代表持仓，也不触发交易或投资建议。

### 当前不存在的概念

仓库没有用户登录、账户身份、自选股列表、持仓/仓位或针对个人风险承受度的投资画像。本设计只新增**单机共享列表**，不能声称是多用户个性化资讯或持仓分析。

## 2. 用户视图模型

**场景与工作（用户报告）：** 打开应用后快速知道今天 A 股市场有什么值得关注的事、哪些资讯和自选股相关，并能查看来源片段或跳转原文；在指定时间生成一份当天综述。

**首屏问题：**
1. 今日综述最近何时生成，覆盖了多少已入库资讯、数据截至何时？
2. 目前最重要/最新的市场与自选股资讯是什么？
3. 每条资讯来自哪里、原文在哪里？
4. 采集或综述是否有来源失败、限流或陈旧数据？

**页面结构：**

1. 顶部“今日资讯综述”：整体市场主线、政策/监管要点、自选股重点、风险与不确定性；每条 AI 要点可回链到支撑资讯，并显示综述时间、输入条数和采集水位。
2. 两个内容视图：“市场资讯”和“自选股资讯”。自选股视图支持按股票筛选；列表行显示标题、来源、原始发布时间、采集时间、重要性标签和来源提供的片段。原文始终可跳转；展开只展示许可的摘要/片段，不镜像全文。
3. 默认按“重要性提示 + 发布时间”排序；提供“最新优先”切换。首屏/每页建议最多显示 20 条，翻页或展开后再看其余条目；这是展示限制，不是采集或 AI 输入上限。
4. 两个独立操作：“采集资讯”“生成今日综述”。显示各自进度、上次成功时间和错误；采集失败不清空旧数据，综述失败不替换旧综述且明确过期状态。
5. 自选管理复用现有股票代码/名称补全；达到 20 只时解释上限。页面默认按“今日”浏览，可用日期范围查看仍在保留期内的内容。

**重要性提示：** 使用可解释标签，不展示黑箱 AI 分数：官方政策/监管/交易所发布、直接关联自选股、市场/行业主题等。排序在同等重要性后按**原始发布时间**倒序；“最新优先”只按原始发布时间。没有可靠发布时间的条目明确标注未知，不能用采集时间冒充。

**相关报道与去重：** 相同 canonical URL 作为同一条记录。不同 URL 的近似标题/片段不删除原记录，只在高置信度时作为“可能相关报道”收拢展示，并保留每个来源链接；不能确认独立报道时不显示“多源佐证”，也不因转载数量加权。AI 综述可按已确认的相关报道组避免重复强调，但引用仍可展开到各来源。

**证据等级：** A 股/自选股范围、调度频率、摘要和交互要求为用户已确认；接口返回字段由当前 AKShare 文档与一次公开只读请求观察；来源稳定性、转载授权、正式 rate limit 和实际官方源完整性仍是低置信度，必须先做来源准入。

## 3. 诊断

当前产品没有持续更新、可回看且与自选股关联的资讯库；新闻能力主要存在于问答的按需网页搜索路径，且 MCP `get_news_data` 已被明确禁用。聊天中的一次搜索回答不能替代“当天资讯流 + 可追溯来源 + 定时综述”：既不能保证每天持续采集，也没有页面级的持久化新鲜度与运行状态。新增页面填补的是完整用户任务缺口，而非把现有 RAG/聊天执行记录搬到新页面。

## 4. 设计原则

| 原则 | 被拒绝的方案与原因 |
| --- | --- |
| **先采集入库，再展示**：页面读取本地规范化记录，允许查历史、去重、生成有水位的综述。 | 页面每次打开实时抓取：无法可靠回看，来源故障会让页面空白，也不能证明综述输入范围。 |
| **采集与综述分开**：定时与手动采集不暗中产生模型费用；综述只消费数据库当日数据。 | 一个“更新”按钮同时做所有事：用户无法知道数据是否刷新、是否调用 AI、失败发生在哪一步。 |
| **来源和时间可见**：保存并展示发布时间、采集时间、来源、原文链接和运行状态。 | 仅给一个 AI 结论或采集时间：用户无法区分旧新闻、转载、来源故障和模型推断。 |
| **重要性提示可解释且保守**：来源类型、直接自选股关联和时效性是可见标签，不预测股价。 | 以标题数量/转载数量当成独立佐证，或输出黑箱 AI 重要性分数：样本显示相似事件会以不同 URL/媒体出现。 |
| **先满足来源条件再启用**：公开可访问不等于允许保存片段 90 天；不符合条件的源不接入或只保存其明确允许的字段。 | 把网页能抓到当成转载授权或稳定 SLA。 |
| **先展示少量、再渐进浏览**：资讯分页，默认控制视觉密度；AI 仍覆盖当天全部已入库的合格条目。 | 为了页面清爽而静默丢弃采集条目，再声称综述覆盖“全部”。 |

## 5. 信息架构与行为

### 页面与空状态

- 新增顶级导航“投资资讯”；使用项目现有浅色导航、颜色 token、系统字体和卡片/列表模式，不引入新的前端框架或风格体系。
- 空资讯库：说明尚无采集数据，展示“采集资讯”动作、来源状态和下一次计划采集时间。
- 无自选股：提示添加代码/名称；市场资讯仍可独立使用。
- 无综述：明确尚未生成，说明自动生成时间（09:00/16:00）并提供单独的“生成今日综述”操作。
- 采集中/生成中：按钮显示对应独立进度和禁用状态；另一个操作仍保持独立，不通过点击隐藏的副作用触发。
- 大量条目：服务端分页，页面默认一页最多 20 条；筛选/翻页不改变数据库和综述输入。

### 核心数据流

1. 来源适配器按来源的请求方式取市场快讯、每个自选股新闻及准入通过的官方政策/监管条目。
2. 规范化字段（时间统一解释为带时区时间，内部存 UTC，并按 `Asia/Shanghai` 切分业务日）、校验 URL scheme、清理 HTML、标准化源标识；逐来源保存成功、部分成功、限流或失败状态。
3. 以来源/规范化 URL 幂等 upsert。为重复事件建立可撤销的关联，不删掉不同来源记录；关联失败或不确定时宁可保留多条。
4. 资讯采集运行只更新新闻库和采集状态；手动采集只调用此流程。
5. 自动综述在 09:00、16:00 触发，并等待同一时点的采集完成；若当天输入指纹未变化，则跳过 AI 并保留既有成功综述。手动生成只读取截至当时已入库的上海自然日条目并强制生成，不拉取新来源。
6. 综述输入是当天**全部已入库且允许使用**的条目，而非互联网所有新闻。通过有覆盖清单的分批/分层摘要控制单次上下文；每条输入都必须出现在批次清单中，最终结构化结论带 source item 引用。展示当天输入条数、涉及来源和数据水位；超出模型能力或子批次失败时显式标为部分/失败，不能静默忽略后仍宣称完整。

### 调度、启动和并发

- 时区固定 `Asia/Shanghai`。
- 定时采集：每日 09:00、10:00、11:00、12:00、13:00、14:00、15:00、16:00。
- 定时综述：仅每日 09:00 与 16:00，且同一时点先完成采集再决定是否生成；除这两个时点外不自动调用 AI。
- 服务在 09:00–16:00 采集窗口内启动时，立即补采一次，然后继续整点计划；启动补采不触发综述。窗口外启动不额外主动采集，等下一个计划时点。使用持久化时段标识避免恰逢整点启动时重复采集。
- 手动采集与手动综述在任意时间可执行，不设应用级每日次数上限；来源本身的访问限制、网络故障或 AI 提供方限制仍可能失败，界面须如实显示。
- 同一类操作已有活动运行时再次触发，返回当前运行状态而不并行发出重复外部请求/模型费用；采集与综述可以独立提交，但写库需序列化。手动综述基于当时数据库快照；若恰逢采集运行，显示其 `data_through`，不隐式等待或发起采集。
- 项目启停脚本使用单个 Uvicorn worker。首期调度器由应用生命周期启动/停止；若未来改成多 worker/多实例，须先添加持久化 leader/lease，不能默认每个进程重复调度。

### 数据源候选与准入

**首选候选：AKShare 暴露的东方财富公开资讯接口。** 项目依赖已包含 `akshare>=1.18.40,<2`，无需新增依赖。AKShare 文档描述：

- `stock_info_global_em()`：近期约 200 条财经快讯，包含标题、摘要、发布时间、链接。2026-10-14 的一次只读调用成功返回 200 条，字段与文档相符；其中含 A 股公司公告类资讯，也可能含与 A 股无关的全球内容，必须标示来源并验证相关性过滤。
- `stock_news_em(symbol=股票代码)`：指定个股近期新闻，文档称当日最近最多 100 条，包含关键词、标题、内容片段、发布时间、文章来源、链接。2026-10-14 对 `600900` 的一次只读调用返回 10 条，字段齐全；同一公告出现了不同媒体/URL的相似报道。
- 官方文档：[AKShare 股票数据/资讯数据](https://akshare.akfamily.xyz/data/stock/stock.html)。此接口是第三方封装公开网页端数据，当前没有经核实的正式 SLA、请求配额或 90 天转载/存储授权；这不是已确认的授权结论。

**官方信息候选：** 中国证监会新闻列表、上交所“本所要闻”、深交所“本所要闻”公开页面（当前候选 URL 分别为 `https://www.csrc.gov.cn/csrc/c100028/common_list.shtml`、`https://www.sse.com.cn/aboutus/mediacenter/hotandd/`、`https://www.szse.cn/aboutus/trends/news/`）。本轮可读取部分页面条目，但未验证它们提供稳定、文档化的机器接口、可持久化的摘要字段和 90 天使用条件；CSRC 候选页的当前性也尚未确认。正式实现前逐项验证页面更新、标题/发布时间/片段/原文 URL、频率限制、robots/使用声明和存储许可。任一候选不通过就不启用/不宣称覆盖，并在页面来源状态说明缺失；不能用伪造条目或来源回退掩盖。

**不作为首期主源：GDELT。** 官方网站称数据免费开放、多语言、持续更新，但本轮 Doc API 实际请求返回 HTTP 429，且中文 A 股资讯质量未证实。参考：[GDELT Project](https://www.gdeltproject.org/)、[DOC API 说明](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)。

**外部研究限制：** 本机 `web_search` 工具因 `searchRouting.fallbackOn` 配置不是非空数组而失败；来源评估因此使用 AKShare 文档、官方页面和上述一次只读接口样本，未完成广泛的服务条款比较。来源准入是实施前阻断条件。

### 持久化与生命周期

建议新增独立 SQLite 数据库 `data/investment_news.sqlite3`，避免资讯内容与现有 `data/tasks.sqlite3` 任务执行状态混在一起；只用标准库 `sqlite3`，复用项目既有模式。逻辑实体：

- `news_items`：规范化资讯、标题、允许保存的片段、来源发布时间/采集时间、来源 URL、关联类别/代码、首次/最近采集时间、规范化 URL 键。
- `news_item_sources` / 相关资讯关系：保留重复报道的各来源链接和来源时间；来源关系不等同独立验证。
- `watchlist`：股票代码、展示名、创建/更新时间，单机共享，上限 20。
- `news_runs`：采集或生成类型、开始/结束、触发方式、状态、条数、来源明细、错误类别、输入指纹及数据水位。
- `daily_digests`：上海日期、结构化综述、生成时间、输入条数/来源清单/水位、指纹、状态和模型标识。

新闻条目与授权片段保留 90 天并清理；最少采集状态和历史综述记录保留用于解释运行与回看，最终保留字段仍服从来源条款。若来源要求更短周期/更少字段，以其规则为上限。数据库用事务、索引、幂等 upsert 和显式 schema migration；读取失败、写入失败均不得静默降级成空数据。

### AI 综述契约

- 使用项目当前配置的 AI 客户端；不逐条生成 AI 摘要，只为当天生成整体综述。
- 结构：市场主题、政策/监管、自选股要点、风险/不确定性；每个事实性要点带一条或多条来源链接/条目引用。没有证据支持的影响或因果关系写为未知/待核实；不得给买卖建议。
- 输入仅限来源许可的标题/片段和可信发布时间、来源等元数据；不抓取/持久化全文。
- 定时综述 09/16 运行时仅在输入指纹变化或当天尚无成功综述时调用 AI；手动综述为用户明确操作，即使输入未变也强制生成。内部可能因数据量分批调用模型，因此“一个综述运行”不保证恰好一次模型请求；UI显示实际运行状态/条数，不显示未测算的成本承诺。
- 任何分批/合并必须维护 item ID 覆盖清单，拒绝模型生成没有来源引用的具体新闻结论。AI 提供方失败时保留上次成功综述并标“旧”，不替换成未经验证的空/错误文本。

### 后端/前端边界建议

- 新增 `webapp/investment_news_store.py`（SQLite schema、查询、去重、保留期）、`webapp/investment_news_sources.py`（每个来源独立适配与字段规范化）、`webapp/investment_news.py`（采集/运行/综述协调）、`webapp/investment_news_scheduler.py`（Asia/Shanghai 时段与启动/关闭）。具体文件边界可在实施计划按现有模式微调，不重构无关的 `server.py`。
- `webapp/server.py` 增加资讯/自选列表读取、运行状态、手动采集、手动综述及自选增删 API；在 FastAPI startup/shutdown 生命周期启动/停止服务组件。
- `webapp/static/index.html` 增加导航和页面容器；新增 `webapp/static/investment_news.js` 管理筛选、分页、状态和展开；复用 `app.js` hash 路由和 `style.css` 设计 token，不引入 JS/CSS 依赖。

## 6. 范围与现有能力

| 桶 | 能力 | 说明 |
| --- | --- | --- |
| ✅ 已有且已暴露 | FastAPI 单页导航、股票代码/名称补全、SQLite 任务持久化、后台任务、配置的 AI 客户端、AKShare 依赖、Asia/Shanghai 时间工具 | 可复用运行时模式和公司/代码匹配；现有任务 SQLite 不是资讯领域数据库。 |
| ⚠️ 已建模但未暴露 | 无独立资讯条目、收藏列表或每日综述模型 | 新增新闻、自选股、采集运行和综述实体；需要设计数据契约、API、前端和清理策略。 |
| ❌ 当前业务未建模 | 登录账户/多用户关注列表、持仓与成本、按账户个性化影响评估、全文转载、交易指令 | 首期不做；若未来需要，需独立产品/授权/隐私设计。 |

**推荐切片：** 用户单机共享的 A 股市场/自选资讯，许可准入的免费来源，90 天新闻保存、两个每日自动综述时点、两个独立人工操作和透明错误状态。完整用户任务闭环为“发现资讯 → 看原文依据 → 检查今天总结覆盖”，不依赖登录或付费新闻供应商。

**明确不做：** 全市场全网新闻保证、来源未许可的全文/长期转载、付费源、每只股票独立 AI 分析、自动投资建议/交易信号、多账户与持仓、无界抓取或 AI 评分。

## 7. 红线

- **当前不存在用户身份；自选列表是本机单一共享数据，不得展示为个人账户列表。**
- **来源条款不允许保存的片段不得入库；“免费抓到”不等于“获准长期转载”。**
- **来源时间未知不能伪装为采集时间；旧数据/旧综述不能标为新鲜。**
- **转载和相似新闻不能被表述为独立佐证；无依据不得宣称资讯覆盖完整。**
- **资讯摘要不构成股价涨跌原因或买卖建议。**
