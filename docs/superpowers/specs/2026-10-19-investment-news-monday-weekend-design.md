# 投资资讯周一周末综述与可用日期筛选设计

## 状态

用户已确认方案；实施分支 `feat/monday-weekend-investment-summary`。

## 目标

让周一投资资讯与 AI 综述覆盖刚过去的周末，同时突出周末要点；综述日期控件只允许查看已有综述的日期。

## 已确认行为

1. 使用 Asia/Shanghai 日历日判断周一。周一综述的常规分析范围为周六至周一（含首尾）；其他日期仍仅分析该日。历史周一综述按同样规则处理。
2. 周一综述额外包含 `weekend_review` 模块，该模块仅使用周六、周日已入库资讯，并通过服务端引用白名单确保要点不引用周一内容。模块聚焦周末事实、相关影响与后续关注，不做股价因果推断或买卖建议。
3. 周一默认资讯列表范围为周六至周一；市场与自选股资讯均适用。选择“昨天”或其他显式日期窗口时仍按该窗口展示。其他日期的“今天”仍是单日。
4. 综述日期筛选由仅含已有 `daily_digests` 日期的选择框提供。默认优先今天（若已有综述），否则选最近一个已有日期；无综述时禁用选择框并显示空状态。新综述产生后刷新选项。
5. 只读本地已采集数据，不因周末数据缺失而触发补采。范围与实际输入数在页面元数据中明确展示；周末没有已采集资讯时明确显示无法分析周末。

## 技术边界

- 不改变 `daily_digests` 一日一条的存储模式；周末模块作为周一 payload 的一个 section。
- Monday 的输入指纹包括窗口边界和摘要格式版本，确保既有单日周一综述即使资讯未变也会标记过期；非周一指纹语义保持兼容。
- 新增只读 API 返回已有综述日期；继续沿用现有 JSON 安全渲染、原文链接、分页和任务调度。
- 实施测试均使用本地 SQLite、fake source、fake AI；不执行真实付费或外部采集。

## 验收

- 周一摘要覆盖周六、周日、周一，且 `weekend_review` 引用只来自周六/周日；周二仍为单日。
- 即使周末无记录，周一仍能生成其他有效综述，页面明确标示周末无数据；摘要无引用的结论不显示。
- 可用日期 API 只返回实际存储的综述日期；选择器仅列出这些日期，并在新增摘要后刷新。
- 相关单元、API、浏览器回归通过；桌面、平板、移动浏览器无页面错误、控制台错误或移动端横向溢出。
