# 智能问答可靠性第四阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Delegation is not authorized by this document; only use subagents if the operator independently authorizes it.

**Goal:** 在 P1–P3 契约上增加可复现的运行级评测，并基于实测结果优化财报检索与多轮上下文预算，而不牺牲范围、来源、证据与终态可信度。

**Architecture:** 新增独立的离线运行级 runner，使用真正的 ASGI/SSE 和隔离替身，不改变既有固定 `AnswerRun` 回放/工作台质量侧车。先产出版本化基线与逐类错误，再分别用可回退候选比较检索/消息预算；后一包未获前一包的可复现证据不得更改默认策略。

**Tech Stack:** 项目现有 Python/FastAPI/Starlette TestClient、pytest、RAG/Chroma 接口、Git、agent-browser（仅必要浏览器契约）；不提高 Python 版本要求。

**Spec:** `docs/superpowers/specs/chat-reliability-p4.md`

## Global Constraints

- 计划为**待用户确认的草案**。仅写计划不授权开发；实施前登记台账「实施中」，从本地 `main` 的 P3 交付基线创建隔离功能分支，合入 `main` 前另行确认，不推送远端。
- 所有默认单测、CI 和 runner 都使用脱敏固定输入、隔离存储及默认拒绝出站网络；漏注入模型/行情/MCP/网页/PDF 时必须失败，不连接生产账号。真实提供方探测只在单独明确授权后实施和运行。
- `webapp/chat_evaluation.py` 的固定输出回放与 `data/research_quality_summary.json`、工作台只读 API 保持不变；运行级逐题详情只写隔离路径，不提交或公开。
- 不改变 P2 冻结 Scope、来源预算、公司/时间/Fact 规则；不改变 P3 普通/研究整轮默认 120/300 秒、默认 worker 4、每轮事件缓冲 64、协作式取消及研究恢复。旧 `AnswerRun` 和旧索引不被静默重新解释。
- 质量先有证据后定阈值：先记录固定输入的基线；后续关键事实与引用支持不可下降，Scope/授权/伪造时效/错误终态属于零容忍阻断项。任何延迟/调用数取舍和定量提升目标在基线后记录、交用户确认；不得事后为候选改阈值。
- 日常验收仅聚焦本次及直接影响回归；不运行真实外网、全量测试或宽泛视觉矩阵作为默认门槛。前端如有实际改动，再按项目 UI 技能与浏览器 QA 验证。

## 文件责任图

- `webapp/chat_runtime_eval_cases.py`：版本化场景 schema 与金标准断言；**不得导入网络客户端**。
- `webapp/chat_runtime_eval_runner.py`：从已注入的 ASGI 客户端消费 SSE、重开会话/研究、观察事件及物理调用计数；与 `webapp/chat_evaluation.py` 固定回放严格分离。
- `webapp/chat_runtime_eval_report.py`：只读评分、对照与原子输出，拒绝不可比输入，不向旧侧车写入。
- `scripts/run_chat_runtime_evaluation.py`：仅手动调用离线 runner 的 CLI；`tests/fixtures/chat_runtime_eval_cases.json` 与 `tests/fixtures/chat_runtime_eval_corpus.json` 提供小规模脱敏真实位置样本。
- `tests/unit/test_chat_runtime_eval_cases.py`、`test_chat_runtime_eval_runner.py`、`test_chat_runtime_eval_report.py`：schema、执行、评分、拒绝泄露/联网与比较边界。
- `financial_report_fetcher/rag/qa.py`：统一证据窗口选择；`financial_report_fetcher/rag/chunking.py`、`ingest.py` 只在基线证实跨页定位有缺口时受控修改；已有 `reranker.py` 默认不加新模型。
- `webapp/chat_context_budget.py`：纯函数历史消息投影、token 预算和必需证据保留；`webapp/server.py`、`financial_report_fetcher/rag/qa.py` 仅接入该边界，不自行实现另一套压缩。
- `tests/browser/chat_reliability_p3_app.py`、`test_chat_reliability_p3.py`：容量饱和/研究恢复的缺口由隔离 app 真实浏览器检查；`docs/superpowers/DESIGN-REGISTRY.md`、`docs/FEATURE-CATALOG.md`、`README.md` 只在合入后记录既有能力。
