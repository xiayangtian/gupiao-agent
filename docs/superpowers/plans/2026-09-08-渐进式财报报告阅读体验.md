# 渐进式财报报告阅读体验 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将动态财报分析结果改造成精简摘要、主题目录、单列研究报告正文和可定位 PDF 页码的统一证据区。

**Architecture:** 保持后端、SSE 与分析 JSON 不变。`analysis_workflow.js` 新增纯渲染/URL 辅助函数，将结论按主题聚合为报告式 HTML 和去重证据区；`app.js` 在既有结果容器中把 PDF 页码点击转换为自定义事件，并复用当前 iframe 预览 URL 定位页码；`style.css` 仅替换分析页结果的视觉规则。

**Tech Stack:** 原生 JavaScript IIFE/DOM、CSS、pytest + Node.js 前端契约测试。

**Spec:** `docs/superpowers/specs/2026-09-08-渐进式财报报告阅读体验-design.md`

## Global Constraints

- 不改 HTTP API 路由或分析模型；允许为已有渐进式分析 JSON 的 evidence catalog 增加向后兼容的展示字段。
- 不新增 npm/Python 依赖，不引入 PDF.js。
- 颜色不能单独传达状态；风险、重点、观察、待核验均须有中文文本标签。
- 主正文与可点击文本满足至少 4.5:1 对比度；交互控件保留 `:focus-visible`。
- 证据 HTML 必须经已有 `escapeMarkup()` 转义；缺失 catalog/页码必须安全降级。
- PDF 页码只对 `pdf_text`/`ocr` 且 `source_locator.page` 为正整数的证据显示；结构化证据不能显示 PDF 跳转按钮。

- [ ] **Step 3: 实现最小纯函数与报告 HTML**

在 `analysis_workflow.js` 的 `renderEvidence`/`renderFinding` 区域以以下职责替换旧卡片渲染：

```javascript
function evidenceKind(evidence) {
  var type = String((evidence || {}).source_type || '');
  if (type === 'pdf_text' || type === 'ocr') return 'pdf';
  if (type === 'structured') return 'structured';
  return 'other';
}

function uniqueEvidenceIds(items) {
  var seen = {};
  return (items || []).reduce(function (ids, item) {
    (item.evidence_ids || []).forEach(function (id) {
      id = String(id);
      if (!seen[id]) { seen[id] = true; ids.push(id); }
    });
    return ids;
  }, []);
}

function evidencePdfPreviewUrl(selected, page) {
  var number = Number(page);
  if (!selected || !selected.code || !selected.period || !Number.isInteger(number) || number < 1) return null;
  return '/api/reports/' + encodeURIComponent(selected.code) + '/'
    + encodeURIComponent(selected.period) + '.pdf#page=' + number;
}
```

实现 `findingTone(item)`，仅返回 `{key, label}`：风险为 `{key:'risk', label:'风险'}`，`style === 'verified_risk'` 同样视为风险；`style === 'observation'` 返回观察；其他返回重点。`renderReportFinding(item, index)` 必须输出 `<article class="analysis-report-finding analysis-tone-...">`，含 `<span class="analysis-finding-label">`、`claim`、可选 `key_data`/`significance` 和 `<a href="#analysis-evidence">引用证据 N</a>`；不调用 `renderEvidence`。

实现 `renderEvidenceSection(items, catalog)`：先通过 `uniqueEvidenceIds` 去重，忽略缺失 catalog 的 id；输出 `<section id="analysis-evidence" class="analysis-evidence-section">`。对 PDF/OCR 且正页码输出：

- [ ] **Step 3: 集成事件委托与 iframe 更新**

将 `evidencePdfPreviewUrl` 加到 `analysis_workflow.js` 的 return object。

在 `app.js` 的 `bindProgressiveTabs` click listener 开头，先处理页码按钮，再处理 Tab：

```javascript
var evidenceButton = event.target && event.target.closest
  ? event.target.closest('[data-evidence-page]') : null;
if (evidenceButton) {
  var page = Number(evidenceButton.dataset.evidencePage);
  container.dispatchEvent(new CustomEvent('analysis:evidence-page', {
    bubbles: true, detail: { page: page }
  }));
  return;
}
```

在 `bindProgressiveTabs` 之后定义一次性的 `document.addEventListener('analysis:evidence-page', ...)`：

```javascript
function openEvidencePdfPage(event) {
  var selected = STATE.selected && STATE.selectedReport ? {
    code: STATE.selected.code, period: STATE.selectedReport.period
  } : null;
  var url = window.AnalysisWorkflow.evidencePdfPreviewUrl(selected, event.detail && event.detail.page);
  var frame = $('#pdf-frame');
  if (!url || !frame) return;
  frame.src = url;
  var preview = document.querySelector('.preview-panel');
  if (preview && preview.scrollIntoView) preview.scrollIntoView({block: 'nearest', behavior: 'smooth'});
  if (frame.focus) frame.focus();
}
document.addEventListener('analysis:evidence-page', openEvidencePdfPage);
```

不要在该监听器中下载、查询或更改 `STATE.selectedReport`；当前报告未选中时静默返回。
