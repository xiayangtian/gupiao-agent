# 智能问答财报补充下载 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在单公司智能问答缺少必要本地财报证据时，经用户勾选授权下载最多 5 份 PDF、摄取后恢复同一问题的回答。

**Architecture:** 新建 `webapp/chat_supplement.py`，承载候选解析、一次性授权状态机和下载/摄取编排；`RagQA` 将受控 `request_missing_reports` 工具调用转换为暂停事件，绝不直接下载。`server.py` 持久化补充请求并提供恢复 SSE 端点，前端在现有聊天流中渲染授权卡、进度与恢复回答。

**Tech Stack:** Python 3.12、FastAPI、Pydantic、dataclasses、现有 CNINFO 数据源、`ReportDownloader`、`IngestionService`、原生 JavaScript、pytest、agent-browser。

**Spec:** `docs/superpowers/specs/2026-09-14-智能问答财报补充下载-design.md`

## Global Constraints

- 未经授权，任何问答路径不得调用 `ReportDownloader.download_one()`。
- 仅 `company_only` 的单一目标公司 Scope 可提出补充；`company_industry` 和 `whole_corpus` 必须按现有证据回答，不自动下载。
- 每个 `supplement_id` 最多包含和批准 5 份候选；重复、过期、跨会话、篡改和已消费请求不得下载。
- 候选只能由后端从受控 `ReportMeta` 解析；模型不能提供 URL、文件路径、股票代码或绕过 Scope。
- 下载成功后必须先完成 PDF 摄取，成功摄取的 `report_id` 才可进入恢复回答。
- 拒绝或全部失败必须产生诚实终结回答，不自动重试或下载。
- 不新增第三方依赖；不自动分析 PDF；不记录下载 URL、异常堆栈或模型原始参数到历史会话。
- 前端授权卡必须默认不选、键盘可操作、使用语义化控件、`aria-live` 进度，并在移动端无横向溢出。
- 每个任务先写失败测试、确认失败、最小实现、确认通过并提交。
