# 分析主题 Tab 优先级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以短标签、可访问的重要度标记和稳定排序提升分析结果动态主题 Tab 的可读性，同时保留完整主题信息。

**Architecture:** Planner 可选地产出短标签并随 section 持久化；所有报告的最终标签、分数、重要度和排序均在前端用纯函数统一计算，以兼容没有新字段的历史文档。主题正文新增完整标题和导语，Tab 仅承载紧凑导航信息。

**Tech Stack:** Python dataclasses、FastAPI 分析管线、原生 JavaScript UMD 模块、CSS、pytest、Node、agent-browser。

**Spec:** `docs/superpowers/specs/2026-09-10-分析主题Tab优先级-design.md`

## Global Constraints

- 仅处理动态主题 Tab；不改分析文件命名/迁移，也不改“待核验”标签。
- 新报告 `tab_label` 最多 6 个汉字，不含编号与标点；字段可选，v3 历史文档缺失字段必须兼容，绝不触发重分析或 AI 请求。
- Tab 标签优先用合法 `tab_label`，再关键词回退，最后用标题首分句前 6 字加省略号；完整标题必须保留在 `title`、`aria-label` 和正文 H3。
- 重要度按 section score 有限数值和相对分档（`>= max-3` 高，`>= max-8` 中，其余一般/无分数）；显示“高/中/常”文本与颜色，不额外标记风险。
- 每次前端渲染复制后排序：总分降序、发现数降序、`section_id` 升序；active tab 用 `section_id` 保持，无效时回退快速结论。
- Tab 触控高度至少 44px；键盘焦点可见；桌面、平板、手机无横向溢出；文本对比度至少 4.5:1，语义不能只靠颜色。
- 不引入新依赖，不修改无关页面或既有报告文件。
