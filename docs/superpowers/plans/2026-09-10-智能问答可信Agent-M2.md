# 智能问答可信 Agent M2 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 M1 的 Scope、AnswerRun 与 Artifact 底座上，实现受控意图路由、工具策略、事实归一、冲突识别和论断核验，让模型不能绕过范围和证据直接输出确定性财务结论。

**Architecture:** M2 将“问题分类→允许来源/工具→结构化事实→论断核验”拆为独立模块。`IntentRouter` 只输出受限意图 JSON；`ToolPolicy` 从意图和 Scope 生成可调用工具与预算；`FactNormalizer` 将受控来源转换为可比较 Fact；`ClaimVerifier` 对最终回答和 Fact/Evidence 进行范围、口径、时间与引用覆盖校验。`RagQA` 仍负责生成，但只接收已冻结 Scope、已批准工具和受控事实摘要。

**Tech Stack:** Python 3.12、dataclasses、Pydantic、FastAPI、ChromaDB、现有 RAG/MCP/Tavily、pytest、Node.js、agent-browser。

**Spec:** `docs/superpowers/specs/2026-09-10-智能问答可信Agent升级-design.md`

## Preconditions

- M1 已上线且 `webapp.chat_models.Scope/Fact/EvidenceArtifact/ToolArtifact/AnswerRun`、`webapp.chat_scope.ScopeResolver`、`webapp.chat_evidence.EvidenceNormalizer` 可用。
- M1 全量测试、浏览器可信范围/证据闭环验收已通过。
- M2 不实现 ResearchPlan、恢复步骤或研究工作台；这些由 M3/M4 负责。

## Global Constraints

- 所有检索必须先应用 M1 Scope；M2 不得创建任何绕过 Scope 的查询或工具调用。
- 意图只能是 `report_fact/company_trend/industry_benchmark/realtime_market/event_attribution/research_task`；无效模型 JSON 回退为保守 `report_fact`，禁用外部工具。
- 外部工具只有在 `realtime_market` 或 `event_attribution` 的批准策略下可运行；行业比较不得用网页/实时数据替代本地可比财报。
- `Fact.verification == verified` 仅允许 PDF 可定位证据，或有 provider/as_of/完整口径的受控结构化外部数据；网页新闻最多为 `reference`。
- 不能确定单季/累计、合并/母公司、单位、币种、期间或公司时，Fact 不得参与计算、排名或确定性结论。
- 冲突不得由模型静默选择；必须以 `FactConflict` 返回并在最终回答中呈现来源与差异。
- M2 只保留用户可理解的业务动作和来源，不向 UI 暴露向量距离、内部提示词或模型推理链。
- 不新增第三方依赖；沿用 M1 AnswerRun 的 schema v2，新增字段必须向后兼容。

## M2 Completion Definition

1. 每次问答都有持久化 IntentDecision、ToolPolicy、facts/conflicts/VerificationReport；
2. Scope 外证据、无支持数字和未披露冲突不能进入确定性最终结论；
3. PDF 财务事实与外部实时/网页参考有清晰来源边界；
4. 不需要实时数据的财报问题不调用外部工具；
5. 行业比较只使用本地可检索同业样本并明确样本边界；
6. 全量 pytest、评测 fixture、浏览器测试和真实浏览器 QA 均通过；
7. 代码评审无 P0/P1；M3 Planner 和 M4 工作台不提前进入 M2。
