# 智能问答可靠性第三阶段实施计划

> **For agentic workers:** 使用 `superpowers:executing-plans` 按任务执行，并应用 `superpowers:test-driven-development`。步骤用 checkbox 跟踪。

**Goal:** 让智能问答规划和整轮执行不阻塞 ASGI，提供有界 SSE 进度/取消/超时，并稳定路由明确研究请求到 ResearchAgent。

**Architecture:** 每轮聊天由有界专用 worker 执行；线程安全运行控制和有界事件 channel 将同步模型/来源调用转为可观察的异步 SSE。取消、断开和 deadline 共用协作式取消事件，所有来源调用前检查；研究路由由服务端明确用户意图决定，不由普通执行计划成功/失败反向决定。

**Tech Stack:** Python 3.12、FastAPI/Starlette、`threading`、`concurrent.futures`、asyncio、pytest/TestClient、现有 agent-browser。

**Spec:** `docs/superpowers/specs/chat-reliability-p3.md`

## Global Constraints

- 普通问答超时默认 120 秒；研究任务超时默认 300 秒；worker 最大并发默认 4；每轮 SSE 缓冲最大 64 个事件。
- 仅显式研究意图进入 ResearchAgent；普通请求不自动升级；模型计划不能扩权或改动 P2 来源预算。
- 在途阻塞调用不可强杀；取消后等待现有单调用超时，且禁止再发起来源调用。
- 固定 fixture 替代真实模型、外网、MCP、腾讯行情和生产账号；不推送；合并 `main` 需另行授权。
- 已完成的研究步骤和来源证据不可因取消/恢复丢弃或重复执行。

**Interfaces:**
- `ChatRunControl(session_id: str, run_id: str, timeout_seconds: float, started_at: float | None = None)`：持有线程安全取消事件与单调时钟 deadline；提供 `cancel(reason: str) -> bool`、`cancelled`、`remaining_seconds()`、`check_active() -> None`。
- `ChatEventChannel(maxsize: int = 64)`：线程 producer `publish(event: dict, control: ChatRunControl) -> bool`；async consumer `receive(timeout: float = 0.1) -> dict | None`；`close()` 唤醒所有等待者并拒绝新事件。`None` 表示超时轮询或已关闭且排空。
- `ChatRunRegistry(max_workers: int = 4)`：`start(control, target)` 在空位时提交并返回 `Future`，无空位返回 false；`cancel(session_id, run_id)` 仅取消匹配活动运行；`finish(run_id)` 释放 slot 并删注册；`active_count` 供测试/健康诊断使用。

- 所有 source runtime call 在执行前调用 control 检查；每次同步在途调用返回后也检查，取消则结束步骤链。
- worker slot、run registry、channel 在所有终态/异常/断开路径 finally 释放；繁忙时发送可读 503/429，不排队。

## 完成定义

- 首个 SSE 身份事件先于所有慢速规划；事件循环在 planner/source 阻塞时仍能服务其他请求。
- 有界 worker/event channel 有可验证并发上限和背压，任何成功/失败/停止/断开/超时路径均释放容量。
- stop/disconnect/deadline 共用取消语义，在途来源按其既有超时收敛，且不会继续发起下一次来源请求。
- 研究只由显式用户研究意图触发；正常研究计划成功执行 ResearchAgent；恢复不重做已完成步骤；普通问题不会自动升级。
- P2 授权/范围/预算/数字事实契约保持；聚焦回归及隔离浏览器验收通过，`git diff --check` 通过。
- 仅在用户另行授权后合入本地 `main`；不推送远端。
