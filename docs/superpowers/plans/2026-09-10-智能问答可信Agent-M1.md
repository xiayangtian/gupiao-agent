# 智能问答可信 Agent M1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将智能问答首期升级为范围可控、证据可持久化、PDF 可跳页、停止状态可恢复的可信回答系统。

**Architecture:** 在现有 RAG/MCP/SSE 框架上引入 `Scope`、`Fact`、`EvidenceArtifact`、`ToolArtifact` 和 `AnswerRun`。服务器在流式开始前解析并冻结 Scope，RAG 仅查询 Scope 允许的 `report_id`；流式结束后将回答、范围、来源、工具轨迹与状态持久化到会话 schema v2。前端使用持久化产物渲染范围、证据和状态，而不是仅消费本次 SSE 的临时字段。

**Tech Stack:** Python 3.12、FastAPI、Pydantic、dataclasses、ChromaDB、现有 RAG/MCP/Tavily、原生 JavaScript、pytest、Node.js、agent-browser。

**Spec:** `docs/superpowers/specs/2026-09-10-智能问答可信Agent升级-design.md`

## Global Constraints

- `company_only` 是硬检索边界；不得以“召回不足”为由混入其他公司或其他报告期。
- 默认单公司问题为 `company_only`；只有问题明确涉及行业、同业、竞争、排名或对比时才解析为 `company_industry`。
- M1 的行业范围仅限“本地 RAG 已索引、且与目标公司具有同一数据源行业分类”的公司；界面必须写明“本地可检索同业样本”，不得将其表述为全市场排名。
- 行业分类无法可靠取得时必须回退 `company_only`，并在回答范围中显示回退原因。
- 财报数字只能以本地 PDF（或同一报告的可定位结构化 PDF 事实）作为确定性证据；网页/MCP 不能替代财报披露。
- 外部网页/工具事实必须有来源与 `as_of`；缺失任一项不得进入 `AnswerRun.facts` 的 `verified` 状态。M1 对无法解析为受控结构的外部工具文本只保存为 `reference` artifact，不自动抽取为 Fact；M2 的 `FactNormalizer/ClaimVerifier` 才负责完整数值归一与论断覆盖。
- PDF 页码链接必须指向 `/api/history-pdf/<pdf_filename>?jump=<timestamp>#page=<N>`；文件或页码不可用时不得生成链接。
- 新会话 schema 为 v2；旧会话可读但必须标识 `legacy_evidence_unavailable`，不得伪装成有证据包的回答。
- 一般结论不显示“待核验”兜底标签；短结论保持左对齐连续段落。证据、范围和运行状态只在确有信息时渲染。
- 用户停止生成时必须持久化 `stopped` 状态、已完成 artifact 与部分文本；不得将其标为 `completed`。
- 不新增第三方依赖；缓存文件位于 `data/` 且必须加入 `.gitignore`。
- 每个任务采用 TDD：先写失败测试、确认失败、最小实现、确认通过、单独提交。

class Scope:
    mode: ScopeMode
    companies: tuple[CompanyRef, ...]
    report_ids: tuple[str, ...]
    industry: IndustryRef | None = None
    source_policy: SourcePolicy = SourcePolicy.local_only()
    fallback_reason: str = ""
