# 可信问答 M4 P2 修补实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 M4 遗留 P2：工作台即时一致性、离线质量观测、健康/负向评测分组、稳定 Fact ID 以及统一后端证据身份规则。

**Architecture:** 以 `Fact.id` 作为新事实的稳定保存身份，并将 PDF/网页身份判断收敛到 `webapp/evidence_identity.py`。质量评测保留固定 fixture 回放，但按 `health` 与 `probe` 两个套件独立汇总，由显式脚本原子写入安全摘要；Web 只读摘要并呈现状态。工作台的保存/撤销动作复用现有加载函数以即时同步行文案。

**Tech Stack:** Python 3.12、dataclasses、hashlib、JSON、FastAPI、原生 JavaScript、pytest、agent-browser；不新增第三方依赖。

**Spec:** `docs/superpowers/specs/2026-09-17-可信问答M4-P2修补-design.md`

## Global Constraints

- 不修改 M1–M4 已持久化的 AnswerRun/ResearchRun 内容，不为旧 Fact 伪造 ID；旧 Fact 可展示/导出但不得保存为研究记忆。
- `company_only`、Scope、ToolPolicy、run/session owner 检查、事实核验与不可变证据语义不得扩权或弱化。
- 评测只回放版本化固定 fixture；不得调用真实 AI、MCP、网页、生产数据或在服务启动/API 请求中执行评测。
- 质量摘要只含 schema version、生成时间、health/probe 聚合、枚举 failure code 计数；不得含问题、prompt、完整外部正文、推理链或逐用例文本。
- 保存/撤销决策后的工作台刷新必须沿用既有 request-generation 保护，不能让过期响应覆盖当前筛选。
- 不实现自动交易、主动监控、推送或未经确认的投资建议。
- `data/research_quality_summary.json` 保持 `.gitignore` 忽略；摘要命令失败不得覆盖有效旧文件。

## Completion Definition

1. 决策保存/撤销后，已打开工作台立即显示最新决策摘要；
2. 新 Fact ID 稳定、同页多 Fact 可独立保存，旧 Fact 不可保存但可读/可导出；
3. 记忆、导出、评测使用同一后端证据身份规则；
4. 显式质量命令只回放 fixture、原子更新摘要且失败不覆盖旧结果；
5. health 与 probe 分开观测，probe 不污染 health 状态；
6. Web 仅显示安全聚合质量状态，未生成摘要时诚实降级；
7. 全量、质量命令、API、JS、浏览器和三视口验收通过；
8. 无 P0/P1、无 Scope/owner 扩权、无自动交易/主动监控/推送。
