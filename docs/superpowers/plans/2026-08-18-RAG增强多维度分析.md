**Goal:** 把 `ReportAnalyzer.analyze()` 的上下文来源从截断全文改为"按维度 RAG 定向检索"，并扩展分析维度模板 + 前端勾选面板。

**Tech Stack:** Python 3、已有 rag 包（store/ingest/config/qa）、FastAPI、原生 JS 前端。

**Spec:** `docs/superpowers/specs/2026-08-18-RAG增强多维度分析设计.md`

### Task 1: rag/analysis.py — 按维度检索与上下文组装

**Files:** Create `financial_report_fetcher/rag/analysis.py`; Test `tests/unit/test_rag_analysis.py`

**Interfaces:**
- `RagAnalysis.__init__(store: RagStore, top_k: int = 8)`
- `RagAnalysis.build_context(report_id: str, dimension: str, queries: List[str], sections: Optional[List[str]] = None, top_k: Optional[int] = None) -> str`
  - 对每个 query 调 `store.query(query, top_k=top_k, where={"report_id": report_id})`；sections 非空时按 metadata.section 过滤（模糊包含匹配，大小写不敏感）；
  - 合并去重（按 chunk id）；指标摘要（section 含「指标」或等于「指标摘要」）在 queries 里显式传即可命中；
  - 组装 `[n] 章节（页码）: 片段` 文本；空结果返回空字符串。
- `build_context` 内单路检索异常捕获（记日志、跳过该路），不影响其他路。

**TDD 要点：**
- fake store（或真实 RagStore + fake_embedder）注入；断言合并去重、section 过滤、空结果、异常容错。
- 至少：多路合并去重、section 过滤命中/不命中、无结果返回空串、单路异常不中断。

**Commit:** `feat(rag): add dimension-based retrieval context builder`
