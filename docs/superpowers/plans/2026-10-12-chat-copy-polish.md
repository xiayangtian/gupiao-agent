# 智能问答对话链路文案优化实施计划

## 范围与约束

按 `docs/superpowers/specs/2026-10-12-chat-copy-polish.md` 优化智能问答对话链路内文案。不改业务行为、事件/API 契约、状态机或安全边界；不触及其他页面。

## 步骤

1. **盘点并归类**：检索 SSE 阶段消息、对话 DOM 渲染、授权卡片、来源/核验说明、失败/终态及操作按钮。筛除日志、内部诊断和非对话页面内容。
2. **先写回归断言**：为代表性文案及按钮文字增加/调整单测与浏览器断言，确认既有状态与授权行为保持一致。
3. **统一文案**：优先采用面向用户的状态描述；避免内部术语与工具名；失败时说明可行下一步。保留来源、数据时点、部分结果、核验与反馈标识的事实边界。
4. **聚焦验证**：运行对话文案相关单测、授权/证据/恢复相关浏览器回归及 `git diff --check`。若因 copy 更新导致断言失败，更新断言并核实业务动作未变。
5. **交付记录**：记录分支、验证结果、合入证据；只在验证通过且按授权合入 `main` 后更新设计台账为已实现。不得推送远端。

## 验收

- 用户可见文案仅在已确认的智能问答范围内变更；保持状态准确、来源可信、操作含义明确。
- 测试不执行真实外部数据源、报告下载或生产账号操作。
- 相关测试及差异检查全部通过；汇报实际测试范围与任何遗留问题。
