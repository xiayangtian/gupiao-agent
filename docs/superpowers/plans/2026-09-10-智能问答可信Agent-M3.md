# 智能问答可信 Agent M3 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为复杂研究问题提供可见计划、可持久化步骤、可恢复执行和独立核验，使“研究任务”不再退化成一次不可解释的长回答。

**Architecture:** M3 在 M1/M2 的 Scope、ToolPolicy、Fact、FactConflict 和 VerificationReport 上构建单运行、分角色的状态机，而不是引入自由协作多 Agent。Planner 生成受限 `ResearchPlan`；Executor 按步骤执行已有 RAG/工具策略；Verifier 重用 M2 核验器并确认计划验收条件；每一步输出 `ResearchStepRun`，完整 `ResearchRun` 作为 AnswerRun 的扩展持久化。服务通过 SSE 转发状态，前端仅在复杂任务显示计划与步骤。

**Tech Stack:** Python 3.12、dataclasses、FastAPI、现有 TaskManager/SSE、RAG/MCP、原生 JavaScript、pytest、agent-browser。

**Spec:** `docs/superpowers/specs/2026-09-10-智能问答可信Agent升级-design.md`

## Preconditions

- M1 和 M2 已上线并通过 Scope、Artifact、Fact、ToolPolicy、ClaimVerifier 的测试与浏览器验收。
- `research_task` 已由 M2 IntentRouter 识别，但尚未执行复杂计划。
- M3 不实现跨会话筛选、收藏、导出与长期研究记忆；这些由 M4 负责。

## Global Constraints

- 简单 `report_fact/company_trend/industry_benchmark/realtime_market/event_attribution` 不创建冗长 ResearchPlan；仅 `research_task` 或用户显式“制定研究计划”启用 M3。
- Planner 输出必须是受限 JSON；无效 JSON 或超出 Scope 的计划回退为单步安全回答，绝不扩大公司、行业或外部来源边界。
- 步骤只能使用 M2 ToolPolicy 允许的来源与工具；Planner 无权授权新工具。
- 每一步都必须保存输入摘要、状态、artifact/fact/conflict/verification 和时间；不可恢复的模型内部推理不得持久化或展示。
- `stopped` 不是 `completed`；恢复只能重用完成步骤的产物，重跑失败/未完成步骤；不得重复执行仍有效的外部调用。
- 独立的本地检索可以并行；涉及同一事实集合的归一、比较、核验和最终回答必须按依赖顺序执行。
- 用户只能看到业务化步骤名称、进度、证据数量、阻塞原因和结果，不显示推理链、内部提示词、向量距离或原始密钥参数。
- 不新增第三方依赖；复用现有 TaskManager，但不得让长研究阻塞普通聊天 SSE。

## M3 Completion Definition

1. 复杂研究任务生成并持久化受限计划、步骤、验收条件和状态；
2. Scope/ToolPolicy 不会被 Planner 或恢复流程扩大；
3. 停止/失败后只恢复未完成步骤，已完成工具与事实不重复调用；
4. Verifier 不通过时研究不得标记 completed；
5. 简单问题仍走 M2 普通流，不展示冗长计划；
6. 跨重启历史会话可查看步骤和恢复资格；
7. 单元、API、浏览器、全量测试和真实浏览器验收通过；
8. 代码评审无 P0/P1，M4 的收藏/导出/长期记忆不提前耦合。
