# Dynamic Evidence-Based Financial Report Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前基于固定模板和整份 PDF 截断文本的财报分析，改造为可追溯证据、动态主题、快速结论先行、深度结果渐进推送的 A 股财报分析流程。

**Architecture:** 新增独立证据层，并行读取结构化财务数据与 PDF 原生文本，对低质量页面按需 OCR，再经主体、期间、单位和来源冲突解析后交给分析管线。管线先产出独立快速结论，再发现、评分、过滤并逐个持久化深度主题；任务事件通过 SQLite 和 SSE 断线续传，前端用同一状态归并器保持财报页与历史页联动。

**Tech Stack:** Python 3.10+、FastAPI、Pydantic、SQLite、pypdf、AKShare、requests、可选 PaddleOCR PP-StructureV3、原生 JavaScript、EventSource/SSE、pytest、Node.js 前端单测。

**Spec:** `docs/superpowers/specs/2026-09-01-动态证据化财报分析-design.md`

## Global Constraints

- PDF 是最终法定披露依据；结构化数据是数值主入口，OCR 只是按需补充，不得用低置信 OCR 覆盖 PDF 或结构化事实。
- 任何确定性数字结论必须绑定 `report_id`、`entity_scope`、`period`、`unit`、`source_locator` 和 `verification_state`。
- 合并、母公司和主体未知数据不得混算；`unknown` 主体不得参与跨期比率和合计。
- 主题评分权重固定为 30/25/20/15/10；`>=75` 生成详细 Tab，`60–74` 只能进入“待验证观察”，`<60` 不展示。
- 快速结论固定第一个 Tab，最多 3 条；详细主题最多 6 个，每个 3–5 条发现，空章节、空表格和纯“未披露”内容不渲染。
- 特殊样式不超过正文约 20%，每条发现通常只强调 1–2 处；红色只用于已验证的风险、恶化或异常。
- 内部质量分仅用于过滤和排序，不得以精确分数呈现给用户，也不得表述为投资评级。
- 新任务状态为 `queued → fast_processing → fast_ready → deep_processing → completed|partial|failed|cancelled`；`fast_ready` 必须是已可消费结果。
- SSE 事件必须有单调递增 ID，支持 `Last-Event-ID` 补发；SSE 不可用时回退到任务快照轮询。
- 旧版分析 JSON/Markdown 必须继续可读；重新分析生成 `schema_version = 3` 的新结构。
- 缓存命中且选择 1–2 个关注方向时，快速结论目标约 30 秒；主要详细结果目标约 90 秒，实施后记录冷/热缓存 P50/P95。
- 本计划不引入交易建议、买卖评级、自动交易、付费数据采购或云端 OCR。

class StructuredDataProvider(Protocol):
    name: str
    def fetch(self, company_code: str, period: str, report_id: str) -> list[EvidenceRecord]: ...

@dataclass(frozen=True)
class StructuredFetchResult:
    records: list[EvidenceRecord]
    providers_used: list[str]
    failures: dict[str, str]

class StructuredDataGateway:
    def __init__(self, providers: Sequence[StructuredDataProvider]):
        self.providers = tuple(providers)

    def fetch(self, company_code: str, period: str, report_id: str) -> StructuredFetchResult:
        records: list[EvidenceRecord] = []
        providers_used: list[str] = []
        failures: dict[str, str] = {}
        for provider in self.providers:
            try:
                fetched = provider.fetch(company_code, period, report_id)
            except Exception as exc:
                failures[provider.name] = f"{type(exc).__name__}: {exc}"
                continue
            if fetched:
                records.extend(fetched)
                providers_used.append(provider.name)
        return StructuredFetchResult(records, providers_used, failures)
```

@dataclass(frozen=True)
class DocumentPage:
    page_number: int
    text: str
    char_count: int
    abnormal_char_ratio: float
    table_alignment_score: float
    visual_area_ratio: float
    quality_score: float
    needs_ocr: bool

def score_page(page_number: int, text: str, visual_area_ratio: float, min_chars: int) -> DocumentPage:
    char_count = len(text.strip())
    abnormal = sum(ch == "\ufffd" or unicodedata.category(ch) == "Cc" for ch in text)
    abnormal_ratio = abnormal / max(len(text), 1)
    quality = max(0.0, min(1.0, 0.55 * min(char_count / max(min_chars, 1), 1.0)
                           + 0.30 * (1.0 - abnormal_ratio)
                           + 0.15 * (1.0 - visual_area_ratio)))
    needs_ocr = char_count < min_chars or abnormal_ratio > 0.08 or visual_area_ratio > 0.70
    return DocumentPage(page_number, text, char_count, abnormal_ratio, 0.0,
                        visual_area_ratio, quality, needs_ocr)

@dataclass(frozen=True)
class DocumentExtraction:
    report_id: str
    pdf_hash: str
    pages: tuple[DocumentPage, ...]
    parser_version: str = "pypdf-page-v1"
```

`DocumentExtractor` 使用 `pypdf.PdfReader`、页号从 1 开始、计算 PDF SHA-256，不再截断 15000 字符。

```python
EventEmitter = Callable[[str, dict[str, Any]], None]

class ProgressiveAnalysisPipeline:
    def run(self, request: AnalysisPipelineRequest, emit: EventEmitter, stop_event: Event) -> AnalysisDocument:
        emit("job.stage_changed", {"stage": "fast_processing"})
        structured_future = self.quick_executor.submit(
            self.structured_gateway.fetch, request.company_code, request.period, request.report_id)
        document_future = self.quick_executor.submit(
            self.document_extractor.extract, request.pdf_path, request.report_id)
        structured = structured_future.result()
        extracted = document_future.result()
        resolved = self.resolver.resolve([*structured.records, *self.pdf_records(extracted)])
        quick = self.quick_analyzer.analyze(resolved.records, request.interests)
        document = self.new_document(request, quick, resolved)
        self.save(document)
        emit("job.stage_changed", {"stage": "fast_ready"})
        emit("quick.ready", {"quick": document.quick.to_dict()})
        emit("job.stage_changed", {"stage": "deep_processing"})
        ocr_pages = [page.page_number for page in extracted.pages if page.needs_ocr]
        ocr_future = self.ocr_executor.submit(
            self.enrich_ocr, request, ocr_pages, emit, stop_event)
        candidates = self.insight_planner.plan(resolved.records, request.interests)
        ranked = self.rank_candidates(candidates, resolved.records, request.interests)
        self.analyze_ranked_sections(document, ranked, emit, stop_event)
        self.merge_ocr_result(document, ocr_future.result(), emit)
        document.stage = self.terminal_stage(document)
        self.save(document)
        emit(f"job.{document.stage}", {"analysis": document.to_dict()})
        return document
```

管线分别使用 `quick_io_workers=2`、`deep_workers=2`、`ocr_workers=1` 的有界 executor：用户关注的 1–2 个方向先进入 deep 队列，OCR 不能占用 quick executor。事件名固定为 `job.stage_changed`、`quick.ready`、`extraction.page_started`、`extraction.page_completed`、`theme.started`、`theme.filtered`、`section.ready`、`section.updated`、`quick.corrected`、`job.completed`、`job.partial`、`job.failed`；取消额外发布 `job.cancelled`。如新证据推翻快速结论，不覆盖原值：写入 `QuickCorrection(before, after, reason, evidence_ids)` 并发布 `quick.corrected`。取消时保留已生成 quick/sections 并以 `cancelled` 结束。
