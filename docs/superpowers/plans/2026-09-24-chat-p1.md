> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. 默认由当前会话直接执行；未经用户另行授权不调用子代理。

**Goal:** 将智能问答的来源执行、实际调用预算、证据归一及最终状态贯通，消除重复取数、证据丢失和失败冒充完成。

**Architecture:** 新增运行级 SourceRuntime，provider 适配层负责受控输入、结果解析和时间归一，执行计划及兼容工具循环共用同一运行实例。已验证计划先取得 AnswerContext，再由 RagQA 基于上下文生成，禁止第二次自主外部查询。统一来源结果投影到 SSE、AnswerRun 和前端，保留旧历史与补报/研究恢复契约。

**Tech Stack:** 现有 Python、dataclasses、FastAPI/SSE、pytest、原生 JavaScript 和 agent-browser；不新增第三方依赖。

**Spec:** `docs/superpowers/specs/2026-09-24-chat-reliability.md`（第一阶段；用户于 2026-09-24 确认详细设计）。

## 关键实现决策

### 调用计数口径

外部数据预算计量应用层实际发出的 MCP call_tool、腾讯 HTTP 数据请求、网页搜索请求，包括应用自己发起的重试，不声称能够计数第三方 MCP 进程内部的 HTTP 请求。list_tools 为能力发现，不当作市场数据；按一次有限超时探测缓存，探测失败不得回退成可用权限。冻结 Scope 前的既有身份/行业解析保持原行为，不与回答数据预算混淆，后续优化见第二阶段。

### 兼容边界

- `RagQA.answer_stream` 增加可选、仅服务端注入的 `source_runtime`，不改变无该参数的旧同步/CLI 调用默认行为。
- 三个 Web 流入口（普通/研究恢复/补报恢复）均显式传入；禁止修改共享 RagQA 实例的 executor 来实现每轮隔离。
- 补报确认恢复和研究恢复是新的 AnswerRun，可拥有新预算，但旧已完成研究步骤只复用持久化产物，不得重新执行。补报恢复仍不得再次申请补报授权。
- 保留旧 SSE 事件与字段。新来源结果事件是内部结构化输入，对外仅投影安全的 artifact/tool_result/执行摘要；原始内容不直接进入 SSE。

### 结果状态与生成规则

来源内部状态：success/partial/failed/unavailable；依赖未满足的执行步骤为 skipped。仅有可用行的部分成功可供生成使用，缺少 as_of 的市场行标为 partial。失败和不可用均携带安全错误码，不把异常原文交给模型。

required 步骤不是 success 时，生成确定性限制说明而不是调用模型编造关键结论；保留已取得来源供用户查阅。optional 步骤失败时允许依据剩余证据生成，但最终状态为 partial。answer 在取数阶段为 pending，生成和核验完成后才结束；blocked/partial 核验不能对应 completed。

## 风险与停止条件

1. 某 provider 无法可靠识别数据字段：记录为 unsupported_payload/partial，不假造成功。若因此无法实现已确认验收，暂停并报告，不扩大范围接入新 provider。
2. 新状态与旧 Fact/ToolArtifact 合约矛盾：保留旧 success 要求，未知数据时间使用 partial；不得为了测试通过补造时间。
3. 一个 handler 内多个请求无法经运行服务计数：拆到适配层逐次调用，不把聚合预算记成一次；第三方进程内部请求数不可观测，必须披露计数口径。
4. 发现必须改 Scope 或研究路由才能继续：暂停说明依赖，不把第二、三阶段悄悄并入第一阶段。
5. 基线直接相关测试失败：先定位基线/新回归，再决定修复，禁止把失败测试删除或改成无断言。
