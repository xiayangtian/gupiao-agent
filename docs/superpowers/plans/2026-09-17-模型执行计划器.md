# 模型执行计划器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让所有智能问答先由模型生成并经服务端验证的执行计划，按计划决定 RAG、行情 MCP、网页搜索和最终分析通路。

**Architecture:** 在冻结 `Scope` 后，以问题和能力快照请求轻量 JSON 计划；新校验器将计划约束在 Scope、工具白名单、预算及有限步骤图内。执行器按校验通过的步骤确定性运行检索与外部工具，最后将规范化产物交给现有回答模型；复杂计划才桥接至现有 `ResearchPlan`。

**Tech Stack:** Python 3.12、FastAPI/SSE、dataclasses、现有 `AIClient`、`RagQA`、MCP 与 Tavily 网页搜索。

**Spec:** `docs/superpowers/specs/2026-09-17-模型执行计划器-design.md`

## Global Constraints

- 模型计划不得改变已冻结 `Scope`，不得输出公司代码、URL、工具名或原始工具参数。
- 只有服务端能力快照、工具白名单、次数/轮数/30 秒超时可授权实际调用。
- 计划、步骤状态和来源摘要可持久化；推理、prompt、原始 JSON/参数和向量距离禁止持久化或发 SSE。
- 普通计划最多 4 步，必须以 `answer` 结束；复杂计划才进入既有 M3 `ResearchPlan`。
- 计划无效或模型不可用时 fail-closed，使用保守本地证据路径或诚实说明来源不可用。
